# แผนงาน: ดูรายงานและสถิติห้องสมุด

อ้างอิง: SPEC-ดูรายงานและสถิติห้องสมุด-015 (Draft v2)

## 1. สรุปแนวทาง

- ผู้บริหารห้องสมุด/ผู้จัดการที่เข้าสู่ระบบและมีสิทธิ์เลือกช่วงวันที่กับประเภทรายงาน (Goal, FR-ดูรายงานและสถิติห้องสมุด-01, NFR-SEC-01)
- อ่านข้อมูลการใช้งานที่ระบบมีอยู่และแสดงผลเป็นกราฟหรือสถิติตามประเภทรายงาน (Constraints, FR-ดูรายงานและสถิติห้องสมุด-02)
- รายงานยืมแสดงจำนวนรายการ, หนังสือยอดนิยมเรียงตามจำนวนครั้งยืม, ค่าปรับแสดงยอดรวม และการใช้ห้องแสดงจำนวนรายการจอง (FR-ดูรายงานและสถิติห้องสมุด-03, ASM-02)
- ส่งออก CSV ที่มีข้อมูลเดียวกับรายงานที่แสดง และจำกัดการดู/ส่งออกตามสิทธิ์รายงาน (FR-ดูรายงานและสถิติห้องสมุด-04, NFR-SEC-01, ASM-03, ASM-04)
- เมื่อช่วงที่เลือกไม่มีข้อมูล แจ้งว่าไม่มีข้อมูล; ไม่จัดการธุรกรรมต้นทางและไม่คำนวณค่าปรับ (FR-ดูรายงานและสถิติห้องสมุด-05, Scope: Out of scope)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุภาษา/framework |

## 3. โมเดลข้อมูล

รายงานอ่านจากข้อมูลการใช้งานที่มีอยู่และสร้าง aggregate สำหรับแสดงผล/ส่งออก ไม่แก้ไขธุรกรรมต้นทาง (Constraints, Scope: Out of scope)

| Entity / view | ฟิลด์หรือ aggregate หลัก | รองรับ |
|---|---|---|
| LoanReportView | ช่วงวันที่, จำนวนรายการยืม | FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-03 |
| PopularBookReportView | ช่วงวันที่, หนังสือ, จำนวนครั้งที่ยืม, ลำดับเรียงจากมากไปน้อย | FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-03 |
| FineReportView | ช่วงวันที่, ยอดค่าปรับรวมจากข้อมูลค่าปรับที่มีอยู่ | FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-03 |
| RoomUsageReportView | ช่วงวันที่, จำนวนรายการจองห้อง | FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-03 |
| ReportExport | report type, date range, dataset identical to displayed report, CSV output | FR-ดูรายงานและสถิติห้องสมุด-04, ASM-03 |

ทุก view ใช้ขอบเขตวันเริ่มต้นและวันสิ้นสุดแบบรวมทั้งสองวันตามเวลาท้องถิ่นห้องสมุด (FR-ดูรายงานและสถิติห้องสมุด-01, ASM-01).

## 4. API / หน้าจอ

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| สร้าง/ดูรายงาน | `GET /api/reports?type={type}&startDate={date}&endDate={date}`; input: ประเภทรายงานและช่วงวันที่; output: aggregate สำหรับกราฟ/สถิติ หรือผลไม่มีข้อมูล | FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-02, FR-ดูรายงานและสถิติห้องสมุด-03, FR-ดูรายงานและสถิติห้องสมุด-05 |
| ส่งออกรายงาน | `GET /api/reports/export?type={type}&startDate={date}&endDate={date}`; input: ประเภทรายงานและช่วงวันที่เดียวกับรายงาน; output: CSV ที่บรรจุข้อมูลเดียวกับที่แสดง | FR-ดูรายงานและสถิติห้องสมุด-04, NFR-SEC-01, ASM-03, ASM-04 |
| หน้ารายงานและสถิติ | input: ช่วงวันที่/ประเภทรายงาน; output: กราฟหรือสถิติตาม metric, ปุ่มส่งออก CSV หรือข้อความไม่มีข้อมูล | FR-ดูรายงานและสถิติห้องสมุด-01 ถึง FR-ดูรายงานและสถิติห้องสมุด-05, NFR-SEC-01 |

API และหน้าจอต้องตรวจสิทธิ์ก่อนส่งข้อมูลหรือสร้าง CSV และใช้ช่วงวันที่เดียวกันกับรายงานที่แสดง (NFR-SEC-01, FR-ดูรายงานและสถิติห้องสมุด-04, ASM-01, ASM-04).

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ดูรายงานและสถิติห้องสมุด-015

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ผู้บริหารต้องเข้าสู่ระบบและมีสิทธิ์ดูรายงาน | ตรวจ authenticated user และ report permission ก่อนเรียก API ดู/ส่งออกทุกประเภท (NFR-SEC-01, ASM-04) | ใช้แล้ว |
| ไม่มี ID: รายงานต้องอ้างอิงข้อมูลการใช้งานที่ระบบมีอยู่ | สร้าง aggregates จากข้อมูลยืม หนังสือ ค่าปรับ และจองที่มีอยู่ โดยไม่แก้ธุรกรรมต้นทาง (FR-ดูรายงานและสถิติห้องสมุด-03, Scope: Out of scope) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ดูรายงานและสถิติห้องสมุด-01 | `test_AC_ดูรายงานและสถิติห้องสมุด_01` | ใช้ผู้ใช้ที่มีสิทธิ์และข้อมูล fixture สำหรับแต่ละ report type; เลือกช่วงวันที่แล้วตรวจ metric, การจัดอันดับหนังสือยอดนิยม และขอบเขตวันแบบ inclusive (FR-ดูรายงานและสถิติห้องสมุด-01 ถึง FR-ดูรายงานและสถิติห้องสมุด-03, NFR-SEC-01, ASM-01, ASM-02) |
| AC-ดูรายงานและสถิติห้องสมุด-02 | `test_AC_ดูรายงานและสถิติห้องสมุด_02` | สร้างรายงานที่มีข้อมูลแล้วส่งออก CSV ตรวจว่าเนื้อหา/records ตรงกับข้อมูลในรายงานที่แสดงและผู้ใช้มีสิทธิ์ (FR-ดูรายงานและสถิติห้องสมุด-04, NFR-SEC-01, ASM-03, ASM-04) |
| AC-ดูรายงานและสถิติห้องสมุด-03 | `test_AC_ดูรายงานและสถิติห้องสมุด_03` | เลือกช่วงที่ไม่มีข้อมูล ตรวจว่าระบบแจ้งว่าไม่มีข้อมูล (FR-ดูรายงานและสถิติห้องสมุด-01, FR-ดูรายงานและสถิติห้องสมุด-05) |

การทดสอบ NFR-PERF-01 ใช้เป้าหมายเวลาและชุดข้อมูลที่ทีมพัฒนากำหนดก่อนทดสอบตาม ASM-06 (NFR-PERF-01, ASM-06).

## 7. ลำดับงาน

1. ยืนยันแหล่งข้อมูลการใช้งานที่มีอยู่และทำ read-only aggregates (Constraints, Scope: Out of scope)
2. รับช่วงวันที่และประเภทรายงาน พร้อมใช้วันต้น/ปลายแบบ inclusive ตามเวลาท้องถิ่น (FR-ดูรายงานและสถิติห้องสมุด-01, ASM-01)
3. ประมวลผลรายงานยืมและจำนวนรายการยืม (FR-ดูรายงานและสถิติห้องสมุด-02, FR-ดูรายงานและสถิติห้องสมุด-03, ASM-02)
4. ประมวลผลหนังสือยอดนิยมตามจำนวนครั้งที่ยืมและเรียงจากมากไปน้อย (FR-ดูรายงานและสถิติห้องสมุด-03, ASM-02)
5. ประมวลผลยอดค่าปรับรวมและจำนวนรายการจองห้องจากข้อมูลที่มี (FR-ดูรายงานและสถิติห้องสมุด-03, ASM-02)
6. แสดงกราฟ/สถิติหรือข้อความไม่มีข้อมูลตามผลลัพธ์ (FR-ดูรายงานและสถิติห้องสมุด-02, FR-ดูรายงานและสถิติห้องสมุด-05)
7. ตรวจ permission ก่อนแสดงหรือสร้าง export และส่งออก CSV ตามข้อมูลที่แสดง (FR-ดูรายงานและสถิติห้องสมุด-04, NFR-SEC-01, ASM-03, ASM-04)
8. ทดสอบ AC ทั้งสามข้อและ performance ตาม target/data ที่ทีมกำหนด (AC-ดูรายงานและสถิติห้องสมุด-01 ถึง AC-ดูรายงานและสถิติห้องสมุด-03, NFR-PERF-01, ASM-06)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน SPEC-ดูรายงานและสถิติห้องสมุด-015 (Draft v2); ไม่มีรายการที่ต้องระงับไว้รอคำตอบ (ASM-07).
