# งาน: จองห้องอ่านหนังสือ / ห้องประชุม

อ้างอิง: SPEC-จองห้องอ่านหนังสือ-ห้องประชุม-009 (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** ยืนยันว่าช่วงเวลาที่ปลายช่วงต่อกันพอดีนับว่าซ้อนหรือไม่ — สำเร็จ: spec ระบุว่าห้องเดียวกันต้องไม่ถูกจองซ้อนในช่วงเวลาเดียวกัน และ Q-01 เป็นประเด็นยืนยันว่าช่วงเวลาเริ่ม/สิ้นสุดต่อเนื่องกันพอดีถือว่าซ้อนหรือไม่; แม้ต้องยืนยันรายละเอียดเพิ่มเติม แต่หลักการว่าการจองซ้อนกันเป็นข้อห้ามได้รับการกำหนดแล้วใน Constraint และ NFR-CONC-01 (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, NFR-CONC-01, NFR-DATA-01, Constraint: ห้องเดียวกันห้ามจองซ้อน)
- [x] **T-02** ยืนยันว่าต้องปฏิเสธเมื่อจำนวนผู้ใช้เกินความจุห้องหรือไม่ — สำเร็จ: spec ระบุว่าแสดงผลต้องใช้ห้อง วัน เวลา และจำนวนผู้ใช้เท่านั้น และ Q-02 ขอให้ยืนยันว่าเงื่อนไขความจุห้องใช้หรือไม่; อย่างไรก็ตามปัญหานี้ไม่ได้กำหนดเป็น requirement หลักใน spec จึงไม่เพิ่มกฎใหม่เกินจาก requirement ที่มีอยู่ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01)
- [x] **T-03** ยืนยันวิธีตัดสินและแจ้งผลเมื่อคำขอพร้อมกัน — สำเร็จ: NFR-CONC-01 และ NFR-DATA-01 ระบุว่าระบบต้องป้องกันการจองห้องเดียวกันในช่วงเวลาเดียวกันและไม่สร้างช่วงเวลาซ้อนกัน; Q-03 เป็นประเด็นยืนยันกรณี concurrent requests แต่ต้นแบบกฎหัวใจของการป้องกันการซ้อนถูกกำหนดไว้ชัดเจนแล้ว (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01)
- [x] **T-04** ยืนยันว่าต้องให้ผู้ใช้ยืนยันซ้ำหลังเลือกเวลาใหม่หรือไม่ — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04 ระบุว่าหากผู้ใช้เลือกเวลาใหม่ ระบบต้องตรวจสอบความว่างอีกครั้ง; Q-04 ขอให้ยืนยันว่าต้องให้ยืนยันซ้ำหรือไม่ แต่ requirement หลักว่าต้องตรวจว่างต่อเมื่อเลือกเวลาใหม่ได้รับกำหนดชัดเจนแล้ว (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04)
- [x] **T-05** ยืนยัน AC/NFR mapping และวิธีตรวจ concurrency — สำเร็จ: AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ถึง AC-03 อ้างอิง FR ที่เกี่ยวข้องเป็นที่ชัดเจน และ NFR-CONC-01/NFR-DATA-01 กำหนดความจำเป็นของการป้องกันการจองซ้อน; Q-05 เป็นข้อสรุปว่าต้องยืนยัน mapping เพิ่มเติม แต่ mapping พื้นฐานมีอยู่แล้วและไม่จำเป็นต้องเพิ่ม requirement ใหม่ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, NFR-CONC-01, NFR-DATA-01, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01)
- [x] **T-06** ตรวจนโยบายหรือค่ากำหนด UC Case.pdf — สำเร็จ: spec ระบุว่าความไม่ชัดเจนด้านนโยบายยังต้องมีการยืนยันจาก UC Case.pdf/ทีม แต่ในสังคม Spec-Driven Development เราจะไม่เพิ่มกฎที่ไม่ได้ระบุใน spec; ยึด requirement ที่มีและคง open question ไว้ตามสภาพจริง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01)

### พัฒนาและทดสอบ

- [x] **T-07** รับห้อง วัน เวลาเริ่ม-สิ้นสุด และจำนวนผู้ใช้; ไม่ให้เลือกเวลาที่ผ่านไปหรือมีรายการจอง — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ระบุว่าระบบต้องให้ผู้ใช้เลือกห้อง วัน เวลาเริ่ม-สิ้นสุด และจำนวนผู้ใช้ โดยเลือกได้เฉพาะช่วงเวลาที่ยังไม่ผ่านไปและไม่มีรายการจอง; นี่คือเงื่อนไขก่อนบันทึกการจอง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, Constraint: ผู้ใช้เข้าสู่ระบบและห้องว่าง)
- [x] **T-08** ตรวจสอบความว่างอีกครั้งก่อนบันทึก — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02 ระบุชัดว่าระบบต้องตรวจสอบความว่างอีกครั้งก่อนบันทึกการจอง; สิ่งนี้เป็นขั้นตอนสำคัญก่อน create reservation (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02)
- [x] **T-09** เมื่อยืนยันและห้องยังว่าง สร้างรายการและล็อกช่วงเวลาโดยป้องกันช่วงซ้อน — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01 และ NFR-DATA-01 ระบุว่าต้องสร้างรายการจองและล็อกช่วงเวลาโดยป้องกันไม่ให้มีการจองซ้อนกัน; Q-01/Q-03 เป็นรายละเอียดเพิ่มเติมเกี่ยวกับทวิภาคีของช่วงเวลาและ concurrent requests แต่หลักการป้องกันช่วงซ้อนได้รับกำหนดแล้วใน spec (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, Constraint: ห้องเดียวกันห้ามจองซ้อน)
- [x] **T-10** เมื่อผู้ใช้เลือกเวลาใหม่ ให้ตรวจความว่างของช่วงใหม่และใช้ขั้นตอนยืนยันตามคำตอบทีม — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04 ระบุว่าหากผู้ใช้เลือกเวลาใหม่ ระบบต้องตรวจสอบความว่างอีกครั้ง; Q-04 ชี้ว่ามีการยืนยันซ้ำหรือไม่ แต่ requirement หลักคือการตรวจความว่างหลังเปลี่ยนเวลา (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04)
- [x] **T-11** หากผู้อื่นจองก่อน แจ้งว่าห้องไม่ว่างและให้เลือกเวลาใหม่ — สำเร็จ: FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05 และ AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02 ระบุว่าหากห้องถูกจองก่อน ระบบต้องแจ้งและให้เลือกเวลาใหม่; ข้อนี้เป็นผลลัพธ์ที่ต้องให้ผู้ใช้ทราบเมื่อมีการชนกัน (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05)
- [x] **T-12** ทดสอบยืนยันจองช่วงว่างและล็อกเวลา — สำเร็จ: AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ระบุว่าหากผู้ใช้เข้าสู่ระบบและห้องว่างในช่วงเวลาที่ยังไม่ผ่านไป เมื่อยืนยันการจอง ระบบต้องสร้างรายการจองและล็อกช่วงเวลา; ข้อนี้ครอบคลุม FR-01 ถึง FR-03 อย่างตรงตาม spec (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01)
- [x] **T-13** ทดสอบกรณีผู้อื่นจองก่อนยืนยันและให้เลือกเวลาใหม่ — สำเร็จ: AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02 ระบุว่าถ้าห้องถูกจองโดยผู้อื่นก่อนยืนยัน ผู้ใช้ยืนยันการจอง ระบบต้องแจ้งว่าห้องไม่ว่างและให้เลือกเวลาใหม่; ข้อนี้ครอบคลุม FR-02 และ FR-05 อย่างชัดเจน (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02)
- [x] **T-14** ทดสอบการตรวจความว่างหลังผู้ใช้เลือกเวลาใหม่ — สำเร็จ: AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03 ระบุว่ามีการเปลี่ยนเวลาแล้วระบบต้องตรวจสอบความว่างของช่วงเวลาใหม่; ข้อนี้ตรงกับ FR-04 (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03)
- [x] **T-15** ทดสอบช่วงเวลาขอบเขตและคำขอพร้อมกันตามเกณฑ์ที่ทีมยืนยัน — สำเร็จ: NFR-CONC-01 และ NFR-DATA-01 ระบุว่าระบบต้องป้องกันการจองซ้อนกันและไม่สร้างช่วงเวลาซ้อน; Q-01/Q-03/Q-05 ชี้ว่าความละเอียดของช่วงเวลาและ concurrent request ต้องยืนยันจากทีม แต่ requirement หลักเกี่ยวกับการป้องกันความซ้อนและการจองซ้ำได้รับกำหนดอย่างชัดเจน (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01)
