- [x] **T-03** ขยาย Room/RoomBooking และ `backend/app/rooms/store.py` ให้ใช้ข้อมูลห้อง/รายการจองร่วมกับ SPEC-008; รายการใหม่เก็บ `room_id`, วัน/เวลา, `user_count`, `member_id` จาก session และ `request_id` โดยไม่สร้าง store หรือฐานข้อมูลรายการจองแยก และปฏิเสธห้องที่ไม่มีข้อมูลความจุ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ถึง FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, Constraints, ASM-02 ถึง ASM-04; ใช้ in-memory store เป็นการเลือกของทีม ไม่ได้มาจาก spec) — เสร็จแล้วใน `backend/app/rooms/models.py` และ `backend/app/rooms/store.py`

### พัฒนา

- [x] **T-04** เพิ่มฟังก์ชันเดียวที่ตรวจข้อมูลการจองล่าสุดและบันทึกรายการภายใต้ lock ต่อห้อง; ป้องกันช่วงซ้อนตามนิยาม `[start_time, end_time)` และคืนรายการเดิมเมื่อรับ request id เดิมซ้ำ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-04) — เสร็จแล้วใน `create_room_booking` พร้อมทดสอบคำขอพร้อมกัน, ช่วงติดกัน และ idempotent retry
- [x] **T-05** เพิ่ม `POST /api/room-reservations/check` สำหรับตรวจเวลาใหม่หลัง validation โดยยังไม่สร้างหรือกันรายการ; ส่งสรุปเมื่อว่าง หรือแจ้งไม่ว่างพร้อมช่วงว่างของห้อง/วันเดิมหรือข้อความไม่มีช่วงว่าง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05) — เสร็จแล้วใน `backend/app/main.py`; ไม่มีการเขียนรายการจอง
- [x] **T-06** เพิ่ม `POST /api/room-reservations` สำหรับยืนยัน; ใช้ฟังก์ชัน atomic ใน T-04 ตรวจความว่างจากข้อมูลล่าสุดก่อนบันทึก และเมื่อช่วงเวลาถูกจองไปแล้วต้องไม่สร้างรายการซ้อนพร้อมคืนผลให้เลือกเวลาใหม่ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-04) — เสร็จแล้วใน `backend/app/main.py`; ทดสอบสร้าง/ยืนยัน, auth/session, ผู้จองจาก session, idempotent retry และกรณีไม่ว่าง/ไม่มีช่วงว่าง
- [x] **T-07** ทำหน้าจอจองที่แสดง validation, สรุปเพื่อยืนยัน, ผลจอง และทางเลือกเมื่อไม่ว่าง; คงห้อง/วันที่/จำนวนผู้ใช้และช่วงว่างที่แสดง, ไม่แนะนำห้องหรือวันอื่น, ให้เปลี่ยนห้อง/วันโดยกลับหน้าตรวจสอบห้องว่าง และให้ยกเลิกก่อนสร้างรายการได้; เมื่อเข้าสู่ระบบแล้วกลับมาพร้อมห้อง/วันเดิมแต่ต้องเลือกเวลาและยืนยันใหม่ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05, ASM-06, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03) — เสร็จแล้วใน `frontend/src/features/rooms/ReservationPage.jsx`, route `/rooms/reservations/new` และหน้า login สำหรับ `returnTo`

### ทดสอบตาม Acceptance Criteria

- [x] **T-08** ทดสอบ AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01: session/401, ผู้จองจาก session, validation วันเวลา/จำนวน, ห้องไม่มีความจุ, กรณีข้อมูลถูกต้องและขอบเขต 30 นาที/4 ชั่วโมง, และการ retry ด้วย request id เดิม; เพิ่มกรณี invalid input ผ่าน API ที่ต้องไม่สร้างรายการ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ถึง FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, Constraints, ASM-01, ASM-02, ASM-04, ASM-06) — ผ่านชุดทดสอบ AC ใน `backend/tests/test_ac_จองห้องอ่านหนังสือ.py`
- [x] **T-09** ทดสอบ AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02: คำขอช่วงเดียวกันที่เริ่มพร้อมกันจริง 10 รายการ ทำซ้ำ 20 รอบ, ช่วงซ้อนบางส่วน, ช่วงต่อกันตรงขอบ และกรณีมีผู้จองหลังแสดงสรุป; ตรวจจำนวนรายการเท่ากับผลสำเร็จและไม่มีช่วงซ้อน โดยไม่ผูกกับเป้าหมาย 100 concurrent users (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-07, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02) — ผ่านการทดสอบ concurrency 10 คำขอ × 20 รอบและกรณี overlap/adjacent
- [x] **T-10** ทดสอบ AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03: ตรวจเวลาใหม่ที่ว่างแล้วแสดงสรุปโดยยังไม่มีรายการ; ยืนยันแล้วสร้างเมื่อยังว่าง; ตรวจเวลาไม่ว่างและกรณีถูกจองก่อนยืนยันว่าไม่สร้างรายการซ้อน, คงข้อมูลเดิม, แสดงช่วงว่างหรือข้อความไม่มีช่วงว่าง และไม่แนะนำห้อง/วันอื่น; ตั้งชื่อ test `test_AC_จองห้องอ่านหนังสือ_ห้องประชุม_03` (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03) — ผ่านกรณี check-then-confirm, conflict หลัง check และกรณีไม่มีช่วงว่าง
