# แผนงาน: จองห้องอ่านหนังสือ / ห้องประชุม

อ้างอิง: [spec.md](./spec.md) — SPEC-จองห้องอ่านหนังสือ-ห้องประชุม-009 (Draft v2)

## 1. สรุปแนวทาง

- สมาชิกที่เข้าสู่ระบบเลือกห้อง วัน เวลาเริ่ม-สิ้นสุด และจำนวนผู้ใช้ตามกติกาที่กำหนด (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, ASM-01, ASM-02)
- ใช้ข้อมูลห้องและความจุจากฟีเจอร์ตรวจสอบห้องว่าง; ยืนยันตัวผู้จองจาก session เท่านั้น (Constraints, ASM-06)
- ตรวจเวลาใหม่โดยยังไม่สร้างรายการ แล้วแสดงสรุปให้ยืนยันเมื่อช่วงเวลาว่าง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, ASM-05)
- เมื่อยืนยัน ให้ตรวจความว่างจากข้อมูลล่าสุดและบันทึกรายการแบบ atomic ต่อห้อง พร้อมป้องกันคำขอเดิมซ้ำ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-04)
- เมื่อช่วงเวลาไม่ว่าง ให้คงห้อง/วัน/จำนวนผู้ใช้ แสดงช่วงว่างที่เหลือหรือข้อความตาม spec และให้เลือกเวลาใหม่หรือกลับไปตรวจสอบห้องว่าง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03)

| In-memory store ร่วมกับ SPEC-008 และ lock ต่อห้อง | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ใช้ store เดียวกับ [`backend/app/rooms/store.py`](../../backend/app/rooms/store.py); ตรวจความว่างและบันทึกในฟังก์ชันเดียวภายใต้ lock; ป้องกันการจองซ้อนได้เฉพาะเมื่อรัน backend 1 process; รัน Uvicorn โดยไม่ใช้ `--workers` มากกว่า 1 และไม่ใช้ Gunicorn หลาย worker (`--reload` ระหว่างพัฒนาใช้ได้); ข้อมูลหายเมื่อ process หยุด ซึ่งทีมยอมรับในขอบเขตรายวิชา (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03) |

การย้ายไปฐานข้อมูลภายหลังอยู่นอกแผนนี้; เมื่อตัดสินใจย้าย ต้องย้ายข้อมูลห้องและรายการจองของ SPEC-008/009/010 ร่วมกันในงานเดียว (Constraints, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03).

หากภายหลังต้องรองรับหลาย process ให้ย้ายไปฐานข้อมูล โดยย้ายข้อมูลห้องและรายการจองของ SPEC-008/009/010 ร่วมกัน; เพิ่มหมายเหตุข้อจำกัด single process ใน [`backend/README.md`](../../backend/README.md) (NFR-CONC-01, NFR-DATA-01; แนวทางจัดเก็บและ topology เป็นการเลือกของทีม ไม่ได้มาจาก spec).

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่วางแผน | รองรับ |
|---|---|---|
| Room (อ้างอิงจาก SPEC-008) | `room_id`, `room_type`, `capacity` | ใช้ห้องที่เลือกและตรวจว่าจำนวนผู้ใช้ไม่เกินความจุ; ห้องที่ไม่มีความจุจองไม่ได้ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, Constraints, ASM-02) |
| RoomBooking (รายการเดิมและการจองใหม่ใน store เดียว) | ฟิลด์เดิม `booking_id`, `room_id`, `booking_date`, `start_time`, `end_time`; เพิ่ม metadata ที่จำเป็นสำหรับรายการจองใหม่ `request_id`, `member_id` จาก session, `user_count` (รายการเดิมไม่ต้องมี metadata ใหม่) | ใช้รายการชุดเดียวทั้งคำนวณช่วงว่างและบันทึกการจอง; ตรวจคำขอเดิมซ้ำและ overlap ภายใต้ lock ต่อห้อง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-04) |
| BookingCheck (ผลชั่วคราว ไม่จัดเก็บเป็นรายการจอง) | `room_id`, `booking_date`, `start_time`, `end_time`, `user_count`, `available`, `available_slots` | ตรวจเวลาใหม่และแสดงสรุป/ช่วงว่าง โดยยังไม่กันห้องหรือสร้างรายการ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05) |
| AuthenticatedMember (ข้อมูลอ้างอิงจาก session) | `member_id` หรือ identifier ที่มีอยู่ใน session | ระบุตัวผู้จองจาก session เท่านั้น; ไม่รับ `member_id` จาก client และไม่คัดลอกข้อมูลส่วนบุคคลที่ไม่จำเป็นลงรายการจอง (Constraints, ASM-06, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01) |

เพิ่มรายการจองใหม่เข้า collection รายการจองเดิมใน store ห้อง ไม่สร้าง store หรือฐานข้อมูลรายการจองแยก; lock ของห้องเดียวกันครอบคลุมการตรวจรายการล่าสุดและการ append ในฟังก์ชันเดียว (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03).

ช่วงเวลาใน RoomBooking ใช้นิยามครึ่งเปิด `[start_time, end_time)`; ตรวจการซ้อนด้วย `startA < endB and endA > startB`; ไม่มีสถานะติดตามหรือยกเลิกการจองในโมเดลนี้ (ASM-03, Scope: Out of scope).

เส้นทางด้านล่างเป็นข้อเสนอใน plan; การค้นหาห้องว่างทั่วไปยังใช้ API สาธารณะของ SPEC-008 ส่วนการตรวจเวลาเพื่อจองต้องผ่าน session (Constraints, ASM-06).

| รายการ | Method / path, input/output หลัก | รองรับ |
|---|---|---|
| ตรวจช่วงเวลาใหม่ก่อนยืนยัน | `POST /api/room-reservations/check`; input: `room_id`, `booking_date`, `start_time`, `end_time`, `user_count`; ผู้จองจาก session; output: สรุปเมื่อว่าง หรือข้อความไม่ว่างพร้อมช่วงว่างของห้อง/วันนั้นหรือข้อความไม่มีช่วงว่าง | FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05, ASM-06 |
| ยืนยันและสร้างรายการจอง | `POST /api/room-reservations`; input: รายละเอียดห้อง/วัน/เวลา/จำนวนผู้ใช้และ `request_id`; ผู้จองจาก session; output: รายการที่สร้าง หรือผลไม่ว่าง/ช่วงว่างที่เลือกต่อได้; เรียกฟังก์ชันใน store เดียวที่ล็อกห้อง ตรวจ และบันทึกแบบ atomic | FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, NFR-CONC-01, NFR-DATA-01, ASM-03, ASM-04, ASM-06 |
| หน้าจองห้อง | `/rooms/reservations/new`; input: ห้อง/วันที่ที่เลือกจากหน้าตรวจสอบ, เวลาเริ่ม-สิ้นสุด, จำนวนผู้ใช้; output: ข้อผิดพลาด, สรุปเพื่อยืนยัน, ผลจอง หรือช่วงว่างให้เลือกใหม่ | FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ถึง FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 ถึง AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03 |
| เปลี่ยนเส้นทางเข้าสู่ระบบ | ใช้กลไก session/หน้าเข้าสู่ระบบเดิม; เมื่อได้รับ 401 แจ้งและกลับหน้าจองพร้อมห้อง/วันเดิม โดยให้ผู้ใช้เลือกเวลาและยืนยันใหม่ | Constraints, ASM-06, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 |

## 5. ตารางตรวจ Constraints

Constraints ไม่มี ID เฉพาะใน spec; ตารางนี้อ้างข้อความ Constraint ตามเดิมโดยไม่สร้าง ID ใหม่

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ต้องเข้าสู่ระบบก่อนตรวจความว่างเพื่อจองและก่อนยืนยัน; ไม่มี/หมดอายุ session ตอบ 401 ไม่ตรวจและไม่สร้างรายการ | Authenticated API guard และกรณี AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01; return URL กลับหน้าจองตาม ASM-06 | ใช้แล้ว |
| ไม่มี ID: ระบุผู้จองจาก session เท่านั้น ไม่รับรหัสสมาชิกจาก client | `AuthenticatedMember` อ้างอิง session ใน API และการบันทึก RoomBooking; ทดสอบ spoofed member id ใน AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01 | ใช้แล้ว |
| ไม่มี ID: การดูห้องว่างตาม SPEC-008 ไม่ต้องเข้าสู่ระบบ | คง API/หน้าตรวจสอบห้องว่างทั่วไปเป็นสาธารณะ; บังคับ session เฉพาะขั้นตอนเพื่อจอง (ASM-06) | ใช้แล้ว |
| ไม่มี ID: ห้องต้องว่าง ณ เวลายืนยันและห้องเดียวกันห้ามมีช่วงเวลาซ้อนกัน | ตรวจ availability ล่าสุดและ append ในฟังก์ชันเดียวภายใต้ lock ของห้อง; ใช้นิยามช่วงครึ่งเปิด (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03) | ใช้แล้ว |
| ไม่มี ID: ทุกห้องต้องมีข้อมูลความจุ; ห้องที่ไม่มีความจุจองไม่ได้ | อ่าน `capacity` จาก Room ของ SPEC-008 และปฏิเสธห้องที่ไม่มีข้อมูล (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, ASM-02, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01) | ใช้แล้ว |
| NFR-CONC-01 | การล็อกห้อง ตรวจความว่าง/บันทึก และทดสอบคำขอพร้อมกัน (AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02) | ใช้แล้ว |
| NFR-DATA-01 | ตรวจ invariant ว่าไม่มีคู่รายการของห้องเดียวกันที่ช่วงเวลาซ้อนกัน (AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, ASM-03) | ใช้แล้ว |

## 7. ลำดับงาน

1. ขยายแบบจำลอง RoomBooking และ validation วัน/เวลา/จำนวนตามกติกา รวมถึงนิยามช่วงซ้อน (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, NFR-DATA-01, ASM-01 ถึง ASM-03).
2. เชื่อมข้อมูลห้อง/ความจุจาก SPEC-008 และ session จาก SPEC-002; ปฏิเสธห้องไม่มีความจุและใช้ผู้จองจาก session เท่านั้น (Constraints, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, ASM-02, ASM-06).
3. ขยาย RoomBooking และ store ห้องของ SPEC-008 ให้เก็บการจองใหม่ใน collection เดียว; ไม่สร้าง store แยก และบันทึกการจองด้วยฟังก์ชันเดียวภายใต้ lock ต่อห้อง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, NFR-CONC-01, NFR-DATA-01, ASM-03).
4. ทำ service ตรวจเวลาใหม่โดยไม่บันทึกหรือกันช่วง และคืนสรุป/ช่วงว่าง/สถานะไม่มีช่วงว่าง (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05).
5. ทำ API ตรวจช่วงเวลาและ API ยืนยัน โดยทั้งคู่บังคับ session; ยืนยันทำ recheck+append แบบ atomic และรองรับ request idempotency (Constraints, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-03, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-03, ASM-04, ASM-06).
6. ทำหน้าจอจองและเชื่อมการกลับจาก login; แสดงสรุปเพื่อยืนยันและเส้นทางเลือกเวลาใหม่/กลับไปหน้าตรวจสอบ (FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-04, FR-จองห้องอ่านหนังสือ-/-ห้องประชุม-05, ASM-05, ASM-06).
7. เพิ่มชุดทดสอบ validation, auth, success, idempotency และ flow เปลี่ยนเวลาให้ตรง AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01/AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03 (AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-01, AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-03).
8. เพิ่มชุดทดสอบ concurrency แบบพร้อมกันจริง 10 requests x 20 รอบ และตรวจ invariant ไม่มี overlap (AC-จองห้องอ่านหนังสือ-/-ห้องประชุม-02, NFR-CONC-01, NFR-DATA-01).
9. บันทึกข้อจำกัด single-process deployment และคำสั่งรันใน backend/README.md โดยไม่เปลี่ยนขอบเขตหรือเพิ่ม NFR (NFR-CONC-01, NFR-DATA-01; ทีมเลือกเอง ไม่ได้มาจาก spec).
10. ทบทวนเวลาทำการจริง/วันปิดทำการกับผู้ดูแลก่อนเพิ่มการรองรับตารางจริงหรือวันหยุด (Q-07, ASM-01).
