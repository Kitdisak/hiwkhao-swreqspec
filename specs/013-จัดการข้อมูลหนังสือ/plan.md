# แผนงาน: จัดการข้อมูลหนังสือ

อ้างอิง [spec.md](./spec.md) (SPEC-จัดการข้อมูลหนังสือ-013, Draft v2) และรูปแบบข้อมูล/บริการที่มีอยู่ของ SPEC-001, SPEC-003, SPEC-011 และ SPEC-012

## 1. สรุปแนวทาง

- บรรณารักษ์ที่เข้าสู่ระบบและมี Permission เพิ่มหรือแก้ไขระเบียน Catalog และข้อมูล Copy (FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-06)
- แยกข้อมูลชื่อเรื่องออกจาก Copy โดย Catalog หนึ่งรายการมีหลายหมวดหมู่และหลาย Copy; Copy แต่ละเล่มมีรหัสและสถานะของตนเอง (FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-06, ASM-01, ASM-04, ASM-15)
- เก็บ Catalog และ Copy ในที่เก็บร่วมที่บริการค้นหา รายละเอียด ยืม จอง และคืนใช้อยู่; บันทึกระเบียนพร้อม Copy แบบ all-or-nothing (NFR-DATA-01, AC-จัดการข้อมูลหนังสือ-01, AC-จัดการข้อมูลหนังสือ-02, ASM-14)
- ใช้ Open Library Books API เติมชื่อและผู้แต่งให้บรรณารักษ์ตรวจ โดยมี timeout และทางเลือกกรอกเอง (FR-จัดการข้อมูลหนังสือ-05, ASM-11)
- ใช้หน้าจัดการ Catalog/Copy ตรวจข้อมูลและสถานะตาม spec; ไม่ตรวจรูปแบบบาร์โค้ดหรือมาตรฐานหมวดหมู่ที่ยังรอคำตอบ (FR-จัดการข้อมูลหนังสือ-02 ถึง FR-จัดการข้อมูลหนังสือ-06, Q-01, Q-03)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นของรายวิชาและเป็นโครงสร้างหน้าบ้านที่มีอยู่ |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นของรายวิชาและเป็นรูปแบบ backend ที่มีอยู่ |
| SQLite ผ่าน `sqlite3` โดยใช้ฐานข้อมูลเดียวกับ Reservation/Loan/Copy | **ทีมเลือกเอง ไม่ได้มาจาก spec**; การใช้ที่เก็บร่วมอ้าง ASM-14 | ขยาย schema ใน store เดิม ห้ามสร้างฐานข้อมูลหรือ store แยกสำหรับ Catalog/Copy |
| Open Library Books API | ASM-11 | ทดสอบด้วยข้อมูลจำลอง ไม่เรียกบริการจริงใน automated tests |

## 3. โมเดลข้อมูล

แบบจำลองเชิงตรรกะ โดยข้อมูล Catalog และ Copy ต้องอยู่ใน store ร่วมเดิมและอ่านได้จากฟีเจอร์ที่เกี่ยวข้อง (ASM-14)

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| CatalogRecord | `book_id`, `title`, `authors[]`, `isbn`, `publisher`, `publication_year`, `categories[]`, `call_number`, `shelf`, `zone` | FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04; AC-จัดการข้อมูลหนังสือ-01 |
| Category | `code`, `label` (ชื่อหมวดหมู่); ผูกได้หลายหมวดหมู่กับ CatalogRecord | FR-จัดการข้อมูลหนังสือ-04, ASM-12, ASM-15 |
| BookCopy | `book_id`, `item_identifier` ที่ตัดช่องว่างหน้า-หลังและไม่ซ้ำ, `status` | FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-06; DOM-OPAC-05 |
| ISBNLookupResult (ข้อมูลชั่วคราว) | `title`, `authors[]`; ไม่บันทึกจนกว่าบรรณารักษ์ยืนยัน | FR-จัดการข้อมูลหนังสือ-05, ASM-11 |
| Permission context | ผู้ใช้จาก session และ permission `manage_books`; ใช้ของระบบยืนยันตัวตนเดิม ไม่สร้างข้อมูลผู้ใช้ใหม่ | Constraints เรื่องเข้าสู่ระบบ/Permission, FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-06 |

- ใช้ BookCopy เป็นแหล่งสถานะ Copy หลักร่วมกับ Loan/Reservation; ย้ายข้อมูลจากตารางเดิมและคงชื่อ `loan_copy_status` เป็น compatibility view ที่อ่าน/เขียนสถานะไปยัง BookCopy เดียวกัน เพื่อรักษาความเข้ากันได้โดยไม่เก็บสถานะซ้ำ (FR-จัดการข้อมูลหนังสือ-06, ASM-14)
- จำนวน Copy คำนวณจากรายการ BookCopy; การเพิ่ม Copy ต้องระบุรหัสประจำเล่มทีละเล่ม; ไม่ลบ Copy เดิม; เมื่อจำนวนที่ส่งมาน้อยกว่าจำนวนเดิมให้ปฏิเสธด้วยข้อความใน FR-จัดการข้อมูลหนังสือ-04 (FR-จัดการข้อมูลหนังสือ-04, ASM-15)
- หากเลิกใช้ Copy ให้เปลี่ยนเป็น Lost หรือ Damaged เพื่อรักษาประวัติ Loan/ค่าปรับ/Reservation; ห้ามแก้สถานะเองขณะที่มี Loan หรือ Reservation Ready ค้าง (FR-จัดการข้อมูลหนังสือ-06, ASM-10, ASM-15)
- เก็บรหัสและชื่อหมวดหมู่ตามข้อมูลที่บรรณารักษ์กรอก; ยังไม่ตรวจรูปแบบมาตรฐานจนกว่าจะได้คำตอบ Q-03 (FR-จัดการข้อมูลหนังสือ-04, ASM-12, Q-03)

## 4. API / หน้าจอ

| รายการ | Method / path และ input/output หลัก | รองรับ |
|---|---|---|
| ค้นหาระเบียนเดิมเพื่อแก้ไข | `GET /api/manage/books?query={query}`; input: คำค้น; output: รายการ Catalog ที่เลือกไปแก้ไขได้; ต้องมี session/Permission | FR-จัดการข้อมูลหนังสือ-01 |
| อ่านรายละเอียดเพื่อแก้ไข | `GET /api/manage/books/{book_id}`; output: ฟิลด์จัดการ Catalog และ Copy ที่อ่านจาก store ร่วม; ต้องมี session/Permission | FR-จัดการข้อมูลหนังสือ-01, ASM-14 |
| อ่านรายละเอียดสาธารณะหลังบันทึก | ใช้ `GET /api/books/{book_id}` ที่มีอยู่; output: ข้อมูล Catalog และ Copy จาก store ร่วม | AC-จัดการข้อมูลหนังสือ-01, ASM-14 |
| ค้นข้อมูล ISBN | `GET /api/manage/isbn-metadata?isbn={isbn}`; output: ชื่อและผู้แต่ง หรือผลไม่พบ/บริการไม่พร้อม; backend เรียก Open Library ด้วย timeout 5 วินาที | FR-จัดการข้อมูลหนังสือ-05, ASM-11 |
| เพิ่มระเบียนและ Copy | `POST /api/manage/books`; input: ข้อมูล Catalog และรหัสประจำเล่มของทุก Copy; output: ข้อมูลอ่านกลับหรือข้อผิดพลาด; บันทึก Catalog/Copy ใน transaction เดียว | FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-05, NFR-DATA-01 |
| แก้ไขระเบียน/เพิ่ม Copy | `PUT /api/manage/books/{book_id}`; input: ข้อมูล Catalog และ Copy ที่เพิ่ม; output: ข้อมูลอ่านกลับหรือข้อผิดพลาด; ไม่ลบ Copy เดิม และปฏิเสธจำนวนที่ต่ำกว่าจำนวนเดิม | FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-04, NFR-DATA-01, ASM-15 |
| เปลี่ยนสถานะ Copy | `PATCH /api/manage/copies/{item_identifier}/status`; input: สถานะใหม่; output: สถานะที่บันทึกหรือข้อผิดพลาดเรื่อง permission/รายการค้าง/transition | FR-จัดการข้อมูลหนังสือ-06, AC-จัดการข้อมูลหนังสือ-03 |
| หน้าจัดการ Catalog/Copy | `/manage/books`; ค้นหา/เลือกชื่อเรื่อง, เพิ่มหรือแก้ไขข้อมูล, เพิ่ม Copy ทีละรหัส, ค้น ISBN, เปลี่ยนสถานะ และแสดงข้อผิดพลาดข้างช่อง | FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-06, NFR-USE-01 |

## 5. ตารางตรวจ Constraints

Constraints ใน SPEC-013 ไม่มีรหัส CON แยก จึงอ้างอิงด้วยข้อความเดิม; DOM-OPAC-05/06 อ้างอิงข้อกำหนดร่วมจาก SPEC-001

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: บรรณารักษ์ต้องเข้าสู่ระบบและมี Permission | ตรวจ session และ `manage_books` ที่ API เพิ่ม/แก้ไข/เปลี่ยนสถานะ; ปฏิเสธผู้ไม่มีสิทธิ์ (FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-06) | ใช้แล้ว |
| DOM-OPAC-05 (SPEC-001): รหัสประจำเล่มไม่ซ้ำ | `BookCopy.item_identifier` ตัดช่องว่างและ unique ใน store ร่วม; ไม่ตรวจรูปแบบรหัสซึ่งยังรอ Q-01 (FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, ASM-09, Q-01) | ใช้แล้ว |
| ไม่มี ID: หนังสือต้องจัดหมวดหมู่ตามมาตรฐานที่ห้องสมุดกำหนด | เก็บหมวดหมู่เป็น code/name และไม่บังคับ DDC; ไม่ตรวจรูปแบบมาตรฐานจนกว่าจะทราบค่าจริง (FR-จัดการข้อมูลหนังสือ-04, ASM-12, Q-03) | ใช้แล้ว |
| DOM-OPAC-06 (SPEC-001): ใช้มาตรฐานจัดหมวดหมู่ที่ห้องสมุดกำหนด | ให้ข้อมูลหมวดหมู่เป็นค่าจากบรรณารักษ์; ไม่สร้างกฎตรวจมาตรฐานแทนทีม (FR-จัดการข้อมูลหนังสือ-04, ASM-12, Q-03) | ใช้แล้ว |
| ไม่มี ID: Lost, Damaged หรืออยู่ระหว่างซ่อมต้องยืมหรือจองไม่ได้ | ใช้สถานะ BookCopy ร่วมในขั้นตอนยืม/จอง และปฏิเสธการยืม/จองเมื่อสถานะถูกห้าม (FR-จัดการข้อมูลหนังสือ-06, ASM-05, ASM-10) | ใช้แล้ว |

## 7. ลำดับงาน

1. ออกแบบตาราง CatalogRecord, Category และ BookCopy ใน SQLite store เดิม พร้อม migration/seed โดยไม่สร้าง store ใหม่ (NFR-DATA-01, ASM-14, ASM-15)
2. สร้าง repository และ validation สำหรับ required fields, checksum ISBN, unique ISBN/รหัส Copy, trim และ transaction all-or-nothing (FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, NFR-DATA-01)
3. เชื่อมข้อมูลค้นหา/รายละเอียด/ยืม/จอง/คืนให้ใช้ Catalog และ BookCopy ชุดเดียวกัน; ลบการพึ่งพาสถานะ Copy ซ้ำเมื่อย้ายข้อมูลสำเร็จ (FR-จัดการข้อมูลหนังสือ-06, AC-จัดการข้อมูลหนังสือ-01, ASM-14)
4. เพิ่ม API เพิ่ม/แก้ไข Catalog, เพิ่ม Copy และเปลี่ยนสถานะ พร้อมตรวจ session/Permission, จำนวน Copy และ transition (FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-06, ASM-15)
5. เพิ่ม endpoint lookup ISBN ที่เรียก Open Library ด้วย timeout 5 วินาที; map เฉพาะชื่อ/ผู้แต่งให้ฟอร์ม; แยกผล timeout, error และ not found (FR-จัดการข้อมูลหนังสือ-05, ASM-11)
6. สร้างหน้า `/manage/books` สำหรับค้นหา เพิ่ม/แก้ไข กรอกรหัส Copy ทีละเล่ม และเปลี่ยนสถานะ; แสดง validation ตาม NFR-USE-01 (FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-06, NFR-USE-01, ASM-15)
7. เพิ่ม API/UI/integration tests สำหรับ AC-01 ถึง AC-03 รวม mock API และ rollback ของ transaction (AC-จัดการข้อมูลหนังสือ-01, AC-จัดการข้อมูลหนังสือ-02, AC-จัดการข้อมูลหนังสือ-03)
8. รัน tests ของฟีเจอร์และ regression tests ของ SPEC-001/003/004/011/012; ยืนยันการค้นพบ/รายละเอียดและการป้องกันยืม/จองจาก store ร่วม (AC-จัดการข้อมูลหนังสือ-01, AC-จัดการข้อมูลหนังสือ-03, ASM-14)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** รูปแบบรหัสประจำเล่มจริงของห้องสมุดเป็นอย่างไร? ผู้กำหนดรหัสคือบรรณารักษ์ตาม ASM-09 แล้ว; ต้องถามบรรณารักษ์ — ส่วนตรวจสอบรูปแบบรหัสจริงจะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** หากหนังสือหายระหว่างถูกยืม ต้องปิดรายการยืมหรือคิดค่าเสียหายอย่างไร? ต้องถามบรรณารักษ์ — ส่วนการจัดการหนังสือหายระหว่างมี Loan จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03** ห้องสมุดใช้มาตรฐานจัดหมวดหมู่และรูปแบบเลขเรียกหนังสือใดจริง? ระหว่างรอคำตอบไม่ตรวจรูปแบบตามมาตรฐาน; อ้างอิงประเด็นเปิดเดียวกับ SPEC-003 Q-02; ต้องถามบรรณารักษ์ — ส่วนตรวจรูปแบบมาตรฐานจะยังไม่สร้างจนกว่าจะได้คำตอบ
