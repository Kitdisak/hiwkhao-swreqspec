# แผนงาน: จัดการข้อมูลหนังสือ

อ้างอิง: SPEC-จัดการข้อมูลหนังสือ-013 (Draft v2)

## 1. สรุปแนวทาง

- บรรณารักษ์ที่เข้าสู่ระบบและมีสิทธิ์เพิ่มหรือแก้ไขระเบียนหนังสือและ Copy (FR-จัดการข้อมูลหนังสือ-01, ASM-06)
- แยกข้อมูล Catalog ของชื่อหนังสือออกจากข้อมูล Copy เพื่อให้ ISBN เดียวกันอยู่ได้หลาย Copy และแต่ละ Copy มีรหัสประจำเล่มเฉพาะ (FR-จัดการข้อมูลหนังสือ-03, ASM-01, Constraints)
- ตรวจข้อมูลสำคัญและสิทธิ์ก่อนบันทึก; ใช้ข้อมูล ISBN จากบริการเมื่อมี และให้กรอกเองเมื่อบริการไม่พร้อม (FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-05, ASM-02, ASM-03)
- รองรับหมวดหมู่ เลขเรียกหนังสือ ตำแหน่ง จำนวน Copy และสถานะราย Copy (FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-06, Constraints)
- ป้องกัน ISBN ซ้ำข้าม Catalog, รหัส Copy ซ้ำ และสถานะ Lost/Damaged/ซ่อมที่ยังยืมหรือจองได้; รายละเอียดที่ยังเปิดอยู่รอ Q-01/Q-02 (FR-จัดการข้อมูลหนังสือ-03, NFR-DATA-01, ASM-05, Q-01, Q-02)

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| CatalogRecord | title, authors, ISBN, publisher, publication year, category, call number | FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-04 |
| BookCopy | CatalogRecord reference, unique item identifier, location, copy status | FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-06; Constraints: รหัสประจำเล่มและสถานะห้ามยืม/จอง |
| ISBNMetadata (ข้อมูลชั่วคราวจากบริการ ถ้ามี) | ISBN, partial metadata fields | FR-จัดการข้อมูลหนังสือ-05, ASM-03 |
| Permission context | librarian identity, permission to create/edit/update copy status | FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-06, Constraints: Permission |

ISBN uniqueness ตรวจที่ CatalogRecord; BookCopy หลายรายการอ้าง CatalogRecord เดียวกันได้ แต่ `unique item identifier` ของแต่ละ Copy ต้องไม่ซ้ำ กลไกออกหรือกำหนดรหัสยังรอ Q-01 (FR-จัดการข้อมูลหนังสือ-03, Constraints, ASM-01, Q-01). สถานะถูกเก็บระดับ Copy; Lost, Damaged และอยู่ระหว่างซ่อมต้องไม่ให้ยืมหรือจอง (FR-จัดการข้อมูลหนังสือ-06, Constraints, ASM-04, ASM-05).

## 4. API / หน้าจอ

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ค้นหา Catalog ด้วย ISBN | `GET /api/catalog?isbn={isbn}`; input: ISBN; output: ระเบียน Catalog ที่ตรงกันและ Copy ที่เกี่ยวข้อง | FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-03 |
| ดึงข้อมูลบางส่วนจาก ISBN | `GET /api/catalog/isbn-metadata?isbn={isbn}`; input: ISBN; output: metadata บางส่วนเมื่อบริการพร้อม หรือผลไม่พร้อมเพื่อให้กรอกเอง | FR-จัดการข้อมูลหนังสือ-05, ASM-03 |
| เพิ่ม/แก้ไขระเบียน Catalog | `POST /api/catalog` และ `PUT /api/catalog/{catalogId}`; input: ชื่อ ผู้แต่ง ISBN สำนักพิมพ์ ปีพิมพ์ หมวดหมู่ เลขเรียกหนังสือ; output: ระเบียนที่บันทึกหรือข้อผิดพลาด validation/permission | FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-04 |
| จัดการ Copy | `POST /api/catalog/{catalogId}/copies`; input: item identifier และตำแหน่ง; output: Copy ที่บันทึกหรือข้อผิดพลาดรหัสซ้ำ | FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04, Constraints: รหัสประจำเล่ม |
| เปลี่ยนสถานะ Copy | `PATCH /api/book-copies/{copyId}/status`; input: สถานะใหม่; output: สถานะ Copy หลังตรวจ permission/เงื่อนไข | FR-จัดการข้อมูลหนังสือ-06, Constraints: Permission และข้อห้ามยืม/จอง |
| หน้าจัดการ Catalog/Copy | input: ข้อมูลหนังสือและ Copy; output: แบบฟอร์มบันทึก/แก้ไข, ผล lookup ISBN หรือให้กรอกเอง, ผล validation และสถานะ Copy | FR-จัดการข้อมูลหนังสือ-01 ถึง FR-จัดการข้อมูลหนังสือ-06, NFR-DATA-01, NFR-USE-01 |

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-จัดการข้อมูลหนังสือ-013

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: บรรณารักษ์ต้องเข้าสู่ระบบและมี Permission | ตรวจ permission ในการเพิ่ม/แก้ Catalog และเปลี่ยนสถานะ Copy (FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-06) | ใช้แล้ว |
| ไม่มี ID: หนังสือแต่ละเล่มต้องมีรหัสประจำเล่มไม่ซ้ำกัน | unique item identifier ใน BookCopy; กลไกกำหนดรหัสยังรอ Q-01 (FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04, Q-01) | ใช้แล้ว |
| ไม่มี ID: หนังสือต้องจัดหมวดหมู่ตามมาตรฐานห้องสมุด | เก็บ category ตามมาตรฐานที่ห้องสมุดกำหนด; ไม่เลือกมาตรฐานเพิ่มเติมนอกตัวอย่าง spec (FR-จัดการข้อมูลหนังสือ-04, Constraints) | ใช้แล้ว |
| ไม่มี ID: Lost, Damaged หรืออยู่ระหว่างซ่อมต้องไม่สามารถยืมหรือจองได้ | เก็บสถานะราย Copy และใช้เงื่อนไขดังกล่าวก่อนอนุญาตยืมหรือจอง (FR-จัดการข้อมูลหนังสือ-06, ASM-04, ASM-05) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-จัดการข้อมูลหนังสือ-01 | `test_AC_จัดการข้อมูลหนังสือ_01` | ใช้บรรณารักษ์ที่มีสิทธิ์ กรอกข้อมูลสำคัญครบและบันทึกระเบียนพร้อม Copy; ตรวจ ISBN เดียวมีหลาย Copy ได้, ข้อมูลบันทึกถูกต้อง และเมื่อ lookup ไม่พร้อมยังกรอกเองได้ (FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04, FR-จัดการข้อมูลหนังสือ-05, NFR-DATA-01, ASM-01, ASM-03) |
| AC-จัดการข้อมูลหนังสือ-02 | `test_AC_จัดการข้อมูลหนังสือ_02` | ทดสอบ ISBN ซ้ำกับ Catalog อื่น, ข้อมูลสำคัญขาด และไม่มี permission แยกกรณี; ตรวจว่าทุกกรณีปฏิเสธและแจ้งข้อผิดพลาด (FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03, AC-จัดการข้อมูลหนังสือ-02) |
| AC-จัดการข้อมูลหนังสือ-03 | `test_AC_จัดการข้อมูลหนังสือ_03` | เปลี่ยนสถานะ Copy เป็น Lost, Damaged และอยู่ระหว่างซ่อม ตรวจว่าสถานะบันทึกและ Copy เหล่านั้นถูกห้ามยืมหรือจอง (FR-จัดการข้อมูลหนังสือ-06, AC-จัดการข้อมูลหนังสือ-03, ASM-05) |

การทดสอบว่าแบบฟอร์ม “ใช้งานง่าย” ยังต้องมีเกณฑ์จาก Q-02 ก่อนกำหนด pass/fail ของ NFR-USE-01.

## 7. ลำดับงาน

1. ยืนยันวิธีกำหนด unique item identifier สำหรับแต่ละ Copy (Constraints, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-04, Q-01)
2. ออกแบบ CatalogRecord แยกจาก BookCopy เพื่อรองรับ ISBN ร่วมกันในหลาย Copy (FR-จัดการข้อมูลหนังสือ-03, FR-จัดการข้อมูลหนังสือ-04, ASM-01)
3. สร้าง lookup/update Catalog และตรวจฟิลด์สำคัญกับ permission ก่อนบันทึก (FR-จัดการข้อมูลหนังสือ-01, FR-จัดการข้อมูลหนังสือ-02, FR-จัดการข้อมูลหนังสือ-03)
4. เพิ่มการดึง metadata จาก ISBN และ fallback กรอกเองเมื่อบริการใช้ไม่ได้ (FR-จัดการข้อมูลหนังสือ-05, ASM-03)
5. เพิ่มการกำหนดหมวดหมู่ เลขเรียกหนังสือ ตำแหน่ง และจำนวน Copy (FR-จัดการข้อมูลหนังสือ-04, Constraints: มาตรฐานหมวดหมู่)
6. เพิ่มการเปลี่ยนสถานะระดับ Copy ตาม permission และข้อห้ามยืม/จอง (FR-จัดการข้อมูลหนังสือ-06, Constraints, ASM-04, ASM-05, ASM-06)
7. ทดสอบการบันทึก/ปฏิเสธ/สถานะตาม AC ทั้งสามข้อ และตรวจ NFR-DATA-01 (AC-จัดการข้อมูลหนังสือ-01 ถึง AC-จัดการข้อมูลหนังสือ-03, NFR-DATA-01)
8. กำหนดและประเมินเกณฑ์ usability เมื่อได้คำตอบจากทีม (NFR-USE-01, Q-02)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** รหัสประจำเล่มของแต่ละ Copy ถูกกำหนดโดยบรรณารักษ์หรือสร้างโดยระบบ และต้องใช้รูปแบบใด? ต้องถามบรรณารักษ์/ทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** ใช้เกณฑ์ใดตรวจว่าแบบฟอร์ม “ใช้งานง่าย” ตาม NFR-USE-01? ต้องถามทีม/บรรณารักษ์ผู้ใช้ระบบ ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
