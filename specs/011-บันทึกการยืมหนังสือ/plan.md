# แผนงาน: บันทึกการยืมหนังสือ

อ้างอิง: SPEC-บันทึกการยืมหนังสือ-011 (Draft v2)

## 1. สรุปแนวทาง

- บรรณารักษ์ค้นหานักศึกษาจากบัตรที่อ่านเป็นรหัสนักศึกษาหรือพิมพ์รหัส และค้นหาบุคลากรด้วยอีเมล พร้อมตรวจสถานะ/สิทธิ์ (FR-01, FR-02, ASM-19)
- ตรวจ Copy ที่สแกนตามลำดับ รวมจำนวนที่ยืมอยู่กับเล่มที่ผ่านแล้วในรายการ และไม่เพิ่มรหัสซ้ำ (FR-02, FR-05, FR-06, ASM-08, ASM-14)
- กำหนดจำนวนสูงสุดและจำนวนวันยืมจากตารางค่ากำหนดตามประเภทสมาชิกและประเภทหนังสือ แล้วคำนวณวันคืนที่ server ด้วย Asia/Bangkok (FR-03, ASM-09, ASM-10)
- บันทึก Loan, เปลี่ยน Copy เป็น Borrowed และปรับ reservation Ready ที่เกี่ยวข้องเป็น Completed ในชุด transaction เดียว โดยใช้ store การจองเดิม (FR-04, NFR-DATA-01, ASM-15, ASM-18)
- แสดงผลรายเล่ม รวมผลสำเร็จ วันคืน ข้อความปฏิเสธ และข้อความรหัสซ้ำ; ทดสอบทุก AC และเกณฑ์ประสิทธิภาพ (FR-05, FR-06, NFR-PERF-01, AC-01 ถึง AC-03)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตามรายวิชา; spec ไม่ได้ระบุ framework |
| Python FastAPI สำหรับหลังบ้าน | ทีมเลือกเอง ไม่ได้มาจาก spec | ค่าเริ่มต้นตามรายวิชา; spec ไม่ได้ระบุภาษา/framework |
| SQLite สำหรับที่เก็บข้อมูลของฟีเจอร์ | ทีมเลือกเอง ไม่ได้มาจาก spec | Reservation ต้องใช้ store เดิมใน `backend/app/reservations/`; ห้ามสร้าง store การจองใหม่ |
| เวลาท้องถิ่น Asia/Bangkok | FR-03, ASM-10, ASM-17 | คำนวณและตรวจวันที่ที่ server; ไม่รับวันยืมหรือวันคืนที่ client คำนวณมาเป็นค่าตัดสิน |

## 3. โมเดลข้อมูล

| Entity / store | ฟิลด์หรือข้อมูลหลัก | รองรับ |
|---|---|---|
| Member | รหัสสมาชิก/รหัสนักศึกษา, ประเภทสมาชิก, สถานะบัญชี, สถานะสิทธิ์ยืม | FR-01, FR-02, FR-05; Constraint สถานะรหัสนักศึกษา; ASM-11, ASM-17 |
| BookCopy | รหัสประจำเล่มไม่ซ้ำ, ชื่อเรื่อง, ประเภทหนังสือ, สถานะ Copy | FR-02, FR-04, FR-06; Constraint รหัสประจำเล่ม; ASM-12, ASM-14 |
| Loan | สมาชิก, วันยืมที่คำนวณจากเวลาของ server, ตัวระบุคำขอ | FR-04, NFR-DATA-01, ASM-10, ASM-16 |
| LoanItem | Loan, BookCopy, วันคืนที่คำนวณจากเวลาของ server | FR-03, FR-04, FR-06, ASM-10 |
| LoanPolicy | คีย์ (ประเภทสมาชิก, ประเภทหนังสือ), ค่า (จำนวนเล่มสูงสุด, จำนวนวันยืม) | FR-02, FR-03, Constraint จำนวน/ระยะเวลาตามประเภท, ASM-09, Q-01; เก็บเป็นค่ากำหนดไม่ hard-code; ใช้ค่าชั่วคราวที่ทีมเลือกใน ASM-09 จนกว่าจะยืนยันค่าจริง |
| Reservation store เดิม | รายการจอง, สมาชิก, ชื่อเรื่อง, สถานะ Waiting/Ready/Completed, รหัส Copy ที่กันไว้ | FR-02, FR-04, ASM-02, ASM-12, ASM-18; ใช้ store/service ใน `backend/app/reservations/` เท่านั้น ไม่สร้างที่เก็บใหม่ |

ข้อมูล overdue และ fine ใช้สถานะจากแหล่งข้อมูลที่มีตาม ASM-17; ฟีเจอร์นี้ไม่คำนวณค่าปรับหรือรับคืนหนังสือตาม Out of scope (UC-12).

## 4. API / หน้าจอ

| รายการ | Method / path และ input/output หลัก | รองรับ |
|---|---|---|
| ค้นหาสมาชิก | `GET /api/members/lookup?identifier={studentIdOrStaffEmail}`; input: บัตรนักศึกษาที่อ่านเป็นรหัสนักศึกษา/รหัสที่พิมพ์ หรืออีเมลบุคลากร; output: ข้อมูลสมาชิกและข้อมูลตรวจสิทธิ์; ไม่พบให้ตอบ “ไม่พบข้อมูลสมาชิก” และไม่เริ่มรายการ | FR-01, FR-02, ASM-19 |
| ตรวจรายการ Copy ที่สแกน | `POST /api/loans/check`; input: สมาชิก, รหัสประจำเล่มปัจจุบัน และรายการ Copy ที่ผ่านก่อนหน้า; output: ผลตรวจตามลำดับและข้อความปฏิเสธเมื่อครบจำนวน | FR-02, FR-05, FR-06, ASM-08, ASM-12, ASM-14 |
| ยืนยันการยืม | `POST /api/loans`; input: สมาชิก, Copy ที่สแกน, request identifier; output: ผลรายเล่มพร้อมวันคืนหรือข้อความปฏิเสธ; backend ทำ transaction กับ Loan, Copy และ reservation store เดิม | FR-03 ถึง FR-06, NFR-DATA-01, ASM-15, ASM-16, ASM-18 |
| หน้าจอบันทึกการยืม | input: บัตร/รหัสนักศึกษาและรหัสประจำเล่ม; output: สมาชิก, ผลตรวจสิทธิ์, ผลรายเล่ม, วันคืนและข้อความตอบกลับ | FR-01 ถึง FR-06, AC-01 ถึง AC-03 |

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: นักศึกษาต้องใช้รหัสนักศึกษาที่มีสถานะใช้งานอยู่ | ตรวจสถานะบัญชี/รหัสนักศึกษาที่ server ก่อนยืนยัน (FR-01, FR-02, FR-05) | ใช้แล้ว |
| ไม่มี ID: จำนวนสูงสุดและระยะเวลายืมขึ้นอยู่กับประเภทสมาชิก ประเภทหนังสือ และนโยบายห้องสมุด | อ่าน LoanPolicy ด้วยคีย์ประเภทสมาชิกและประเภทหนังสือ; ใช้ค่าเริ่มต้นชั่วคราวจาก ASM-09 เป็นค่ากำหนด ไม่ hard-code ใน logic; ค่าจริงยังรอ Q-01 | ใช้แล้ว |
| ไม่มี ID: หนังสือแต่ละเล่มต้องมีรหัสประจำเล่มไม่ซ้ำกัน | BookCopy ใช้รหัสประจำเล่มที่ไม่ซ้ำ; ตรวจรหัสซ้ำก่อนยืนยันและไม่เพิ่มจำนวนซ้ำ (FR-06, ASM-14) | ใช้แล้ว |
| ไม่มี ID: สมาชิกที่มีหนังสือเกินกำหนดอย่างน้อยหนึ่งเล่มหรือมีค่าปรับค้างอย่างน้อยหนึ่งรายการถูกระงับสิทธิ์ยืม | ตรวจข้อมูล overdue/fine ณ เวลาตรวจโดย server และปฏิเสธตาม FR-02/FR-05, ASM-01/ASM-17 | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-บันทึกการยืมหนังสือ-01 | `test_AC_บันทึกการยืมหนังสือ_01` | Given สมาชิกใช้งานได้และ Copy เป็น Available หรือ Reserved ที่กันไว้ให้สมาชิก ทดสอบยืนยันแล้วตรวจ Loan, วันคืนจาก server Asia/Bangkok, Copy Borrowed และ reservation Ready → Completed ใน transaction เดียว; ส่ง request identifier เดิมซ้ำและตรวจว่าได้ผลเดิมไม่มีรายการซ้ำ (FR-01 ถึง FR-04, NFR-DATA-01, ASM-10, ASM-12, ASM-15, ASM-16, ASM-18) |
| AC-บันทึกการยืมหนังสือ-02 | `test_AC_บันทึกการยืมหนังสือ_02` | ทดสอบสมาชิกไม่ใช้งาน ถูกระงับ เป็นบุคคลภายนอก และครบจำนวนตั้งแต่ต้นแยกกรณี ตรวจว่าไม่บันทึกรายการและแสดง “ไม่สามารถยืมได้” (FR-05, ASM-11, ASM-13, ASM-17) |
| AC-บันทึกการยืมหนังสือ-03 | `test_AC_บันทึกการยืมหนังสือ_03` | สแกนหลาย Copy ที่ผ่าน/ไม่ผ่าน สถานะ Reserved ที่ไม่มีสิทธิ์ รหัสซ้ำ และจำนวนที่ครบระหว่างลำดับ ตรวจผลรายเล่ม วันคืน ข้อความปฏิเสธ ไม่เพิ่ม duplicate และความสอดคล้องหลังยืนยัน (FR-02, FR-04, FR-06, NFR-DATA-01, ASM-08, ASM-12 ถึง ASM-15) |

## 7. ลำดับงาน

1. ปรับโค้ดเดิมของ T-03 ให้ค้นหานักศึกษาด้วยรหัสที่สแกน/พิมพ์และบุคลากรด้วยอีเมล; ไม่พบให้แจ้งตาม FR-01; ปรับ T-04 ให้ตรวจสถานะสมาชิก สิทธิ์ จำนวน และ Copy Available หรือ Reserved ที่กันให้ผู้จอง Ready (FR-01, FR-02, FR-05, ASM-11, ASM-12, ASM-19).
2. ปรับโค้ดเดิมของ T-05 ให้ใช้ตารางค่ากำหนดคีย์ (ประเภทสมาชิก, ประเภทหนังสือ) → (จำนวนเล่มสูงสุด, จำนวนวันยืม) โดย seed ค่าชั่วคราวจาก ASM-09 เป็นข้อมูลในตาราง ไม่ hard-code ใน business logic; คำนวณวันยืม/วันคืนที่ server ด้วย Asia/Bangkok (FR-02, FR-03, ASM-09, ASM-10, Q-01).
3. ปรับโค้ดเดิมของ T-06 ให้ตรวจและบันทึกรายการยืม/เปลี่ยน Copy เป็น Borrowed แบบ all-or-nothing ภายใต้ lock/transaction เดียว; ใช้ reservation store เดิมใน `backend/app/reservations/` เปลี่ยน Ready → Completed ในชุดเดียวกันโดยไม่สร้าง store ใหม่ (FR-04, NFR-DATA-01, ASM-15, ASM-18).
4. ปรับโค้ดเดิมของ T-07 ให้ปฏิเสธทั้งรายการเมื่อปัญหาระดับสมาชิกหรือครบจำนวนก่อนเริ่มรายการ และแสดงข้อความทั่วไปตามที่กำหนด (FR-05, ASM-05, ASM-11, ASM-13).
5. ปรับโค้ดเดิมของ T-08 ให้ประเมิน Copy ตามลำดับสแกน, ทำ partial success ตาม FR-06, แสดงผลรายเล่ม และแสดง “รหัสนี้อยู่ในรายการแล้ว” เมื่อสแกนซ้ำโดยไม่เพิ่มจำนวน (FR-05, FR-06, ASM-08, ASM-13, ASM-14).
6. เพิ่มการป้องกันยืนยันซ้ำโดย request identifier ตาม SPEC-004; คำขอเดิมต้องคืนผลเดิมและไม่สร้างรายการซ้ำ (FR-04, NFR-DATA-01, ASM-16).
7. ปรับโค้ดเดิมของ T-12 ให้ทดสอบเกณฑ์ NFR-PERF-01: scan ≤ 1 วินาที, confirm ≤ 10 Copy ≤ 2 วินาที, concurrency 10 librarians และอย่างน้อย 95% ผ่าน.
8. รัน/ปรับการทดสอบ AC-01 ถึง AC-03 ครอบคลุม all-or-nothing, การยืม Copy เดียวกันพร้อมกัน, Ready → Completed และผลรายเล่ม (NFR-DATA-01, AC-01 ถึง AC-03, ASM-15, ASM-18).

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** ค่าจริงของประเภทหนังสือและรายการในตารางค่ากำหนด (ประเภทสมาชิก, ประเภทหนังสือ) สำหรับจำนวนเล่มสูงสุดและจำนวนวันยืมยังไม่ทราบ; ระหว่างรอใช้ค่าชั่วคราวและการจัดประเภทตาม ASM-09 ต้องถามบรรณารักษ์/ผู้กำหนดนโยบายห้องสมุด; ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** เลขบัตรประจำตัวจริงของบุคลากรและแหล่งข้อมูลสำหรับค้นหาด้วยเลขดังกล่าวยังไม่ทราบ; ระหว่างรอให้ค้นบุคลากรด้วยอีเมลที่ใช้เข้าสู่ระบบตาม ASM-19 ต้องถามบรรณารักษ์/ฝ่ายบุคคล; ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
