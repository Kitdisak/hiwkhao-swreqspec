# Test Cases: AC-บันทึกการยืมหนังสือ-01

อ้างอิง: SPEC-บันทึกการยืมหนังสือ-011 (Draft v2)

## ขอบเขต

ทดสอบการบันทึกการยืมของสมาชิกที่มีสิทธิ์ โดยครอบคลุม Copy สถานะ Available และ Reserved ที่กันไว้ให้สมาชิก, วันคืนตาม LoanPolicy และ Asia/Bangkok, สถานะ Copy, รายการจอง Ready → Completed และการบันทึกซ้ำ/ผิดพลาดแบบ all-or-nothing ตาม AC-บันทึกการยืมหนังสือ-01, FR-01 ถึง FR-04, NFR-DATA-01, ASM-09, ASM-10, ASM-12, ASM-15, ASM-16 และ ASM-18.

## กรณีทดสอบ

### กรณียืม Copy สถานะ Available

**ข้อมูลตั้งต้น**

- สมาชิกนักศึกษามีสถานะใช้งานและมีสิทธิ์ยืม
- Copy ของหนังสือทั่วไปมีสถานะ Available
- LoanPolicy นักศึกษา + หนังสือทั่วไปใช้ค่าชั่วคราว 14 วันตาม ASM-09
- ใช้เวลายืม 18 พฤศจิกายน 2569 เวลา 23:30 น. ตาม Asia/Bangkok

**ขั้นตอน**

1. ส่งคำขอยืนยันการยืม Copy ที่ Available
2. ตรวจผลตอบกลับ รายการยืม และสถานะ Copy ใน store

**ผลที่คาดหวัง**

- ระบบบันทึกรายการยืมสำเร็จ
- วันคืนเป็น 2 ธันวาคม 2569 ตามจำนวนวันใน LoanPolicy และวันที่ฝั่ง server ใน Asia/Bangkok (FR-03, ASM-10)
- สถานะ Copy เปลี่ยนเป็น Borrowed และมี LoanItem หนึ่งรายการ (FR-04)

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-01, FR-02 ถึง FR-04, ASM-09, ASM-10.

### กรณียืม Copy Reserved ที่กันไว้ให้ผู้จอง Ready

**ข้อมูลตั้งต้น**

- สมาชิกมีรายการจองชื่อเรื่องเดียวกับ Copy โดยสถานะ Ready
- รายการ Ready กัน Copy นั้นไว้ และ Copy มีสถานะ Reserved

**ขั้นตอน**

1. ยืนยันการยืม Copy Reserved ด้วยสมาชิกผู้จอง
2. ตรวจ Loan, สถานะ Copy และรายการจองใน store เดียวกัน

**ผลที่คาดหวัง**

- ระบบบันทึก Loan และเปลี่ยน Copy เป็น Borrowed
- รายการจอง Ready เปลี่ยนเป็น Completed พร้อมการบันทึก Loan/Copy ใน transaction เดียวกัน

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-01, FR-02, FR-04, NFR-DATA-01, ASM-12, ASM-15, ASM-18.

### กรณีบันทึกซ้ำด้วย request identifier เดิม

**ข้อมูลตั้งต้น**

- สมาชิกและ Copy ผ่านเงื่อนไข
- เตรียม request identifier หนึ่งค่า

**ขั้นตอน**

1. ส่งคำขอยืนยันการยืมด้วย request identifier ดังกล่าว
2. ส่งคำขอเดิมซ้ำโดยใช้ payload และ request identifier เดิม

**ผลที่คาดหวัง**

- ทั้งสองคำตอบให้ผลเดิม
- ไม่มี Loan หรือ LoanItem ซ้ำ

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-01, NFR-DATA-01, ASM-16.

### กรณีเกิดข้อผิดพลาดระหว่างปรับรายการจอง

**ข้อมูลตั้งต้น**

- สมาชิกมี Ready reservation ที่กัน Copy ไว้
- เตรียมให้การเปลี่ยน reservation เป็น Completed ล้มเหลวระหว่าง transaction

**ขั้นตอน**

1. ยืนยันการยืม Copy Reserved
2. ตรวจ Loan, LoanItem, สถานะ Copy และ reservation หลังคำขอล้มเหลว

**ผลที่คาดหวัง**

- ไม่มี Loan หรือ LoanItem ถูกสร้าง
- Copy ยังคง Reserved และ reservation ยังคง Ready

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-01, FR-04, NFR-DATA-01, ASM-15, ASM-18.

## การทดสอบอัตโนมัติ

- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_01_available_copy_records_due_date_and_status` ตรวจ Available, วันคืนตามเวลา Asia/Bangkok, LoanItem และสถานะ Borrowed
- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_01_borrow_completes_reserved_copy_in_same_store` ตรวจ Ready → Completed และ Copy → Borrowed
- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_01_repeated_request_returns_original_result` ตรวจการยืนยันซ้ำและไม่มี Loan ซ้ำ
- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_01_rolls_back_copy_and_loan_if_reservation_fails` ตรวจ rollback เมื่อปรับ reservation ไม่สำเร็จ

ค่าจำนวนวัน 14 วันในกรณีทดสอบอ้างอิงค่าชั่วคราวตาม ASM-09; ค่าจริงของนโยบายยังไม่ทราบตาม Q-01.

# Test Cases: AC-บันทึกการยืมหนังสือ-02

อ้างอิง: SPEC-บันทึกการยืมหนังสือ-011 (Draft v2)

## ขอบเขต

ทดสอบการปฏิเสธทั้งรายการเมื่อสมาชิกไม่ใช้งาน/ถูกระงับสิทธิ์ เป็นบุคคลภายนอก หรือยืมครบจำนวนตั้งแต่ก่อนเริ่มรายการ โดยต้องใช้ข้อความทั่วไปและไม่เปลี่ยนสถานะ Copy ตาม AC-บันทึกการยืมหนังสือ-02, FR-05, ASM-01, ASM-05, ASM-11, ASM-13 และ ASM-17.

## กรณีทดสอบ

### กรณีสมาชิกมีสถานะไม่ใช้งานหรือถูกระงับสิทธิ์

**ข้อมูลตั้งต้น**

- สมาชิกมีสถานะไม่ใช้งานตามข้อมูลสมาชิก (ชุดทดสอบแทนด้วยสถานะ Suspended ที่โมเดลรองรับ)
- Copy ที่ส่งในคำขอมีสถานะ Available

**ขั้นตอน**

1. ยืนยันรายการที่มี Copy Available อย่างน้อยสองเล่ม
2. ตรวจผลระดับรายการและรายเล่ม รวมทั้งข้อมูล Loan และสถานะ Copy

**ผลที่คาดหวัง**

- ระบบปฏิเสธทั้งรายการและแสดง “ไม่สามารถยืมได้”
- ไม่มี Loan/LoanItem ใหม่ และ Copy ทุกเล่มคงสถานะ Available

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-02, FR-05, ASM-05, ASM-13.

### กรณีสมาชิกมีหนังสือเกินกำหนดหรือค่าปรับค้าง

**ข้อมูลตั้งต้น**

- เตรียมสมาชิกแยกกรณีมีหนังสือเกินกำหนดอย่างน้อยหนึ่งรายการ และมีค่าปรับค้างอย่างน้อยหนึ่งรายการ
- Copy ที่ส่งในคำขอมีสถานะ Available

**ขั้นตอน**

1. ยืนยันรายการยืมสำหรับสมาชิกแต่ละกรณี
2. ตรวจผลตอบกลับ รายการ Loan และสถานะ Copy

**ผลที่คาดหวัง**

- แต่ละกรณีถูกปฏิเสธทั้งรายการด้วย “ไม่สามารถยืมได้”
- ไม่มี Loan/LoanItem ใหม่ และ Copy คงสถานะ Available

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-02, FR-02, FR-05, ASM-01, ASM-05, ASM-17.

### กรณีบุคคลภายนอก

**ข้อมูลตั้งต้น**

- สมาชิกมีประเภทเป็นบุคคลภายนอก
- Copy ที่ส่งในคำขอมีสถานะ Available

**ขั้นตอน**

1. พยายามยืนยันรายการยืมที่มี Copy Available
2. ตรวจผลระดับรายการและรายเล่ม รวมทั้งข้อมูล Loan และสถานะ Copy

**ผลที่คาดหวัง**

- ระบบปฏิเสธทั้งรายการด้วย “ไม่สามารถยืมได้”
- ไม่มี Loan/LoanItem ใหม่ และ Copy คงสถานะ Available

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-02, FR-05, ASM-05, ASM-11, ASM-13.

### กรณียืมครบจำนวนก่อนเริ่มรายการ

**ข้อมูลตั้งต้น**

- จำนวน LoanItem ที่ยังไม่คืนของสมาชิกเท่ากับจำนวนสูงสุดใน LoanPolicy
- คำขอใหม่มี Copy สถานะ Available อย่างน้อยสองเล่ม

**ขั้นตอน**

1. ยืนยันรายการยืมใหม่
2. ตรวจผลตอบกลับ จำนวน Loan/LoanItem และสถานะ Copy

**ผลที่คาดหวัง**

- ระบบปฏิเสธทั้งรายการด้วย “ไม่สามารถยืมได้”
- ไม่มี Loan/LoanItem เพิ่ม และ Copy ทุกเล่มคงสถานะ Available

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-02, FR-02, FR-05, ASM-08, ASM-13.

## การทดสอบอัตโนมัติ

- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_02_rejects_ineligible_member_and_whole_list` ทดสอบสมาชิก Suspended, มีรายการเกินกำหนด, มีค่าปรับค้าง และบุคคลภายนอก; ตรวจปฏิเสธทุกเล่ม ไม่มี Loan/LoanItem และ Copy ไม่เปลี่ยนสถานะ
- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_02_rejects_member_at_limit_before_request` เตรียมจำนวน LoanItem ถึง maximum_items ใน LoanPolicy แล้วตรวจว่าปฏิเสธทั้งรายการก่อนบันทึก

# Test Cases: AC-บันทึกการยืมหนังสือ-03

อ้างอิง: SPEC-บันทึกการยืมหนังสือ-011 (Draft v2)

## ขอบเขต

ทดสอบการสแกนหลายเล่มตามลำดับ การบันทึกเฉพาะเล่มที่ผ่าน การแสดงผลรายเล่ม การปฏิเสธเล่มถัดไปเมื่อครบจำนวน และการไม่เพิ่มรหัสประจำเล่มซ้ำ ตาม AC-บันทึกการยืมหนังสือ-03, FR-02, FR-04, FR-05, FR-06, NFR-DATA-01, ASM-03, ASM-08, ASM-13 และ ASM-14.

## กรณีทดสอบ

### กรณีหลายเล่มมีทั้งผ่านและไม่ผ่าน พร้อมรหัสซ้ำ

**ข้อมูลตั้งต้น**

- สมาชิกมีสิทธิ์และยังไม่ครบจำนวนสูงสุด
- รายการสแกนตามลำดับ: Copy ที่ Available, รหัสที่ไม่มี/ไม่ผ่านเงื่อนไข, แล้วสแกนรหัสแรกซ้ำ

**ขั้นตอน**

1. สแกน Copy แรกและรอผลตรวจ
2. สแกนรหัสที่ไม่ผ่านเงื่อนไข
3. สแกน Copy แรกซ้ำ และยืนยันรายการ

**ผลที่คาดหวัง**

- ระบบคงลำดับผลตามลำดับสแกน
- หลังยืนยัน Copy แรกถูกบันทึกพร้อมวันคืน; Copy ที่ไม่ผ่านแสดง “ไม่สามารถยืมได้”
- การสแกนซ้ำแจ้ง “รหัสนี้อยู่ในรายการแล้ว” ทันที ไม่เพิ่มแถวหรือจำนวนซ้ำ
- มี LoanItem เฉพาะ Copy ที่ผ่านเงื่อนไข และสถานะ Copy ที่ไม่ผ่านคงเดิม

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-03, FR-04, FR-06, NFR-DATA-01, ASM-03, ASM-13, ASM-14.

### กรณีครบจำนวนระหว่างสแกน

**ข้อมูลตั้งต้น**

- จำนวน LoanItem ที่ยังไม่คืนเท่ากับจำนวนสูงสุดลบหนึ่ง
- มี Copy Available อย่างน้อยสองเล่มที่ส่งตรวจตามลำดับ

**ขั้นตอน**

1. สแกน Copy แรกและตรวจว่าผ่าน
2. สแกน Copy ถัดไป
3. ยืนยันรายการและตรวจผลรายเล่มกับจำนวน LoanItem

**ผลที่คาดหวัง**

- Copy แรกผ่านและถูกบันทึก
- เมื่อครบจำนวนแล้ว Copy ถัดไปถูกปฏิเสธด้วย “ไม่สามารถยืมได้”
- จำนวน LoanItem รวมไม่เกิน maximum_items; Copy ที่ถูกปฏิเสธคงสถานะ Available

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-03, FR-05, FR-06, ASM-08, ASM-13.

### กรณีตรวจรหัสซ้ำทันทีบนหน้าจอ

**ข้อมูลตั้งต้น**

- เปิดหน้าบันทึกการยืมและเพิ่ม Copy หนึ่งรหัสในรายการแล้ว

**ขั้นตอน**

1. สแกนหรือป้อนรหัสเดิมซ้ำอีกครั้ง
2. ตรวจข้อความตอบกลับและรายการบนหน้าจอก่อนยืนยัน

**ผลที่คาดหวัง**

- แสดง “รหัสนี้อยู่ในรายการแล้ว” ทันที
- รายการยังมี Copy รหัสนั้นเพียงครั้งเดียว และจำนวนเล่มไม่เพิ่ม

**อ้างอิง:** AC-บันทึกการยืมหนังสือ-03, FR-06, ASM-04, ASM-14.

- `backend/tests/test_ac_บันทึกการยืมหนังสือ.py::test_AC_บันทึกการยืมหนังสือ_03_scan_stops_at_member_limit` ตรวจผล scan และ confirm เมื่อเล่มแรกทำให้ครบจำนวน; มีเพียงเล่มแรกถูกบันทึก
