# แผนงาน: จองหนังสือ

อ้างอิง: SPEC-จองหนังสือ-004 (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกที่เข้าสู่ระบบส่งคำขอจองหนังสือและได้รับลำดับคิว (Goal, Constraints, FR-จองหนังสือ-01, FR-จองหนังสือ-02)
- ตรวจสิทธิ์ผู้ใช้และตรวจว่าหนังสืออนุญาตให้จองก่อนบันทึกรายการ (FR-จองหนังสือ-01, FR-จองหนังสือ-04, Constraints)
- เรียงคิวตามเวลาที่บันทึกในระบบ และเมื่อเวลาเท่ากันเรียงตามอักษรแรกของชื่อจาก ก-ฮ (FR-จองหนังสือ-03, NFR-DATA-01, ASM-01)
- ปฏิเสธผู้ใช้ที่ถูกระงับพร้อมแจ้งสาเหตุ และป้องกันการสร้างรายการซ้ำ (FR-จองหนังสือ-04, FR-จองหนังสือ-05, NFR-REL-01, ASM-02)
- จำกัดขอบเขตที่ส่งคำขอและดูคิว ไม่รวมติดตามหรือยกเลิกการจองภายหลัง; ประเด็นที่ยังไม่ชัดรอคำตอบ Open Questions (Scope: Out of scope, Q-01 ถึง Q-06)

## 3. โมเดลข้อมูล

แบบจำลองเชิงแนวคิดเท่าที่รองรับข้อกำหนดที่มี; ขอบเขตคิว/ฟิลด์ที่ใช้แยกคำขอซ้ำยังรอคำตอบ Q-02/Q-04

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| Reservation | member reference, book reference, recorded timestamp, queue position, reservation request reference | FR-จองหนังสือ-02, FR-จองหนังสือ-03, FR-จองหนังสือ-05, NFR-REL-01, NFR-DATA-01 |
| Member | account reference, name (ใช้ตัวอักษรแรกสำหรับ tie-break), reservation eligibility/suspension reason | FR-จองหนังสือ-01, FR-จองหนังสือ-03, FR-จองหนังสือ-04, ASM-01, ASM-02 |
| Book | book reference, reservable status | FR-จองหนังสือ-01, Constraints: หนังสือต้องอนุญาตให้จองและหนังสือสูญหาย/ชำรุด/ซ่อมจองไม่ได้ |

`recorded timestamp` ใช้เป็นลำดับหลัก; เมื่อเวลาเท่ากันเรียงด้วยอักษรแรกของชื่อจาก ก-ฮ ตามข้อกำหนด ส่วนชื่อที่อักษรแรกซ้ำและการระบุคำขอเดียวกันต้องรอคำตอบ (FR-จองหนังสือ-03, NFR-DATA-01, Q-03, Q-04). ยังไม่ระบุระดับการแยกคิวและเลขเริ่มต้น (Q-02).

## 4. API / หน้าจอ

รายการต่อไปนี้เป็นข้อเสนอระดับ interface; การใช้งานจริงต้องรอคำตอบประเด็นที่เกี่ยวข้อง

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ส่งคำขอจอง | `POST /api/reservations`; input: book reference และข้อมูลคำขอ; output: ผลตรวจสิทธิ์, ผลบันทึก และลำดับคิวเมื่อสำเร็จ | FR-จองหนังสือ-01, FR-จองหนังสือ-02, FR-จองหนังสือ-05, AC-จองหนังสือ-01 |
| ดูลำดับคิวหลังส่งคำขอ | `GET /api/books/{bookId}/reservations/queue`; input: book reference; output: ลำดับคิวตามเวลาบันทึกและกติกา tie-break | FR-จองหนังสือ-02, FR-จองหนังสือ-03, NFR-DATA-01, AC-จองหนังสือ-02, Q-02, Q-03 |
| ผลปฏิเสธกรณีถูกระงับ | ใช้ผลตอบกลับจาก `POST /api/reservations`; output: ปฏิเสธคำขอพร้อมสาเหตุการระงับ | FR-จองหนังสือ-04, AC-จองหนังสือ-03, ASM-02 |
| หน้าจอยืนยันการจองและแสดงคิว | input: หนังสือที่เลือกและการยืนยันของสมาชิก; output: ผลการจอง/สาเหตุปฏิเสธและลำดับคิว | FR-จองหนังสือ-01 ถึง FR-จองหนังสือ-04, AC-จองหนังสือ-01 ถึง AC-จองหนังสือ-03 |

รูปแบบการระบุ request เดียวกันและวิธีตอบเมื่อส่งซ้ำยังไม่กำหนดจนกว่าจะได้คำตอบ Q-04 (FR-จองหนังสือ-05, NFR-REL-01, Q-04).

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-จองหนังสือ-004

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ผู้ใช้ต้องเข้าสู่ระบบและหนังสือต้องอนุญาตให้จอง | ตรวจ session/สิทธิ์สมาชิกและสถานะหนังสือก่อนสร้าง Reservation (FR-จองหนังสือ-01, Q-01) | ใช้แล้ว |
| ไม่มี ID: จัดลำดับคิวตามลำดับการจองก่อน-หลัง | ใช้เวลาที่บันทึกในระบบเรียงคิว; เวลาเท่ากันเรียงอักษรแรกชื่อจาก ก-ฮ (FR-จองหนังสือ-03, NFR-DATA-01, ASM-01) | ใช้แล้ว |
| ไม่มี ID: หนังสือสูญหาย ชำรุด หรืออยู่ระหว่างซ่อมจองไม่ได้ | ตรวจสถานะหนังสือก่อนบันทึกรายการจอง (FR-จองหนังสือ-01, Q-01) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-จองหนังสือ-01 | `test_AC_จองหนังสือ_01` | ใช้สมาชิกที่เข้าสู่ระบบและมีสิทธิ์ กับหนังสือที่อนุญาตให้จอง ยืนยันคำขอ ตรวจว่ามีรายการจองและแสดงลำดับคิว (FR-จองหนังสือ-01, FR-จองหนังสือ-02, AC-จองหนังสือ-01) |
| AC-จองหนังสือ-02 | `test_AC_จองหนังสือ_02` | เตรียมคำขอที่มีเวลาบันทึกต่างกันและเท่ากัน ตรวจว่าลำดับเป็นไปตามเวลา และกรณีเวลาเท่ากันเรียงอักษรแรกของชื่อจาก ก-ฮ (FR-จองหนังสือ-03, NFR-DATA-01, AC-จองหนังสือ-02); กรณีอักษรแรกซ้ำรอ Q-03 |
| AC-จองหนังสือ-03 | `test_AC_จองหนังสือ_03` | ใช้สมาชิกที่ถูกระงับ พยายามจอง ตรวจว่าระบบปฏิเสธและแสดงสาเหตุการระงับ (FR-จองหนังสือ-04, AC-จองหนังสือ-03, ASM-02) |

FR-จองหนังสือ-05 และ NFR-REL-01 ยังไม่มี AC เฉพาะ; วิธีทดสอบและความหมายของคำขอซ้ำรอคำตอบ Q-04/Q-05. การตรวจสิทธิ์และสถานะที่ปฏิเสธเพิ่มเติมรอ Q-01.

## 7. ลำดับงาน

1. ยืนยันเงื่อนไขสิทธิ์และสถานะหนังสือที่อนุญาตให้จอง (FR-จองหนังสือ-01, FR-จองหนังสือ-04, Q-01)
2. กำหนดขอบเขตคิวและเลขเริ่มต้นก่อนออกแบบ queue position (FR-จองหนังสือ-02, FR-จองหนังสือ-03, Q-02)
3. ยืนยัน tie-break เมื่ออักษรแรกชื่อซ้ำ (FR-จองหนังสือ-03, NFR-DATA-01, Q-03)
4. กำหนดนิยามคำขอเดียวกันและวิธีป้องกันคำขอซ้ำ (FR-จองหนังสือ-05, NFR-REL-01, Q-04)
5. ออกแบบและพัฒนาการตรวจสิทธิ์ก่อนสร้างรายการจอง (FR-จองหนังสือ-01, AC-จองหนังสือ-01)
6. บันทึกรายการจองและคำนวณ/แสดงคิวตามกติกาที่ตกลง (FR-จองหนังสือ-02, FR-จองหนังสือ-03, NFR-DATA-01, AC-จองหนังสือ-01, AC-จองหนังสือ-02)
7. ปฏิเสธสมาชิกที่ถูกระงับพร้อมสาเหตุ (FR-จองหนังสือ-04, AC-จองหนังสือ-03)
8. ทดสอบ AC ทั้งสามข้อและข้อกำหนดป้องกันรายการซ้ำเมื่อทีมกำหนดเกณฑ์ทดสอบแล้ว (AC-จองหนังสือ-01 ถึง AC-จองหนังสือ-03, FR-จองหนังสือ-05, NFR-REL-01, Q-05)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** นอกจากกรณีผู้ใช้ถูกระงับและหนังสือที่จองไม่ได้ตาม Constraint แล้ว มีเงื่อนไขสิทธิ์หรือสถานะหนังสือใดที่ต้องปฏิเสธการจองอีกบ้าง? ต้องถามทีม/ผู้รับผิดชอบนโยบายการจอง ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** คิวแยกตามหนังสือระดับใด และลำดับคิวเริ่มนับจากเลขใด? ต้องถามทีม/บรรณารักษ์ ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03** หากผู้จองมีอักษรแรกของชื่อเหมือนกัน ระบบใช้ชื่อส่วนใดและเกณฑ์ใดตัดสินลำดับต่อ? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-04** ระบบจะถือว่าคำขอใดเป็นคำขอเดียวกันที่ส่งซ้ำ และแยกจากการจองซ้ำโดยตั้งใจอย่างไร? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-05** AC แต่ละข้อควรอ้างอิง FR/NFR ID ใด และจะตรวจ FR-จองหนังสือ-05 กับ NFR-REL-01/NFR-DATA-01 อย่างไร? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-06** UC Case.pdf มีนโยบายหรือค่ากำหนดใดที่ยังต้องยืนยันสำหรับการจองหนังสือ? ต้องถามผู้จัดทำ UC Case.pdf/ทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
