# แผนงาน: SPEC-004 จองหนังสือ

อ้างอิง: `specs/004-จองหนังสือ/spec.md` (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกที่เข้าสู่ระบบส่งคำขอจองหนังสือระดับชื่อเรื่องและรับผลตรวจสิทธิ์กับลำดับคิว (Goal, Constraints, FR-จองหนังสือ-01, FR-จองหนังสือ-02)
- ตรวจสถานะบัญชี หนังสือเกินกำหนด/ค่าปรับ และสถานะ Copy ก่อนสร้างรายการ โดยปฏิเสธและแจ้งเหตุผลตาม spec (FR-จองหนังสือ-01, FR-จองหนังสือ-04, ASM-02, ASM-03)
- บันทึกรายการใหม่เป็น Waiting; คำนวณตำแหน่งจาก Waiting ของชื่อเรื่องเดียวกันตามเวลาและเกณฑ์เรียงชื่อที่กำหนด (FR-จองหนังสือ-02, FR-จองหนังสือ-03, ASM-01, ASM-04, NFR-DATA-01)
- ป้องกันการสร้างซ้ำด้วย request identifier และการตรวจรายการค้างแบบทนต่อคำขอพร้อมกัน (FR-จองหนังสือ-05, NFR-REL-01, ASM-05)
- จำกัดเฉพาะการส่งจองและแจ้งผล; ไม่ทำหน้าติดตามหรือยกเลิกการจอง และใช้นโยบาย Copy Available แบบชั่วคราวตาม ASM-03 ระหว่างรอ Q-07 (Scope: Out of scope, Q-07)

## 3. โมเดลข้อมูล

แบบจำลองเชิงแนวคิด ใช้เฉพาะข้อมูลจำเป็นต่อข้อกำหนดและอ้างอิง entity ที่ระบบมีอยู่ โดยไม่เพิ่มข้อมูลส่วนบุคคลอื่น (FR-จองหนังสือ-01, FR-จองหนังสือ-03, ASM-01)

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Reservation | reservation_id, request_id, member_id, title_id, recorded_at, status (Waiting/Ready/Completed), queue_position_at_success สำหรับการตอบซ้ำด้วยผลเดิม | FR-จองหนังสือ-02, FR-จองหนังสือ-03, FR-จองหนังสือ-05, NFR-REL-01, NFR-DATA-01, ASM-04, ASM-05 |
| Member / Account (ข้อมูลอ้างอิง) | member_id, account_status, overdue indicator, unpaid-fine indicator, first_name, last_name, member_code | FR-จองหนังสือ-01, FR-จองหนังสือ-03, FR-จองหนังสือ-04, ASM-01, ASM-02 |
| Book title | title_id และความสัมพันธ์ไปยัง Copy ของชื่อเรื่อง | Constraints เรื่องจองระดับชื่อเรื่อง, FR-จองหนังสือ-01, FR-จองหนังสือ-02 |
| BookCopy (ข้อมูลอ้างอิงจาก Catalog) | copy_id, title_id, status (Available/Borrowed/Reserved/Lost/Damaged/อยู่ระหว่างซ่อม) | FR-จองหนังสือ-01, FR-จองหนังสือ-04, AC-จองหนังสือ-03, Constraint เรื่องสถานะ Copy |

ตำแหน่งคิวของ Waiting คำนวณจากจำนวนรายการ Waiting ที่อยู่ก่อนหน้าบวกหนึ่ง ไม่เก็บเป็นค่าคงที่; เก็บตำแหน่งเมื่อคำขอสำเร็จเพื่อคืนผลเดิมเมื่อ request_id เดิมถูกส่งซ้ำ (FR-จองหนังสือ-02, FR-จองหนังสือ-03, ASM-04, ASM-05). การตรวจรายการค้างซ้ำและการสร้างรายการต้องเป็นหน่วยเดียวกันเชิง atomic (FR-จองหนังสือ-05, NFR-REL-01).

## 5. ตารางตรวจ Constraints

Constraints ไม่มี ID เฉพาะใน spec; อ้างอิงด้วยข้อความ Constraint เดิม ไม่สร้าง ID ใหม่

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ผู้ใช้ต้องเข้าสู่ระบบและผ่านเงื่อนไขการจองตาม FR-จองหนังสือ-01 | ยืนยันตัวตนและตรวจ eligibility ก่อนสร้าง Reservation; ใช้ข้อมูล Member/Account และ BookCopy (FR-จองหนังสือ-01, FR-จองหนังสือ-04) | ใช้แล้ว |
| ไม่มี ID: การจองทำได้ระดับชื่อเรื่อง ไม่ผูกกับ Copy ล่วงหน้า | Reservation อ้าง title_id; ตรวจ Copy เพื่ออนุญาต/ปฏิเสธ แต่ไม่ผูกการจองกับสำเนาใด (FR-จองหนังสือ-02, ASM-03) | ใช้แล้ว |
| ไม่มี ID: หนังสือที่สูญหาย ชำรุด หรืออยู่ระหว่างซ่อมต้องไม่สามารถจองได้ | ตรวจสถานะ Copy ก่อนสร้างและทดสอบกรณีไม่มีเล่มที่จองได้ (FR-จองหนังสือ-01, AC-จองหนังสือ-03, ASM-03) | ใช้แล้ว |
| ไม่มี ID: การไม่อนุญาตเมื่อมี Copy Available เป็นนโยบายชั่วคราวระหว่างรอคำยืนยันใน Q-07 | ใช้พฤติกรรมชั่วคราวตาม ASM-03; ไม่สรุปเป็นนโยบายถาวรจนกว่าจะได้คำตอบ Q-07 | ใช้แล้ว |

## 7. ลำดับงาน

1. ตรวจจุดเชื่อมต่อข้อมูลบัญชี สมาชิก หนังสือ และ Copy ที่มีอยู่; ระบุช่องว่างก่อนเลือก storage (FR-จองหนังสือ-01, FR-จองหนังสือ-03).
2. กำหนด Reservation และ request identifier ให้รองรับคิวระดับชื่อเรื่อง สถานะ และการ replay ผลเดิม (FR-จองหนังสือ-02, FR-จองหนังสือ-05, ASM-04, ASM-05).
3. ทำบริการตรวจ eligibility ของสมาชิกและความพร้อมของชื่อเรื่อง/Copy พร้อมข้อความปฏิเสธตาม spec (FR-จองหนังสือ-01, FR-จองหนังสือ-04, AC-จองหนังสือ-03).
4. ทำการป้องกัน request ซ้ำและรายการ Waiting/Ready ซ้ำแบบ atomic เพื่อรองรับการส่งพร้อมกัน (FR-จองหนังสือ-05, NFR-REL-01, AC-จองหนังสือ-01).
5. ทำตัวจัดลำดับคิวแบบ deterministic ตามเวลา ชื่อจริง นามสกุล และรหัสสมาชิก โดยคำนวณคิว Waiting ระดับชื่อเรื่อง (FR-จองหนังสือ-03, NFR-DATA-01, ASM-01, ASM-04).
6. ทำ `POST /api/reservations` ให้สร้างรายการและคืนคิวหรือผลปฏิเสธตาม validation (FR-จองหนังสือ-01 ถึง FR-จองหนังสือ-05).
7. ทำหน้าส่งคำขอและแสดงผลสำเร็จ/ปฏิเสธ พร้อมใช้ request_id เดิมเมื่อลองส่งซ้ำ (FR-จองหนังสือ-02, FR-จองหนังสือ-04, FR-จองหนังสือ-05).
8. เพิ่มชุดทดสอบ AC-01 ถึง AC-03 รวมกรณี concurrent request และ tie-break; ตรวจไม่ทำส่วนติดตามหรือยกเลิกการจอง (AC-จองหนังสือ-01 ถึง AC-จองหนังสือ-03, Scope: Out of scope).

## 8. สิ่งที่ยังไม่ทำ

- **Q-07** บรรณารักษ์ยืนยันหรือไม่ว่าต้องปฏิเสธการจองเมื่อชื่อเรื่องมี Copy สถานะ Available และแจ้ง “มีเล่มว่าง สามารถยืมได้ที่ห้องสมุด”? ระหว่างรอคำยืนยัน ให้ใช้พฤติกรรมนี้ตาม ASM-03 ต้องถามบรรณารักษ์/ผู้รับผิดชอบนโยบายการจอง ส่วนที่เกี่ยวข้องกับการตัดสินใจนโยบายถาวรจะยังไม่สร้างจนกว่าจะได้คำตอบ; ระหว่างนี้ให้ใช้พฤติกรรมชั่วคราวตาม ASM-03

## ประเด็นตรวจสอบสำหรับทีม

- Constraints ทั้งสี่ข้อไม่มี ID เฉพาะ; ตารางตรวจจึงอ้างข้อความ Constraint โดยตรง ไม่สร้าง ID.
- AC-จองหนังสือ-01 กรณี 01-4 ทดสอบยากกว่ากรณีทั่วไป เพราะต้องประสานคำขอพร้อมกันและยืนยันความเป็น atomic; ต้องใช้ชุดทดสอบที่ควบคุม concurrency ได้.
- AC-จองหนังสือ-02 กรณี 02-2 ทดสอบยากกว่ากรณีทั่วไป เพราะต้องตรึงเวลาให้เท่ากันถึงหลักวินาทีและตรวจการเรียงภาษาไทย/ชื่อที่ไม่ใช่ภาษาไทย; ควรทดสอบตัวเปรียบเทียบแยกจากการจัดเก็บจริง.
- Q-07 ยังไม่ตัดสินนโยบายถาวรเรื่อง Copy Available; ไม่เดาเกินพฤติกรรมชั่วคราวที่ spec ระบุไว้ใน ASM-03.
