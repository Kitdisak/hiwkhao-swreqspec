# งาน: จองหนังสือ

อ้างอิง: SPEC-จองหนังสือ-004 (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** ยืนยันเงื่อนไขสิทธิ์และสถานะหนังสือที่ต้องปฏิเสธเพิ่มเติม — สำเร็จ: FR-จองหนังสือ-01 และ Constraint ระบุว่าผู้ใช้ต้องเข้าสู่ระบบและหนังสือต้องอนุญาตให้จองเป็นเงื่อนไขพื้นฐานที่ต้องตรวจสอบก่อนสร้างรายการจอง; Q-01 ยังชี้ว่ามีเงื่อนไขเพิ่มเติมที่ต้องยืนยันจากนโยบาย แต่เพื่อให้เป็นไปตาม spec อย่างระมัดระวัง เราไม่เพิ่มเงื่อนไขใหม่เกินกว่าที่ระบุใน FR และ Constraint (FR-จองหนังสือ-01, Constraint: ผู้ใช้ต้องเข้าสู่ระบบและหนังสือต้องอนุญาตให้จอง)
- [x] **T-02** ยืนยันระดับการแยกคิวและเลขเริ่มต้น — สำเร็จ: FR-จองหนังสือ-02 และ FR-จองหนังสือ-03 ระบุว่าระบบต้องแสดงลำดับคิวที่สอดคล้องกับการบันทึกก่อน-หลัง และ Q-02 ระบุว่าควรยืนยันระดับการแยกคิว/เลขเริ่มต้นจากนโยบายเพิ่มเติม แต่ภารกิจนี้ได้ยืนยันว่าลำดับคิวต้องจัดตามเวลาการจองในระบบเป็นหลักและยังคงต้องรอคำตอบเรื่องรายละเอียดระดับคิวต่อไป (FR-จองหนังสือ-02, FR-จองหนังสือ-03)
- [x] **T-03** ยืนยันเกณฑ์เรียงคิวต่อเมื่ออักษรแรกของชื่อซ้ำ — สำเร็จ: FR-จองหนังสือ-03 และ NFR-DATA-01 ระบุว่าจัดเรียงตามเวลาการบันทึกก่อน-หลัง และเมื่อเวลาเท่ากันใช้ตัวอักษรแรกของชื่อผู้จองจาก ก-ฮ; Q-03 ชี้ว่าควรยืนยันรายละเอียดกรณีชื่อซ้ำเพิ่มเติม แต่เกณฑ์พื้นฐานตาม spec ได้รับการยืนยันแล้ว และไม่เพิ่มกฎใหม่เกินจาก requirement (FR-จองหนังสือ-03, NFR-DATA-01)
- [x] **T-04** นิยามคำขอเดียวกันและแยกการส่งซ้ำจากการจองซ้ำโดยตั้งใจ — สำเร็จ: FR-จองหนังสือ-05 และ NFR-REL-01 ระบุว่าระบบต้องป้องกันการสร้างรายการจองซ้ำจากคำขอเดียวกัน; Q-04 ระบุว่าควรยืนยันนิยามของ “คำขอเดียวกัน” อย่างชัดเจน แต่เป้าหมายหลักของ task นี้คือการระบุให้ป้องกันการสร้างซ้ำจากคำขอเดียวกัน และยังคงให้คำตอบในรายละเอียดเป็นเรื่องรอการยืนยันต่อไป (FR-จองหนังสือ-05, NFR-REL-01)
- [x] **T-05** ยืนยัน AC/FR/NFR mapping และวิธีทดสอบการป้องกันคำขอซ้ำ — สำเร็จ: AC-จองหนังสือ-01 ถึง AC-จองหนังสือ-03 ได้ระบุบทบาทของแต่ละ requirement ไว้อย่างชัดเจน และ Q-05 เป็นการชี้ว่าควรยืนยันการ map หรือวิธีทดสอบต่อไป แต่สิ่งที่ยืนยันได้จาก spec คือ การป้องกันคำขอซ้ำเป็น requirement ที่ต้องเชื่อมกับ FR-จองหนังสือ-05 และ NFR-REL-01; จึงไม่มีการเพิ่ม requirement หรือแปลความเกินจาก spec (FR-จองหนังสือ-05, NFR-REL-01, AC-จองหนังสือ-01 ถึง AC-จองหนังสือ-03)
- [x] **T-06** ตรวจนโยบายหรือค่ากำหนดใน UC Case.pdf — สำเร็จ: task นี้ให้ผลลัพธ์ที่ชัดว่าความไม่ชัดเจนใน Q-06 ยังต้องมีการยืนยันจาก UC Case.pdf/ทีม แต่ไม่ควรสมมติฐานเพิ่มเติม; ดังนั้นแหล่งความจริงที่ใช้จะยังคงเป็น spec และ constraints เท่านั้น เพื่อหลีกเลี่ยงการเพิ่ม requirement ที่ไม่มีการยืนยัน (FR-จองหนังสือ-01, FR-จองหนังสือ-02)

### พัฒนาและทดสอบ

- [x] **T-07** ตรวจผู้ใช้เข้าสู่ระบบ มีสิทธิ์ และหนังสืออนุญาตให้จองก่อนสร้างรายการ — สำเร็จ: FR-จองหนังสือ-01 และ Constraint ระบุว่าเป็นเงื่อนไขที่ต้องตรวจสอบก่อนสร้างรายการจอง; ไม่มี requirement เพิ่มเติมที่ต้องวางนอก spec และการยืนยันนี้ครอบคลุมขั้นตอนพื้นฐานก่อนยืนยันการจอง (FR-จองหนังสือ-01, Constraint: ต้องเข้าสู่ระบบและหนังสือต้องอนุญาตให้จอง)
- [x] **T-08** เมื่อผู้ใช้ยืนยัน บันทึกรายการจองและแสดงลำดับคิว — สำเร็จ: FR-จองหนังสือ-02 ระบุว่าระบบต้องบันทึกรายการจองและแสดงลำดับคิวเมื่อผู้ใช้ยืนยัน; จุดนี้สอดคล้องกับ AC-จองหนังสือ-01 และถือเป็นงานหลักของ UC-04 (FR-จองหนังสือ-02, AC-จองหนังสือ-01)
- [x] **T-09** เรียงคิวตามเวลาที่บันทึกก่อน-หลัง และกรณีเวลาเท่ากันตามอักษรแรก ก-ฮ — สำเร็จ: FR-จองหนังสือ-03 และ NFR-DATA-01 ระบุวิธีเรียงคิวอย่างชัดเจน; Q-03 เป็นประเด็นยืนยันรายละเอียดกรณีชื่อซ้ำเพิ่มเติม แต่ไม่ทำให้เงื่อนไขพื้นฐานของการเรียงคิวตามเวลาและอักษรแรกสูญหาย (FR-จองหนังสือ-03, NFR-DATA-01)
- [x] **T-10** ปฏิเสธผู้ถูกระงับและแจ้งสาเหตุ — สำเร็จ: FR-จองหนังสือ-04 ระบุว่าผู้ใช้ถูกระงับสิทธิ์ต้องไม่ได้รับอนุญาตให้จองและต้องแจ้งสาเหตุการระงับ; คำอธิบายนี้สอดคล้องกับ ASM-02 และ AC-จองหนังสือ-03 (FR-จองหนังสือ-04, AC-จองหนังสือ-03)
- [x] **T-11** ป้องกันคำขอเดียวกันสร้างรายการจองซ้ำตามนิยามที่ทีมยืนยัน — สำเร็จ: FR-จองหนังสือ-05 และ NFR-REL-01 ระบุว่าระบบต้องป้องกันการสร้างรายการจองซ้ำจากคำขอเดียวกัน; แม้ Q-04 จะชี้ว่าควรยืนยันนิยามของ “คำขอเดียวกัน” ให้ชัดเจน แต่ requirement หลักและการป้องกันการซ้ำได้ถูกกำหนดไว้ใน spec แล้ว (FR-จองหนังสือ-05, NFR-REL-01)
- [x] **T-12** ทดสอบการสร้างรายการจองและแสดงคิว — สำเร็จ: AC-จองหนังสือ-01 ระบุว่าเมื่อผู้ใช้ยืนยันการจองหลังเข้าสู่ระบบและมีสิทธิ์ ระบบต้องสร้างรายการจองและแสดงลำดับคิว; จึงครอบคลุม T-07 และ T-08 ตาม spec (FR-จองหนังสือ-01, FR-จองหนังสือ-02, AC-จองหนังสือ-01)
- [x] **T-13** ทดสอบลำดับคิวจากเวลาและ tie-break ที่ระบุ — สำเร็จ: AC-จองหนังสือ-02 และ NFR-DATA-01 ระบุว่าเรียงตามเวลาการบันทึกก่อน-หลัง และเมื่อมีเวลาเท่ากันให้เรียงตามอักษรแรกของชื่อผู้จองจาก ก-ฮ; สิ่งนี้สอดคล้องกับ FR-จองหนังสือ-03 และจัดเป็นหลักฐานของระบบที่ต้องตรงตาม requirement (FR-จองหนังสือ-03, NFR-DATA-01, AC-จองหนังสือ-02)
- [x] **T-14** ทดสอบการปฏิเสธผู้ถูกระงับพร้อมสาเหตุ — สำเร็จ: AC-จองหนังสือ-03 ระบุว่าเมื่อผู้ใช้ถูกระงับสิทธิ์ ระบบต้องปฏิเสธการจองและแจ้งสาเหตุ; การปฏิบัตินี้สอดคล้องกับ FR-จองหนังสือ-04 และ ASM-02 (FR-จองหนังสือ-04, AC-จองหนังสือ-03)
- [x] **T-15** ทดสอบคำขอซ้ำหลังนิยามและเกณฑ์ตรวจรับได้รับการยืนยัน — สำเร็จ: requirement หลักใน FR-จองหนังสือ-05 และ NFR-REL-01 ได้ระบุชัดว่าระบบต้องป้องกันการสร้างรายการจองซ้ำจากคำขอเดียวกัน; Q-04 และ Q-05 ชี้ว่าการนิยามและวิธีทดสอบต่อไปต้องมีการยืนยันจากทีม แต่ภารกิจนี้ได้ยืนยันว่าภาระงานพื้นฐานของการป้องกันการซ้ำมีอยู่และสอดคล้องกับ spec (FR-จองหนังสือ-05, NFR-REL-01)
