# แผนงาน: ต่ออายุการยืมหนังสือ

อ้างอิง: SPEC-ต่ออายุการยืมหนังสือ-006 (Draft v2)

## 1. สรุปแนวทาง

- สมาชิกดูรายการหนังสือที่กำลังยืมและเลือกส่งคำขอต่ออายุ (FR-ต่ออายุการยืมหนังสือ-01, Goal)
- ตรวจวันครบกำหนด คิวจอง และจำนวนครั้งที่ต่ออายุ ก่อนตัดสินผลคำขอ (FR-ต่ออายุการยืมหนังสือ-02, Constraints)
- เมื่อผ่านเงื่อนไข คำนวณวันคืนใหม่และแสดงผลสำเร็จ โดยค่าระยะเวลารอ Q-01 (FR-ต่ออายุการยืมหนังสือ-03, Q-01)
- เมื่อเกินกำหนด มีผู้จองต่อ หรือถึงเพดานจำนวนครั้ง ให้ปฏิเสธด้วยข้อความที่กำหนด (FR-ต่ออายุการยืมหนังสือ-04, ASM-01, ASM-02)
- ออกแบบการอัปเดตวันคืนให้สอดคล้องทุกส่วนตาม FR-05/NFR-DATA-01 แต่ยังไม่ล็อกรายละเอียดจนกว่าจะตอบ Q-03/Q-04 และเกณฑ์ AC-03 รอ Q-02 (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01, Q-02, Q-03, Q-04)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| Loan | member reference, book reference, due date, renewal count, reservation queue reference | FR-ต่ออายุการยืมหนังสือ-01, FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, FR-ต่ออายุการยืมหนังสือ-05 |
| RenewalPolicy | book category, member category, maximum renewal count, renewal duration | Constraints: จำกัดจำนวนครั้งและระยะเวลาตามประเภทหนังสือ/สมาชิก; FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, Q-01 |

`RenewalPolicy` แสดงเพียงข้อมูลแนวคิดที่ต้องมีเพื่อรองรับ constraint ตามประเภท; ค่าเพดานและระยะเวลายังไม่กำหนดจนกว่าจะได้คำตอบ Q-01 (Constraints, Q-01). ขอบเขตของข้อมูลปลายทางที่ต้องรับวันคืนใหม่และพฤติกรรมเมื่ออัปเดตไม่ครบยังรอคำตอบ Q-03/Q-04 (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01, Q-03, Q-04).

## 4. API / หน้าจอ

ข้อเสนอระดับ interface เท่านั้น; การคำนวณวันคืนใหม่และการอัปเดตส่วนที่เกี่ยวข้องต้องรอคำตอบ Q-01/Q-03/Q-04

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| รายการหนังสือที่กำลังยืม | `GET /api/me/loans`; input: ผู้ใช้ที่ยืนยันตัวตนแล้ว; output: รายการ Loan และข้อมูลที่ใช้ตรวจสิทธิ์ต่ออายุ | FR-ต่ออายุการยืมหนังสือ-01 |
| ส่งคำขอต่ออายุ | `POST /api/loans/{loanId}/renew`; input: loan reference และคำขอต่ออายุ; output: ผลตรวจเงื่อนไข, วันคืนใหม่/ผลสำเร็จ หรือข้อความ “ไม่สามารถต่ออายุได้” | FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, FR-ต่ออายุการยืมหนังสือ-04, AC-ต่ออายุการยืมหนังสือ-01, AC-ต่ออายุการยืมหนังสือ-02 |
| หน้ารายการยืมและผลต่ออายุ | input: รายการ Loan; output: รายการหนังสือที่กำลังยืม, ผลตรวจ, วันคืนใหม่หรือผลปฏิเสธ | FR-ต่ออายุการยืมหนังสือ-01 ถึง FR-ต่ออายุการยืมหนังสือ-04, AC-ต่ออายุการยืมหนังสือ-01 ถึง AC-ต่ออายุการยืมหนังสือ-03 |

## 5. ตารางตรวจ Constraints

Constraints ไม่มี ID เฉพาะใน spec จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ต่ออายุการยืมหนังสือ-006

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: หนังสือต้องยังไม่เกินกำหนดและไม่มีผู้อื่นจองต่อ | ตรวจ due date และ reservation queue ก่อนพิจารณาต่ออายุ; ปฏิเสธเมื่อเกินกำหนดหรือมีผู้จองต่อ (FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-04, AC-ต่ออายุการยืมหนังสือ-02) | ใช้แล้ว |
| ไม่มี ID: ต่ออายุได้เฉพาะเมื่อไม่มีผู้ใช้อื่นจองไว้และยังไม่เกินจำนวนครั้งที่กำหนด | ตรวจคิวจองและจำนวนครั้งเทียบ RenewalPolicy; ค่าจำนวนครั้งยังรอ Q-01 (FR-ต่ออายุการยืมหนังสือ-02, Q-01) | ใช้แล้ว |
| ไม่มี ID: ระยะเวลายืมขึ้นอยู่กับประเภทหนังสือและประเภทสมาชิก | RenewalPolicy แยกประเภทหนังสือและสมาชิก; ค่าระยะเวลาและเพดานต้องรอคำตอบ (FR-ต่ออายุการยืมหนังสือ-03, Q-01) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ต่ออายุการยืมหนังสือ-01 | `test_AC_ต่ออายุการยืมหนังสือ_01` | เตรียม Loan ที่ยังไม่เกินกำหนด ไม่มีผู้จองต่อ และยังอยู่ในจำนวนครั้งที่อนุญาต ส่งคำขอต่ออายุ ตรวจวันคืนใหม่และผลสำเร็จ; ค่าคาดหวังวันคืนรอ Q-01 (FR-ต่ออายุการยืมหนังสือ-01 ถึง FR-ต่ออายุการยืมหนังสือ-03, AC-ต่ออายุการยืมหนังสือ-01, Q-01) |
| AC-ต่ออายุการยืมหนังสือ-02 | `test_AC_ต่ออายุการยืมหนังสือ_02` | ทำกรณีทดสอบแยกสำหรับเกินกำหนด, มีผู้จองต่อ และถึงจำนวนครั้งสูงสุด ตรวจว่าทุกกรณีถูกปฏิเสธพร้อมข้อความ “ไม่สามารถต่ออายุได้”; จำนวนครั้งสูงสุดรอ Q-01 (FR-ต่ออายุการยืมหนังสือ-04, AC-ต่ออายุการยืมหนังสือ-02, ASM-02, Q-01) |
| AC-ต่ออายุการยืมหนังสือ-03 | `test_AC_ต่ออายุการยืมหนังสือ_03` | เตรียม Loan ที่ยังไม่เกินกำหนดและผ่านเงื่อนไข ส่งคำขอและตรวจว่าระบบดำเนินการต่ออายุตามเงื่อนไขปกติ; ยังตั้งเงื่อนไข “ใกล้ครบกำหนด” เป็นข้อมูลทดสอบไม่ได้จนกว่าจะได้ Q-02 (FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, AC-ต่ออายุการยืมหนังสือ-03, Q-02) |

การทดสอบยืนยันวันคืนใหม่ให้ตรงกันทุกส่วนยังออกแบบไม่ครบจนกว่าจะทราบขอบเขตส่วนที่เกี่ยวข้องและเกณฑ์ตรวจ (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01, Q-03, Q-04).

## 7. ลำดับงาน

1. ยืนยันเพดานจำนวนครั้งและระยะเวลาตามประเภทหนังสือ/สมาชิก (Constraints, FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, Q-01)
2. แสดงรายการหนังสือที่สมาชิกกำลังยืม (FR-ต่ออายุการยืมหนังสือ-01)
3. ตรวจวันครบกำหนด คิวจอง และจำนวนครั้งตามนโยบายที่ยืนยันแล้ว (FR-ต่ออายุการยืมหนังสือ-02, Q-01)
4. คำนวณวันคืนใหม่ตามประเภทหนังสือและสมาชิก (FR-ต่ออายุการยืมหนังสือ-03, Q-01)
5. ยืนยันขอบเขตข้อมูลทุกส่วนที่ต้องอัปเดตและผลกรณีอัปเดตไม่ครบ ก่อนกำหนดขั้นตอนบันทึก (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01, Q-03, Q-04)
6. แสดงข้อความปฏิเสธทั่วไปเมื่อเกินกำหนด มีผู้จองต่อ หรือถึงเพดานต่ออายุ (FR-ต่ออายุการยืมหนังสือ-04, ASM-01, ASM-02)
7. ยืนยันตัวเลขเกณฑ์ “ใกล้ครบกำหนด” ก่อนทดสอบ AC-03 (AC-ต่ออายุการยืมหนังสือ-03, Q-02)
8. รันทดสอบ AC ทั้งสามข้อและการอัปเดตวันคืนให้สอดคล้องตามเกณฑ์ที่ทีมยืนยัน (AC-ต่ออายุการยืมหนังสือ-01 ถึง AC-ต่ออายุการยืมหนังสือ-03, FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01, Q-04)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** จำนวนครั้งสูงสุดที่ต่ออายุได้และระยะเวลายืมใหม่กำหนดเท่าใด โดยระยะเวลาต้องแยกตามประเภทหนังสือและประเภทสมาชิกอย่างไร? ต้องถามบรรณารักษ์/ผู้กำหนดนโยบายการยืม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** “ใกล้ครบกำหนด” ใน AC-ต่ออายุการยืมหนังสือ-03 หมายถึงเหลือเวลากี่วันหรือกี่ชั่วโมงก่อนวันคืน? ต้องถามทีม/ผู้กำหนดนโยบายการยืม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03** FR-ต่ออายุการยืมหนังสือ-05 ครอบคลุมส่วนใดของระบบบ้าง และต้องจัดการอย่างไรหากอัปเดตวันคืนใหม่ได้ไม่ครบทุกส่วน? ต้องถามทีม/ผู้รับผิดชอบข้อมูลการยืม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-04** จะตรวจ FR-ต่ออายุการยืมหนังสือ-05 และ NFR-DATA-01 อย่างไร และ AC ข้อใดครอบคลุมการอัปเดตวันคืนใหม่ให้สอดคล้องกัน? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
