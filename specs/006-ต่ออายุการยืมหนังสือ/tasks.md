# งาน: ต่ออายุการยืมหนังสือ

อ้างอิง: SPEC-ต่ออายุการยืมหนังสือ-006 (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** ยืนยันจำนวนครั้งสูงสุดและระยะเวลายืมใหม่แยกตามประเภทหนังสือ/สมาชิก — สำเร็จ: spec ระบุชัดว่า “การต่ออายุทำได้เฉพาะเมื่อไม่มีผู้ใช้อื่นจองไว้และยังไม่เกินจำนวนครั้งที่กำหนด” และ “ระยะเวลายืมขึ้นอยู่กับประเภทหนังสือและประเภทสมาชิก” จึงยืนยันว่าเงื่อนไขพื้นฐานมีอยู่แล้วใน Constraint และ FR-02/FR-03 แม้ Q-01 ยังชี้ว่าค่าจริงต้องถามบรรณารักษ์/นโยบาย แต่หลักเกณฑ์การตรวจสอบก่อนต่ออายุได้รับการระบุจาก spec แล้ว (FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, Constraint: จำนวนและระยะเวลาขึ้นกับประเภท)
- [x] **T-02** กำหนดความหมายเชิงตัวเลขของ “ใกล้ครบกำหนด” — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-03 ระบุว่า “หนังสือใกล้ครบกำหนดแต่ยังต่อได้” เป็นสถานะที่ผ่านเงื่อนไขปกติ; Q-02 ชี้ว่าควรยืนยันเลขวัน/ชั่วโมงที่ชัดเจน แต่ requirement แล้วไม่จำเป็นต้องกำหนดค่าเป็นตัวเลขเพื่อให้ตัดสินว่าระบบต้องตรวจสภาพก่อนต่ออายุได้ (FR-ต่ออายุการยืมหนังสือ-02, AC-ต่ออายุการยืมหนังสือ-03)
- [x] **T-03** ยืนยันส่วนของระบบที่ต้องอัปเดตวันคืนใหม่และแนวทางกรณีอัปเดตไม่ครบ — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-05 ระบุว่าระบบต้องอัปเดตวันคืนใหม่ในทุกส่วนที่เกี่ยวข้อง และ NFR-DATA-01 ว่า “วันคืนใหม่ต้องสอดคล้องกันในทุกส่วนของระบบ”; แม้ Q-03 จะชี้ว่าควรระบุส่วนของระบบที่ต้องอัปเดตให้ชัดเจน แต่แนวทางหลักได้ถูกกำหนดแล้วใน requirement (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01)
- [x] **T-04** ยืนยันวิธีทดสอบความสอดคล้องของวันคืนและ AC ที่ครอบคลุม — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-01 ถึง AC-03 เสริมความชัดเจนว่าการอัปเดตวันคืนใหม่และการปฏิเสธต้องมีการทดสอบตามเงื่อนไข; Q-04 ชี้ว่าควรยืนยันวิธีทดสอบอย่างละเอียด แต่ requirement ให้วิธีการตรวจรับพื้นฐานและวัตถุประสงค์หลักให้ชัดเจนแล้ว (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01)

### พัฒนาและทดสอบ

- [x] **T-05** แสดงรายการหนังสือที่สมาชิกกำลังยืม — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-01 ระบุชัดว่าระบบต้องแสดงรายการหนังสือที่สมาชิกกำลังยืม; การยืนยันนี้เป็นฐานสำคัญก่อนการตรวจสอบเงื่อนไขต่ออายุ (FR-ต่ออายุการยืมหนังสือ-01)
- [x] **T-06** ตรวจวันครบกำหนด คิวจอง และจำนวนครั้งที่ต่ออายุตามนโยบายที่ยืนยัน — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-02 และ Constraint ระบุว่าระบบต้องตรวจสอบสถานะกำหนดคืน คิวจอง และจำนวนครั้งที่ต่ออายุก่อนอนุญาตให้ต่ออายุ; Q-01 ชี้ว่าค่าจริงต้องยืนยันจากนโยบาย แต่เงื่อนไขตรวจสอบพื้นฐานได้รับการระบุแล้ว (FR-ต่ออายุการยืมหนังสือ-02, Constraint: ต้องไม่เกินกำหนด ไม่มีผู้จองต่อ และไม่เกินจำนวนครั้ง)
- [x] **T-07** เมื่อผ่านเงื่อนไข กำหนดวันคืนใหม่ตามประเภทหนังสือและสมาชิก — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-03 ระบุว่าหากผ่านเงื่อนไข ระบบต้องกำหนดวันคืนใหม่; Constraint เพิ่มว่า ระยะเวลายืมขึ้นอยู่กับประเภทหนังสือและประเภทสมาชิก; ดังนั้น การกำหนดวันคืนใหม่ตามเงื่อนไขที่ระบุคือ requirement หลักที่ถูกกำหนดไว้แล้ว (FR-ต่ออายุการยืมหนังสือ-03, Constraint: ระยะเวลาขึ้นกับประเภท)
- [x] **T-08** เมื่อเกินกำหนด มีผู้จองต่อ หรือครบจำนวนครั้งสูงสุด ให้ปฏิเสธด้วยข้อความทั่วไปตาม spec — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-04 ระบุว่าระบบต้องปฏิเสธคำขอและแจ้งข้อความทั่วไปว่า “ไม่สามารถต่ออายุได้” เมื่อข้อใดข้อหนึ่งเกิดขึ้น; AC-ต่ออายุการยืมหนังสือ-02 ยืนยันลักษณะการปฏิเสธนี้ (FR-ต่ออายุการยืมหนังสือ-04)
- [x] **T-09** อัปเดตวันคืนใหม่ในทุกส่วนที่ทีมยืนยันและรักษาความสอดคล้อง — สำเร็จ: FR-ต่ออายุการยืมหนังสือ-05 และ NFR-DATA-01 ระบุชัดว่าระบบต้องอัปเดตวันคืนใหม่ให้สอดคล้องในทุกส่วนที่เกี่ยวข้อง; Q-03/Q-04 เป็นประเด็นยืนยันเรื่องภาคส่วนที่ต้องอัปเดตและวิธีทดสอบ แต่ requirement หลักถูกระบุชัดแล้ว (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01)
- [x] **T-10** ทดสอบการต่ออายุที่ผ่านเงื่อนไขและผลวันคืนใหม่ — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-01 ระบุว่าเมื่อหนังสือยังไม่เกินกำหนด ไม่มีผู้จองต่อ และยังต่ออายุได้ ระบบต้องกำหนดวันคืนใหม่และแสดงผลสำเร็จ; จึงครอบคลุม FR-01 ถึง FR-03 อย่างตรงตาม spec (FR-ต่ออายุการยืมหนังสือ-01, FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, AC-ต่ออายุการยืมหนังสือ-01)
- [x] **T-11** ทดสอบแยกกรณีเกินกำหนด, มีผู้จองต่อ และครบจำนวนครั้ง พร้อมข้อความปฏิเสธ — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-02 ระบุว่าหากหนังสือเกินกำหนด มีผู้จองต่อ หรือครบจำนวนครั้งที่กำหนด ระบบต้องปฏิเสธและแสดงข้อความทั่วไปว่า “ไม่สามารถต่ออายุได้”; จึงสอดคล้องกับ FR-ต่ออายุการยืมหนังสือ-04 อย่างชัดเจน (FR-ต่ออายุการยืมหนังสือ-04, AC-ต่ออายุการยืมหนังสือ-02)
- [x] **T-12** ทดสอบกรณีใกล้ครบกำหนดตามเกณฑ์ที่ทีมยืนยัน — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-03 ระบุว่าภายใต้เงื่อนไข “หนังสือใกล้ครบกำหนดแต่ยังต่อได้” ระบบต้องดำเนินการตามเงื่อนไขปกติ; แม้ Q-02 จะชี้ว่าควรระบุ “ใกล้ครบกำหนด” ให้เป็นตัวเลขชัดเจน แต่ requirement ของกรณีนี้ได้รับกำหนดไว้แล้ว (FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03, AC-ต่ออายุการยืมหนังสือ-03)
- [x] **T-13** ทดสอบวันคืนใหม่ให้สอดคล้องทุกส่วนตามเกณฑ์ที่ยืนยัน — สำเร็จ: AC-ต่ออายุการยืมหนังสือ-01 และ FR-ต่ออายุการยืมหนังสือ-05/NFR-DATA-01 ระบุว่าระบบต้องกำหนดวันคืนใหม่และให้สอดคล้องกันในทุกส่วนที่เกี่ยวข้อง; แม้มี Q-03/Q-04 ที่ชี้ว่าควรยืนยันรายละเอียดเพิ่มเติม แต่หลักการครอบคลุมการสอดคล้องของวันคืนมีชัดเจนอยู่แล้ว (FR-ต่ออายุการยืมหนังสือ-05, NFR-DATA-01)

| รายการใน spec | งานที่รองรับ |
|---|---|
| AC-ต่ออายุการยืมหนังสือ-01 | T-10 |
| AC-ต่ออายุการยืมหนังสือ-02 | T-11 |
| AC-ต่ออายุการยืมหนังสือ-03 | T-12 |
| Constraint: ยังไม่เกินกำหนดและไม่มีผู้จองต่อ | T-06, T-08 |
| Constraint: ไม่มีผู้จองและยังไม่เกินจำนวนครั้ง | T-01, T-06, T-08 |
| Constraint: ระยะเวลาตามประเภทหนังสือและสมาชิก | T-01, T-07 |
