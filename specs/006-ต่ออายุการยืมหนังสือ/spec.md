# Feature: ต่ออายุการยืมหนังสือ
Spec ID: SPEC-ต่ออายุการยืมหนังสือ-006 | Source: SRS v0.3 | Use case: UC-06
Owner: ทีม หิวข้าว | Status: Draft v2 | Updated: 2569-11-16

## Goal
สมาชิกต่ออายุการยืมหนังสือได้เมื่อผ่านเงื่อนไขของห้องสมุด โดยวันคืนใหม่ต้องคำนวณจากวันครบกำหนดเดิม ไม่ใช่จากวันที่กดต่ออายุ

## Primary Actor
นักศึกษา / สมาชิก / บรรณารักษ์

## Scope
### In scope
- แสดงรายการยืมพร้อมสถานะการต่ออายุ
- ตรวจสอบเงื่อนไขการต่ออายุ
- กำหนดวันคืนใหม่และแสดงผลการต่ออายุ
- บันทึกประวัติการต่ออายุและแจ้งเตือนวันครบกำหนด
### Out of scope
- รับคืนหนังสือ (UC-12)
- หนังสืออ้างอิง (reference book) ที่ยืมออกไม่ได้ตั้งแต่แรก

## Constraints
- หนังสือต้องยังไม่เกินกำหนดตามเวลา ณ สิ้นวันครบกำหนด (23:59:59 เวลา Asia/Bangkok) และไม่มีการจองที่ยังรออยู่ (status = waiting)
- การต่ออายุทำได้เฉพาะเมื่อไม่มีผู้ใช้อื่นจองไว้ และยังไม่เกินจำนวนครั้งที่กำหนดสำหรับแต่ละรายการยืม
- ระยะเวลายืมใหม่และจำนวนครั้งต่ออายุขึ้นอยู่กับประเภทสมาชิกของผู้ยืม: นักศึกษาปริญญาตรี 7 วัน / 1 ครั้ง / +7 วัน, นักศึกษาบัณฑิตศึกษา 14 วัน / 2 ครั้ง / +14 วัน, อาจารย์/บุคลากร 30 วัน / 3 ครั้ง / +30 วัน
- ค่าการต่ออายุและจำนวนครั้งต่ออายุต้องอยู่ใน config ของระบบ ไม่ใช่ hard-code เพื่อให้บรรณารักษ์ปรับค่าได้
- “ใกล้ครบกำหนด” หมายถึง เหลือเวลาไม่เกิน 3 วันก่อนสิ้นวันครบกำหนด (23:59:59) และระบบสามารถเปิดปุ่มต่ออายุในช่วงนี้เท่านั้น
- วันคืนใหม่นับต่อจากวันครบกำหนดเดิม ไม่ใช่จากวันที่กดต่ออายุ และถ้าวันคืนใหม่ตรงกับวันปิดทำการ ให้เลื่อนไปเป็นวันทำการถัดไป
- สมาชิกที่มีค่าปรับค้างเกิน 100 บาท หรือถูกระงับสิทธิ์ ไม่สามารถต่ออายุได้
- ถ้ามีการจองใหม่เกิดขึ้นระหว่างประมวลผล ระบบต้องตรวจการจองอีกครั้งภายใน transaction ก่อน commit
- การคำนวณค่าปรับใช้ `due_date` เป็น single source of truth และไม่จำเป็นต้องอัปเดตค่าแยกอีกที่

## Requirements
- **FR-ต่ออายุการยืมหนังสือ-01** ระบบต้องแสดงรายการหนังสือที่สมาชิกกำลังยืมพร้อมข้อมูลวันครบกำหนดและจำนวนครั้งที่ต่ออายุแล้ว
- **FR-ต่ออายุการยืมหนังสือ-02** เมื่อผู้ใช้ขอต่ออายุ ระบบต้องตรวจสอบเงื่อนไขต่อไปนี้: (1) สถานะการยืมยังไม่เกินกำหนด ณ สิ้นวันครบกำหนด, (2) ไม่มีการจองที่ยังรออยู่ (status = waiting), (3) จำนวนครั้งที่ต่ออายุยังไม่ครบโควตา, (4) สมาชิกยังมีสิทธิ์ยืมและไม่เกินค่าเบิกทาง, (5) วันที่อยู่ในช่วง “ใกล้ครบกำหนด” และ (6) การจองใหม่ยังไม่ขัดแย้งภายใน transaction
- **FR-ต่ออายุการยืมหนังสือ-03** หากผ่านเงื่อนไข ระบบต้องกำหนดวันคืนใหม่โดยนับต่อจากวันครบกำหนดเดิม และแสดงผลสำเร็จพร้อมบันทึกการเปลี่ยนแปลงในประวัติการต่ออายุ
- **FR-ต่ออายุการยืมหนังสือ-04** หากหนังสือเกินกำหนด มีการจองที่ยังรออยู่ หรือจำนวนครั้งที่ต่ออายุครบจำนวนสูงสุดที่กำหนด ระบบต้องปฏิเสธคำขอและแสดงสาเหตุที่ชัดเจนตามลำดับต่อไปนี้: (1) “หนังสือเกินกำหนดคืนแล้ว กรุณาคืนหนังสือที่เคาน์เตอร์”, (2) “มีผู้จองหนังสือเล่มนี้ไว้”, (3) “ต่ออายุครบจำนวนครั้งที่กำหนดแล้ว (x/x ครั้ง)” (UC-06 Exception 4b)
- **FR-ต่ออายุการยืมหนังสือ-05** ระบบต้องอัปเดตข้อมูลต่อไปนี้ให้สอดคล้องกันใน transaction เดียว: รายการยืม (`due_date` และ `renewal_count`), ประวัติการต่ออายุ (audit log), หน้ารายการยืมของสมาชิกและเจ้าหน้าที่, และตารางแจ้งเตือนวันครบกำหนด (ยกเลิกรายการเดิมแล้วตั้งใหม่) หลังจาก commit สำเร็จแล้ว เท่านั้นจึงส่งแจ้งเตือนให้ผู้ใช้

## Quality Requirements
- **NFR-DATA-01** วันคืนใหม่ต้องสอดคล้องกันในทุกส่วนของระบบ และการคำนวณค่าปรับต้องอ่านจาก `due_date` เป็น source of truth
- **NFR-OPS-01** หากมีส่วนใดล้มเหลวใน transaction ของการต่ออายุ ระบบต้อง rollback ทั้งหมด และไม่ยอมให้มีการนับว่าเป็นการต่ออายุที่สำเร็จ พร้อมบันทึก error log สำหรับผู้ดูแลระบบ

## Acceptance Criteria
- [ ] **AC-ต่ออายุการยืมหนังสือ-01** (FR-ต่ออายุการยืมหนังสือ-01, FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03)
  - **Given** หนังสือยังไม่เกินกำหนด ณ สิ้นวันครบกำหนด ไม่มีการจองที่ยังรออยู่ และยังมีโควตาอยู่ และผู้ยืมมีสิทธิ์ยืมและอยู่ในช่วง “ใกล้ครบกำหนด” ไม่เกิน 3 วันก่อนครบกำหนด
  - **When** ผู้ใช้กดต่ออายุ
  - **Then** ระบบกำหนด `due_date` ใหม่โดยบวกระยะเวลาเพิ่มจากวันครบกำหนดเดิม เพิ่ม `renewal_count` ในรายการยืม และแสดงผลสำเร็จ พร้อมบันทึกผู้ทำรายการและเวลาในประวัติการต่ออายุ
- [ ] **AC-ต่ออายุการยืมหนังสือ-02** (FR-ต่ออายุการยืมหนังสือ-04)
  - **Given** หนังสือเกินกำหนด มีการจองที่ยังรออยู่ หรือจำนวนครั้งที่ต่ออายุครบสูงสุดที่กำหนด
  - **When** ผู้ใช้กดต่ออายุ
  - **Then** ระบบปฏิเสธและแสดงสาเหตุครบทุกข้อที่เกิดขึ้น เรียงตามลำดับที่กำหนดโดยไม่เปลี่ยนค่า `due_date` หรือ `renewal_count`
- [ ] **AC-ต่ออายุการยืมหนังสือ-03** (FR-ต่ออายุการยืมหนังสือ-02, FR-ต่ออายุการยืมหนังสือ-03)
  - **Given** หนังสืออยู่ในช่วง “ใกล้ครบกำหนด” (เหลือไม่เกิน 3 วันก่อนสิ้นวันครบกำหนด) แต่ยังผ่านเงื่อนไขการต่ออายุครบทุกข้อ
  - **When** ผู้ใช้ขอต่ออายุ
  - **Then** ระบบเปิดปุ่มต่ออายุให้กดได้ และดำเนินการตามเงื่อนไขปกติ โดยไม่ยกเลิกค่าเดิมก่อนการยืนยัน

## Assumptions
- **ASM-01** เมื่อหนังสือเกินกำหนด ระบบปฏิเสธการต่ออายุ ตาม Constraint ที่ระบุว่าหนังสือต้องยังไม่เกินกำหนด ณ สิ้นวันครบกำหนด (23:59:59 Asia/Bangkok)
- **ASM-02** นโยบายการต่ออายุใช้ค่า config ที่บรรณารักษ์ปรับได้ และค่าดีฟอลต์คือ นักศึกษาปริญญาตรี 7 วัน / 1 ครั้ง, นักศึกษาบัณฑิตศึกษา 14 วัน / 2 ครั้ง, อาจารย์/บุคลากร 30 วัน / 3 ครั้ง
- **ASM-03** จำนวนครั้งต่ออายุเป็นตัวนับแยกต่อเล่มต่อรายการยืม และเมื่อคืนหนังสือแล้วยืมใหม่อีกครั้ง ตัวนับจะเริ่มที่ 0
- **ASM-04** การต่ออายุแบบซ้ำติดกันได้จนกว่าจะครบโควตา แต่ทุกครั้งต้องผ่านการตรวจเงื่อนไขใหม่ทั้งหมดก่อน commit
- **ASM-05** การปฏิเสธคำขอต่ออายุจะแสดงสาเหตุแยกตามเงื่อนไขที่ถูกต้อง และใช้ข้อความที่ระบุใน FR-ต่ออายุการยืมหนังสือ-04 เท่านั้น
- **ASM-06** การอัปเดตทุกส่วนของข้อมูลและบันทึกประวัติการต่ออายุต้องเกิดใน transaction เดียว; ถ้ามีข้อมูลใดล้มเหลวให้ rollback ทั้งหมดและแสดงข้อความ “ทำรายการไม่สำเร็จ กรุณาลองใหม่อีกครั้ง”
- **ASM-07** แจ้งเตือนวันครบกำหนดจะถูกสร้างใหม่หลังจาก commit การต่ออายุสำเร็จเท่านั้น และไม่ส่งก่อน commit
- **ASM-08** สมาชิกและบรรณารักษ์สามารถเป็นผู้ทำรายการต่ออายุได้ และประวัติการต่ออายุต้องบันทึกชื่อผู้ทำรายการพร้อมเวลา
- **ASM-09** ตัวนับ renewal_count ใช้แค่รายการยืมหลัก ไม่รวมกรณีที่ยืมเองใหม่หลังคืนหนังสือแล้ว
- **ASM-10** กรณีวันที่คืนใหม่ตรงกับวันปิดทำการ ให้เลื่อนไปเป็นวันทำการถัดไป และตัวนับค่าปรับใช้ `due_date` เป็นแหล่งข้อมูลเดียวเท่านั้น
