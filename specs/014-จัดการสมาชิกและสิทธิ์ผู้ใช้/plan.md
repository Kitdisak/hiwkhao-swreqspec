# แผนงาน: จัดการสมาชิกและสิทธิ์ผู้ใช้

อ้างอิง: SPEC-จัดการสมาชิกและสิทธิ์ผู้ใช้-014 (Draft v2)

## 1. สรุปแนวทาง

- ผู้ดูแลระบบที่เข้าสู่ระบบและมี Permission ค้นหาและเลือกบัญชีเพื่อจัดการ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, Constraints)
- แก้ไขข้อมูลทั่วไปของบัญชีอื่นและกำหนด Role/Permission จากรายการที่มีได้ไม่เกินอำนาจของ Admin (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, ASM-01, ASM-02)
- ระงับบัญชีเป็น Suspended หรือเปิดใช้งานเป็น Active ตามสิทธิ์ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04, ASM-03)
- ปฏิเสธการมอบ Permission ที่ Admin ไม่มีอำนาจ และควบคุมการเข้าถึงทุกการจัดการ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01)
- บันทึกผู้กระทำ เวลา ค่าเดิม/ค่าใหม่ใน Audit Log และไม่ใช้การเปลี่ยนแปลงเมื่อบันทึก Audit ไม่สำเร็จ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04)

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| UserAccount | account reference, account status (Active/Suspended), editable general fields (รายการรอ Q-01) | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 ถึง FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04 |
| Role | role reference/name จากรายการที่ระบบมีอยู่ | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, ASM-01 |
| Permission | permission reference/name จากรายการที่ระบบมีอยู่; relationship กับ Role/UserAccount | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01 |
| AuditLog | actor, timestamp, target account, change type, old value, new value | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04 |

Role และ Permission เป็นค่าที่มีอยู่แล้ว ไม่สร้างรายการใหม่ใน UC-14 (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, ASM-01). รายละเอียดฟิลด์ข้อมูลบัญชียังไม่กำหนดจนกว่าจะได้ Q-01 (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, Q-01).

## 4. API / หน้าจอ

รายการต่อไปนี้เป็นข้อเสนอระดับ interface; ไม่รวมหน้าตรวจประวัติการใช้งานโดยละเอียดซึ่งอยู่นอกขอบเขต (Scope: Out of scope)

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ค้นหาบัญชี | `GET /api/admin/accounts`; input: search criteria; output: บัญชีที่ Admin มีสิทธิ์จัดการ | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, NFR-SEC-01 |
| แก้ไขข้อมูลบัญชี | `PATCH /api/admin/accounts/{accountId}`; input: ฟิลด์ทั่วไปที่ทีมอนุมัติ; output: บัญชีที่ปรับปรุงแล้วหรือผลปฏิเสธ | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, Q-01 |
| กำหนด Role/Permission | `PATCH /api/admin/accounts/{accountId}/permissions`; input: Role/Permission ที่มีอยู่; output: ผลการเปลี่ยนแปลงหรือปฏิเสธเมื่อเกินอำนาจ | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-SEC-01, NFR-AUDIT-01 |
| ระงับ/เปิดใช้งานบัญชี | `PATCH /api/admin/accounts/{accountId}/status`; input: Suspended หรือ Active; output: สถานะบัญชีและ Audit Log result | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06 |
| หน้าจัดการบัญชี | input: คำค้น, ฟิลด์บัญชี, Role/Permission, สถานะ; output: ผลค้นหา, การเปลี่ยนแปลงที่สำเร็จ/ถูกปฏิเสธ และผลบันทึก Audit | FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 ถึง FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 ถึง AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03 |

การเพิ่มบัญชีอยู่ใน Scope แต่ไม่มี FR หรือ AC ระบุ flow/เงื่อนไขสร้างบัญชีโดยตรง แผนนี้จึงไม่กำหนด endpoint หรือพฤติกรรมเพิ่มบัญชีแยกจาก FR ที่มี (Scope: In scope, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 ถึง FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06).

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-จัดการสมาชิกและสิทธิ์ผู้ใช้-014

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: Admin ต้องเข้าสู่ระบบและมีสิทธิ์จัดการผู้ใช้ | ตรวจ authentication/Permission ก่อนทุก endpoint และกรองบัญชีตามสิทธิ์ของ Admin (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, NFR-SEC-01) | ใช้แล้ว |
| ไม่มี ID: ต้องป้องกันการเข้าถึงข้อมูลโดยไม่ได้รับอนุญาต | ตรวจ authorization ที่ backend สำหรับค้นหา/แก้ไข/จัดการ status/Permission; ปฏิเสธผู้ไม่มีสิทธิ์ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01) | ใช้แล้ว |
| ไม่มี ID: การเปลี่ยน Permission ต้องบันทึกใน Audit Log | บันทึก actor/time/old/new value และไม่ใช้ permission change เมื่อ Audit Log เขียนไม่สำเร็จ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 | `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_01` | ใช้ Admin ที่มีสิทธิ์เปลี่ยน Role หรือสถานะของบัญชีอื่น ตรวจว่าข้อมูลเปลี่ยนและ Audit Log เก็บผู้กระทำ เวลา ค่าเดิม/ค่าใหม่; จำลอง Audit Log ล้มเหลวและตรวจว่าไม่มีการเปลี่ยนแปลงถูกนำไปใช้ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04) |
| AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-02 | `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_02` | ใช้ Admin ที่ไม่มี Permission ที่ร้องขอ ยืนยันการเปลี่ยนสิทธิ์ ตรวจว่าถูกปฏิเสธและ Permission คงเดิม (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01) |
| AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03 | `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_03` | ใช้ Admin ที่มีสิทธิ์เลือกระงับบัญชีอื่น ยืนยันแล้วตรวจสถานะเป็น Suspended (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04) |

## 7. ลำดับงาน

1. เตรียมการยืนยันตัวตนและตรวจ Permission ก่อนเข้าแต่ละการจัดการ (Constraints, NFR-SEC-01)
2. ค้นหาและเลือกบัญชีที่ Admin มีสิทธิ์จัดการ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01)
3. ยืนยันรายการฟิลด์ทั่วไปที่แก้ไขได้ก่อนพัฒนาแบบฟอร์ม (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, Q-01)
4. แสดง Role/Permission ที่มีอยู่และตรวจไม่ให้มอบเกินอำนาจ Admin (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, ASM-01)
5. ระงับบัญชีเป็น Suspended หรือเปิดใช้เป็น Active ตามสิทธิ์ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04, ASM-03)
6. บันทึกการเปลี่ยนบัญชี/Permission พร้อม actor/time/old/new value และป้องกันการใช้การเปลี่ยนแปลงเมื่อ Audit ล้มเหลว (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04)
7. ทดสอบการจัดการที่อนุญาตและปฏิเสธตาม AC ทั้งสามข้อ (AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01 ถึง AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, NFR-SEC-01)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** ฟิลด์ใดบ้างที่นับเป็น “ข้อมูลบัญชีทั่วไป” ซึ่ง Admin แก้ไขได้? ต้องถามทีม/ผู้ดูแลระบบ ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
