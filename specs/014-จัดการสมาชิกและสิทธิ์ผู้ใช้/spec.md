# Feature: จัดการสมาชิกและสิทธิ์ผู้ใช้
Spec ID: SPEC-จัดการสมาชิกและสิทธิ์ผู้ใช้-014 | Source: SRS v0.3 | Use case: UC-14
Owner: ทีม หิวข้าว  | Status: Draft v2 | Updated: 2569-11-19

## Goal
ผู้ดูแลระบบจัดการบัญชีผู้ใช้ สถานะบัญชี บทบาท และสิทธิ์ตามอำนาจที่ได้รับ

## Primary Actor
ผู้ดูแลระบบ (System Administrator)

## Scope
### In scope
- ค้นหาบัญชีผู้ใช้
- เพิ่มหรือแก้ไขข้อมูลบัญชี
- ระงับหรือเปิดใช้งานบัญชี
- กำหนด Role/Permission และบันทึกประวัติการเปลี่ยนแปลง
### Out of scope
- ตรวจสอบประวัติการใช้งานโดยละเอียด (อยู่นอกขอบเขต UC-14 และเกี่ยวข้องกับงาน Audit)

## Constraints
- Admin ต้องเข้าสู่ระบบและมีสิทธิ์จัดการผู้ใช้
- ต้องป้องกันการเข้าถึงข้อมูลโดยไม่ได้รับอนุญาต
- การเปลี่ยน Permission ต้องบันทึกใน Audit Log
- ใช้ฐานข้อมูล SQLite เดิมของระบบ ห้ามสร้างที่เก็บบัญชีใหม่

## Requirements
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01** ระบบต้องให้ Admin ค้นหาบัญชีผู้ใช้ด้วยชื่อ/นามสกุลหรืออีเมลแบบมีคำค้นเป็นส่วนหนึ่ง ไม่สนตัวพิมพ์เล็ก-ใหญ่ หรือด้วยรหัสนักศึกษาแบบตรงทั้งหมด; คำค้นว่างต้องไม่ค้นและแจ้งให้กรอกคำค้น; ผลลัพธ์พบหลายรายการต้องแสดงไม่เกิน 50 รายการพร้อมชื่อ อีเมล ประเภทผู้ใช้ Role และสถานะ; ไม่พบต้องแจ้ง “ไม่พบบัญชีผู้ใช้”
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02** ระบบต้องให้ Admin แก้ไขชื่อ นามสกุล อีเมล และเบอร์โทรศัพท์ของบัญชีอื่นที่ตนมีสิทธิ์จัดการ และกำหนด Role/Permission จากรายการที่มีอยู่ได้เฉพาะที่ตนเองมี ไม่แก้รหัสนักศึกษา เลขบัตรประชาชน ประเภทผู้ใช้ หรือรหัสผ่าน; อีเมลต้องไม่ซ้ำกับบัญชีอื่นและห้ามว่างสำหรับบุคคลภายนอกตาม SPEC-002
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03** ระบบต้องอนุญาตให้ระงับหรือเปิดใช้งานบัญชีผู้ใช้อื่นที่ Admin มีสิทธิ์จัดการ; ห้ามระงับบัญชีตนเองและห้ามระงับ Admin ที่ Active คนสุดท้าย; เมื่อเปิดใช้งาน สถานะบัญชีต้องเป็น Active
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04** เมื่อระงับบัญชี ระบบต้องเปลี่ยนสถานะเป็น Suspended (UC-14 Alternative 4a)
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05** หากผู้ใช้ไม่ได้เข้าสู่ระบบ ระบบต้องคืน 401; หากผู้ใช้เข้าสู่ระบบแต่ไม่มี Permission หรือขัดกับกฎการเปลี่ยน Role/Permission หรือระงับ/เปิดใช้งาน ระบบต้องปฏิเสธด้วยสถานะ 403 และข้อความ “คุณไม่มีสิทธิ์ดำเนินการนี้” (UC-14 Exception 5a); ห้ามเปลี่ยนข้อมูลบัญชี และห้ามสร้าง Audit Log ของการเปลี่ยนแปลง
- **FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06** ระบบต้องบันทึกผู้กระทำ บัญชีเป้าหมาย เวลา Asia/Bangkok ฟิลด์ ค่าเดิม และค่าใหม่ของทุกการเปลี่ยนแปลงที่สำเร็จซึ่งรวมข้อมูลทั่วไป Role/Permission การระงับ และการเปิดใช้งานใน Audit Log แบบ append-only; หากบันทึก Audit Log ไม่สำเร็จหรือส่วนใดของการบันทึกหนึ่งครั้งไม่ผ่าน ระบบต้องไม่เปลี่ยนข้อมูลบัญชีหรือสิทธิ์และต้องไม่เพิ่มรายการ Audit Log สำเร็จ

## Quality Requirements
- **NFR-SEC-01** ต้องควบคุมสิทธิ์การจัดการบัญชีและ Permission
- **NFR-AUDIT-01** การเปลี่ยนข้อมูลบัญชี Role/Permission สถานะระงับ และสถานะเปิดใช้งานต้องถูกบันทึกใน Audit Log พร้อมผู้กระทำ บัญชีเป้าหมาย เวลา Asia/Bangkok ฟิลด์ ค่าเดิม และค่าใหม่แบบ append-only; หากบันทึกไม่สำเร็จ การเปลี่ยนแปลงต้องไม่ถูกนำไปใช้

## Acceptance Criteria
- [ ] **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01** (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01)
  - **Given** Admin มีสิทธิ์จัดการบัญชีและข้อมูลหรือ Role/สถานะที่ส่งมาถูกต้อง
  - **When** Admin ยืนยันการเปลี่ยนข้อมูลบัญชีทั่วไป Role/Permission หรือสถานะในหนึ่งครั้ง
  - **Then** ระบบอัปเดตทุกส่วนที่ผ่านเงื่อนไขและบันทึกผู้กระทำ บัญชีเป้าหมาย เวลา Asia/Bangkok ฟิลด์ ค่าเดิม และค่าใหม่ใน Audit Log แบบ append-only; หากส่วนใดไม่ผ่านหรือบันทึก Audit ไม่สำเร็จ ทุกการเปลี่ยนต้องไม่ถูกนำไปใช้
- [ ] **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-02** (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01)
  - **Given** ผู้ใช้ไม่มีสิทธิ์หรือไม่มีสิทธิ์กำหนด Role/Permission ที่ร้องขอ หรือขัดกฎการจัดการบัญชี
  - **When** ผู้ใช้ดำเนินการเปลี่ยนสิทธิ์หรือจัดการบัญชี
  - **Then** หากไม่ได้เข้าสู่ระบบ ระบบคืน 401; หากเข้าสู่ระบบแต่ไม่มีสิทธิ์ ระบบคืน 403 พร้อมข้อความ “คุณไม่มีสิทธิ์ดำเนินการนี้”; ข้อมูลบัญชีก่อนและหลังต้องเหมือนกันและไม่สร้าง Audit Log ของการเปลี่ยนแปลง
- [ ] **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03** (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04)
  - **Given** Admin เลือกบัญชีอื่นที่ไม่ใช่ Admin Active คนสุดท้ายและยืนยันระงับ
  - **When** Admin ยืนยันการระงับ
  - **Then** ระบบเปลี่ยนสถานะบัญชีเป็น Suspended และบันทึกการเปลี่ยนเป็น Audit Log แบบ append-only ในชุดเดียวกัน

## Assumptions
- **ASM-01** Admin มอบ Role/Permission ได้เฉพาะรายการที่มีอยู่และไม่เกินอำนาจของตน
- **ASM-02** Admin จัดการได้เฉพาะบัญชีอื่น ไม่แก้ไขหรือเปลี่ยนสถานะบัญชีของตนเอง
- **ASM-03** การเปิดใช้งานบัญชีเปลี่ยนสถานะเป็น Active
- **ASM-04** การบันทึกหลายค่าร่วมกับการกดบันทึกหนึ่งครั้งเป็น all-or-nothing รวม Audit Log; ส่วนใดไม่ผ่านหรือ Audit บันทึกไม่สำเร็จ ไม่มีค่าใดเปลี่ยน
- **ASM-05** เฉพาะบัญชี Role Admin ที่มี Permission “จัดการบัญชีผู้ใช้” เข้าถึงฟีเจอร์นี้ได้; Librarian และ Member ไม่มีสิทธิ์เข้าถึง
- **ASM-06** Role ในระบบมี Member เป็นค่าเริ่มต้นสำหรับนักศึกษา บุคลากร และบุคคลภายนอก, Librarian และ Admin; Admin สามารถเปลี่ยน Role ของ Admin คนอื่นได้แต่ห้ามเปลี่ยน Role/Permission ของบัญชีตนเอง
- **ASM-07** ระบบต้องเหลือบัญชี Admin ที่ Active อย่างน้อย 1 บัญชีเสมอ
- **ASM-08** ข้อมูลบัญชีทั่วไปที่ Admin แก้ได้คือชื่อ นามสกุล อีเมล และเบอร์โทรศัพท์; อีเมลต้องไม่ซ้ำและห้ามว่างสำหรับบุคคลภายนอกตาม SPEC-002; ไม่แก้รหัสนักศึกษา เลขบัตรประชาชน ประเภทผู้ใช้ หรือรหัสผ่าน
- **ASM-09** การระงับไม่ลบหรือปิดรายการยืม จอง หรือค่าปรับค้าง; บัญชี Suspended เข้าสู่ระบบไม่ได้และ session ที่เปิดอยู่ใช้ต่อไม่ได้; จองไม่ได้ตาม SPEC-004 และยืมไม่ได้ตาม SPEC-011
- **ASM-10** การค้นหารองรับชื่อ/นามสกุลหรืออีเมลแบบมีคำค้นเป็นส่วนหนึ่งไม่สนตัวพิมพ์ และรหัสนักศึกษาแบบตรงทั้งหมด; คำค้นว่างไม่ค้นและแจ้งให้กรอก; พบหลายรายการแสดงไม่เกิน 50 รายการพร้อมชื่อ อีเมล ประเภทผู้ใช้ Role และสถานะแต่ไม่แสดงเลขบัตรประชาชน
- **ASM-11** หากไม่มีสิทธิ์หรือละเมิดกฎการเปลี่ยน/ระงับ ระบบคืน 401 สำหรับผู้ไม่ได้เข้าสู่ระบบหรือ 403 พร้อมข้อความ “คุณไม่มีสิทธิ์ดำเนินการนี้” สำหรับผู้เข้าสู่ระบบที่ไม่มีสิทธิ์หรือทำผิดกฎ; ตัวตน Admin มาจาก session ตาม SPEC-002 และห้ามรับจากคำขอ
- **ASM-12** การเปลี่ยนแปลงที่สำเร็จทุกประเภทต้องบันทึกผู้กระทำ บัญชีเป้าหมาย เวลา Asia/Bangkok ฟิลด์ ค่าเดิม และค่าใหม่ใน Audit Log; Audit Log append-only ห้ามแก้หรือลบผ่านฟีเจอร์นี้
- **ASM-13** ระบบใช้ฐานข้อมูล SQLite เดิมร่วมกับบัญชีผู้ใช้ ห้ามสร้างที่เก็บบัญชีแยก
- **ASM-14** การตรวจ NFR-SEC-01 ครอบคลุมกรณีผู้ไม่มี Permission ถูกปฏิเสธการจัดการบัญชีหรือสิทธิ์
- **ASM-15** AC-01 อ้างอิง FR-02/FR-06/NFR-AUDIT-01; AC-02 อ้างอิง FR-05/NFR-SEC-01; AC-03 อ้างอิง FR-01/FR-03/FR-04
- **ASM-16** ไม่มีนโยบายหรือค่ากำหนดเพิ่มเติมจากที่ระบุใน spec และ UC Case.pdf สำหรับฟีเจอร์นี้
