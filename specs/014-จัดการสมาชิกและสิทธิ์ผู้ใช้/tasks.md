# งาน: จัดการสมาชิกและสิทธิ์ผู้ใช้

อ้างอิง: SPEC-จัดการสมาชิกและสิทธิ์ผู้ใช้-014 (Draft v2), [plan.md](./plan.md)

## ลำดับงาน

### พัฒนาและทดสอบตามข้อกำหนด

- [x] **T-01** ผูกฟีเจอร์กับ session ที่มีอยู่และตรวจ Permission `manage_users` สำหรับทุก endpoint ค้นหา ดูรายละเอียด แก้ไข ระงับ และเปิดใช้งาน; ไม่รับตัวตน actor จากคำขอ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01, ASM-05, ASM-11) — สำเร็จ
- [x] **T-02** เพิ่มการค้นหาและเลือกบัญชีด้วยชื่อ/นามสกุลหรืออีเมลแบบ substring ไม่สนตัวพิมพ์ หรือรหัสนักศึกษาแบบตรงทั้งหมด; ว่างต้องแจ้งกรอก ค้นพบสูงสุด 50 รายการ และไม่พบแจ้ง “ไม่พบบัญชีผู้ใช้” โดยไม่แสดงเลขบัตรประชาชน (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, ASM-10) — สำเร็จ
- [x] **T-03** เพิ่ม API ดูรายละเอียดและหน้า `/manage/users` พร้อมแสดงชื่อ อีเมล ประเภทผู้ใช้ Role สถานะและเบอร์โทร; ไม่แสดงเลขบัตรประชาชนและไม่เปิดช่องแก้รหัสนักศึกษา ประเภทผู้ใช้ หรือรหัสผ่าน (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, ASM-08) — สำเร็จ
- [x] **T-04** เพิ่มการแก้ไขชื่อ นามสกุล อีเมล และเบอร์โทรศัพท์ของบัญชีอื่น; ตรวจอีเมลไม่ซ้ำและห้ามว่างสำหรับบุคคลภายนอกตาม SPEC-002; ปฏิเสธการแก้บัญชีตนเองและฟิลด์ห้ามแก้ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, ASM-02, ASM-08) — สำเร็จ
- [x] **T-05** เพิ่มการเลือกและตรวจ Role/Permission จากรายการที่มีอยู่เฉพาะ Role/Permission ที่ actor มี; รองรับ Admin เปลี่ยน Role ของ Admin คนอื่นแต่ห้ามเปลี่ยน Role/Permission ของตนเองและป้องกันไม่ให้เหลือ Admin Active น้อยกว่า 1 (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, ASM-01, ASM-06, ASM-07) — สำเร็จ
- [x] **T-06** เพิ่มการระงับและเปิดใช้งานบัญชีอื่นใน SQLite เดิม; ระงับเปลี่ยนเป็น Suspended และเปิดเป็น Active โดยปฏิเสธการระงับตนเองและ Admin Active คนสุดท้าย (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04, ASM-03, ASM-07) — สำเร็จ
- [x] **T-07** เพิ่ม transaction all-or-nothing สำหรับข้อมูลทั่วไป Role/Permission และสถานะรวม Audit Log; เก็บผู้กระทำ บัญชีเป้าหมาย เวลา Asia/Bangkok ฟิลด์ ค่าเดิม และค่าใหม่ และ rollback ทุกการเปลี่ยนถ้าส่วนใดหรือการบันทึก Audit ไม่สำเร็จ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01, ASM-04, ASM-12) — สำเร็จ
- [x] **T-08** เพิ่ม response 401 สำหรับผู้ไม่ได้เข้าสู่ระบบ และ 403 พร้อมข้อความ “คุณไม่มีสิทธิ์ดำเนินการนี้” สำหรับผู้เข้าสู่ระบบที่ไม่มี Permission หรือทำผิดกฎ; ต้องไม่เปลี่ยนข้อมูลหรือสร้าง Audit ของการเปลี่ยนที่ถูกปฏิเสธ (FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, ASM-11) — สำเร็จ
- [x] **T-09** ทดสอบ **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01** ด้วย `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_01_all_or_nothing_update_and_audit` โดยทดสอบการเปลี่ยนข้อมูลทั่วไป/Role/สถานะสำเร็จและกรณี validation/Audit ล้มเหลวพร้อม rollback, timestamp Asia/Bangkok และค่า old/new (AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-06, NFR-AUDIT-01) — สำเร็จ
- [x] **T-10** ทดสอบ **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-02** ด้วย `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_02_unauthorized_and_state_unchanged` โดยทดสอบไม่มี session 401, Member/Librarian ไม่มี Permission 403, ข้อความปฏิเสธ, ข้อมูลก่อน/หลังเหมือนเดิม และไม่มี Audit Log ของการเปลี่ยน (AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-02, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-05, NFR-SEC-01) — สำเร็จ
- [x] **T-11** ทดสอบ **AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03** ด้วย `test_AC_จัดการสมาชิกและสิทธิ์ผู้ใช้_03_suspend_and_audit` โดยทดสอบระงับบัญชีอื่นที่อนุญาต เปลี่ยนเป็น Suspended และ append Audit Log ใน transaction เดียวกัน พร้อมปฏิเสธกรณีระงับตนเองหรือ Admin Active คนสุดท้าย (AC-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-01, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-03, FR-จัดการสมาชิกและสิทธิ์ผู้ใช้-04) — สำเร็จ
- [x] **T-12** ทดสอบ regression กับ SPEC-002, SPEC-004 และ SPEC-011 และตรวจว่า Suspended ไม่เข้าสู่ระบบ/session ใช้ต่อไม่ได้ จองและยืมไม่ได้ตามที่กำหนดโดยไม่ลบรายการยืม จอง หรือค่าปรับค้าง (ASM-09, SPEC-002, SPEC-004, SPEC-011) — สำเร็จ
