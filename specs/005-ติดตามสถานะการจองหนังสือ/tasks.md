# งาน: ติดตามสถานะการจองหนังสือ

อ้างอิง: SPEC-ติดตามสถานะการจองหนังสือ-005 (Draft v2)

## ลำดับงาน

- [x] **T-01** เพิ่มการอ่านรายการจองของผู้ใช้ที่เข้าสู่ระบบ ครบทุกสถานะ พร้อมชื่อหนังสือ ผู้แต่ง และวันที่จอง; ไม่ส่งรหัสประจำเล่ม — สำเร็จใน `backend/app/reservations/service.py` และ `backend/app/main.py`; endpoint กรองด้วย member จาก session (FR-ติดตามสถานะการจองหนังสือ-01, Constraint: ผู้ใช้ต้องเข้าสู่ระบบ, ASM-01, ASM-09)
- [x] **T-02** แสดงสถานะและคิว Waiting ที่คำนวณใหม่ต่อชื่อเรื่อง — สำเร็จโดย reuse comparator ของ SPEC-004; API ส่ง queue position เฉพาะ Waiting (FR-ติดตามสถานะการจองหนังสือ-02, ASM-02, ASM-08)
- [x] **T-03** อ่านข้อมูล server ใหม่ทุกครั้งที่เปิดหน้า — สำเร็จโดย query ต่อ request, `Cache-Control: no-store` และ fetch แบบ `no-store`; ไม่มี auto-refresh ขณะเปิดหน้าค้าง (NFR-ACC-01, ASM-03, Constraint: สถานะต้องตรงกับข้อมูลการจองล่าสุด)
- [x] **T-04** แสดงวันหมดเขตเฉพาะ Ready ที่มีข้อมูล — เพิ่มฟิลด์ `pickup_deadline` แบบ nullable พร้อมรองรับฐานข้อมูลเดิม; Waiting / Completed และ Ready ที่ไม่มีข้อมูลไม่ส่งวันให้หน้าจอ (FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, ASM-04, ASM-05)
- [x] **T-05** เพิ่มหน้า `/my-reservations`, ลิงก์จากหน้าหลัก และข้อความเมื่อไม่มีรายการ — สำเร็จใน `frontend/src/features/reservations/MyReservationsPage.jsx`, `frontend/src/main.jsx` และ `frontend/src/features/book_search/SearchPage.jsx`; รองรับกลับจากหน้า login (FR-ติดตามสถานะการจองหนังสือ-04, ASM-07)
- [x] **T-06** ทดสอบรายการของสมาชิก สถานะล่าสุด และคิว Waiting — `test_AC_ติดตามสถานะการจองหนังสือ_01` ตรวจการกรองสมาชิกอื่น รายละเอียดรายการ คิว และการคำนวณใหม่หลังข้อมูล server เปลี่ยน (FR-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-02, NFR-ACC-01, AC-ติดตามสถานะการจองหนังสือ-01)
- [x] **T-07** ทดสอบเงื่อนไขวันหมดเขตทั้งสามกรณี — `test_AC_ติดตามสถานะการจองหนังสือ_02_1`, `_02_2`, `_02_3` ตรวจ Ready ที่มีวัน, Ready ที่ไม่มีวัน และ Waiting / Completed ที่มีวันตามลำดับ; ตรวจ UI ด้วย browser แบบ manual (FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, AC-ติดตามสถานะการจองหนังสือ-02)
- [x] **T-08** ทดสอบกรณีไม่มีรายการและการเข้าสู่ระบบ — `test_AC_ติดตามสถานะการจองหนังสือ_03` ตรวจผลรายการว่าง; เพิ่มการทดสอบ endpoint ที่ไม่มี session (FR-ติดตามสถานะการจองหนังสือ-04, AC-ติดตามสถานะการจองหนังสือ-03, Constraint: ผู้ใช้ต้องเข้าสู่ระบบ)

## ผลการตรวจสอบ

- `cd backend && python -m pytest -q tests/test_ac_ติดตามสถานะการจองหนังสือ.py tests/test_ac_จองหนังสือ.py` ผ่าน 24 tests; มี Starlette deprecation warning จาก TestClient หนึ่งรายการ
- `cd frontend && npm run build` ผ่าน
- ตรวจ UI ใน browser: รายการ Ready แสดงวัน “20 พ.ย. 2569”; Ready ที่ไม่มีวันไม่แสดงป้ายวันหมดเขต; Waiting แสดงคิว; Completed ไม่แสดงวันหมดเขต; หน้าว่างแจ้ง “ไม่มีรายการ”
- ทดสอบ migration เพิ่ม `pickup_deadline` ให้ตารางเดิมโดยรักษารายการเก่าไว้

หมายเหตุ: Q-01 เรื่องนโยบายลบ/เก็บประวัติยังต้องถามบรรณารักษ์ แต่ไม่กระทบการสร้างฟีเจอร์นี้ตาม ASM-01; ฟีเจอร์ไม่สร้าง ยกเลิก ลบ หรือซ่อนรายการจอง (ASM-07, Q-01).
