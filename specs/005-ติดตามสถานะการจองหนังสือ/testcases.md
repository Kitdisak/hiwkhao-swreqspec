# Test Cases: AC-ติดตามสถานะการจองหนังสือ-01 ถึง AC-ติดตามสถานะการจองหนังสือ-03

อ้างอิง: SPEC-ติดตามสถานะการจองหนังสือ-005 (Draft v2)

## ขอบเขต

ตรวจการแสดงรายการจองของผู้ใช้ที่เข้าสู่ระบบ รายละเอียดและสถานะของแต่ละรายการ คิว Waiting และการอ่านข้อมูลล่าสุดเมื่อเปิดเมนูใหม่ ตาม AC-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-02, NFR-ACC-01, ASM-01, ASM-02, ASM-03, ASM-08, ASM-09.

## กรณีทดสอบ

### กรณีข้อมูลรายการและสถานะครบถ้วน

**ข้อมูลตั้งต้น**

- สมาชิก A เข้าสู่ระบบและมีรายการ Waiting, Ready และ Completed
- สมาชิก B มีรายการจองเพิ่มเติมซึ่งไม่ใช่ของสมาชิก A
- แต่ละรายการอ้างถึงชื่อหนังสือที่มีชื่อเรื่องและผู้แต่งใน catalog

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. ตรวจรายการและรายละเอียดที่แสดง

**ผลที่คาดหวัง**

- แสดงรายการของสมาชิก A ครบทุกสถานะที่มีอยู่ และไม่แสดงรายการของสมาชิก B
- แต่ละรายการแสดงชื่อหนังสือ ผู้แต่ง วันที่จอง และสถานะเป็นข้อความ
- ไม่แสดงรหัสประจำเล่ม
- แสดงลำดับคิวเฉพาะรายการ Waiting; รายการ Ready และ Completed ไม่มีลำดับคิว

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-02, ASM-01, ASM-02, ASM-09.

### กรณีคิว Waiting แยกตามชื่อเรื่องและเรียงตามกติกาเดิม

**ข้อมูลตั้งต้น**

- มีรายการ Waiting หลายรายการในชื่อเรื่องเดียวกัน โดย `recorded_at` เรียงต่างกันอย่างชัดเจน
- สมาชิกที่ทดสอบมีรายการ Waiting หนึ่งรายการในชื่อนี้ และมีรายการ Waiting อีกชื่อเรื่องหนึ่ง
- มีรายการ Ready และ Completed ของสมาชิกที่ทดสอบ

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. เปรียบเทียบลำดับคิวกับ `recorded_at` ของรายการ Waiting ในแต่ละชื่อเรื่อง

**ผลที่คาดหวัง**

- คิวเริ่มที่ 1 และเท่ากับจำนวนรายการ Waiting ของชื่อเรื่องเดียวกันที่อยู่ก่อนหน้าบวก 1
- คิวของแต่ละชื่อเรื่องคำนวณแยกกัน
- การจัดลำดับใช้กติกาเดียวกับ FR-จองหนังสือ-03, NFR-DATA-01 และ ASM-01 ของ SPEC-004; ไม่ใช้ลำดับคิวเดิมที่บันทึกไว้
- Ready และ Completed ไม่แสดงคิว

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-01, FR-ติดตามสถานะการจองหนังสือ-02, ASM-02, ASM-08; SPEC-จองหนังสือ-004, FR-จองหนังสือ-03, NFR-DATA-01, ASM-01.

### กรณีเวลาเท่ากันใช้เกณฑ์เรียงจาก SPEC-004

**ข้อมูลตั้งต้น**

- มีรายการ Waiting ของชื่อเรื่องเดียวกันที่เวลาบันทึกตรงกันถึงหลักวินาที
- เตรียมชื่อสมาชิกภาษาไทยและชื่อที่ไม่ใช่ภาษาไทย เพื่อยืนยันลำดับตามเกณฑ์ใน SPEC-004; หากชื่อจริงและนามสกุลตรงกัน ให้ใช้รหัสสมาชิกตัดสินลำดับ

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน” สำหรับสมาชิกที่มีรายการในชุดข้อมูล
2. เปรียบเทียบ queue position กับลำดับที่ได้จากเกณฑ์เรียงใน SPEC-004

**ผลที่คาดหวัง**

- ลำดับคิวตรงกับเกณฑ์เรียงที่ SPEC-004 กำหนด รวมการเรียงชื่อไทยก่อนชื่ออื่น และการใช้รหัสสมาชิกเมื่อชื่อและนามสกุลยังเท่ากัน
- ลำดับคิวเริ่มที่ 1 และไม่มีการใช้กติกาใหม่เฉพาะ SPEC-005

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-01, ASM-08; SPEC-จองหนังสือ-004, FR-จองหนังสือ-03, NFR-DATA-01, ASM-01.

### กรณีเปิดเมนูซ้ำแล้วอ่านข้อมูลล่าสุดและคำนวณคิวใหม่

**ข้อมูลตั้งต้น**

- สมาชิก A มีรายการ Waiting ในชื่อเรื่องหนึ่ง โดยมีรายการ Waiting ของสมาชิกอื่นอยู่ก่อนหน้า
- บันทึกสถานะและลำดับคิวที่เห็นเมื่อเปิดเมนูครั้งแรก

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน” และตรวจสถานะกับคิว
2. เปลี่ยนสถานะรายการที่อยู่ก่อนหน้าในข้อมูล server ให้พ้นจาก Waiting
3. เปิดเมนู “รายการจองของฉัน” อีกครั้ง

**ผลที่คาดหวัง**

- การเปิดครั้งที่สองแสดงข้อมูลสถานะล่าสุดจาก server
- คิว Waiting คำนวณใหม่จากรายการ Waiting ที่ยังมีอยู่ และลดลงตามจำนวนรายการก่อนหน้าที่ไม่อยู่ในสถานะ Waiting แล้ว
- กรณีนี้ทดสอบการอ่านใหม่เมื่อเปิดเมนู ไม่ได้กำหนดให้หน้าเว็บที่เปิดค้างอยู่ refresh อัตโนมัติ

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-01, NFR-ACC-01, ASM-03, ASM-08.

## การทดสอบอัตโนมัติที่มีอยู่

## AC-ติดตามสถานะการจองหนังสือ-02

ตรวจเงื่อนไขการแสดงวันหมดเขตตาม FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, ASM-04 และ ASM-05.

### กรณี Ready มีวันหมดเขต

**ข้อมูลตั้งต้น**

- ผู้ใช้เข้าสู่ระบบ
- มีรายการจองสถานะ Ready ซึ่ง `pickup_deadline` เป็นวันที่ 20 พฤศจิกายน 2569

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. ตรวจรายละเอียดของรายการ Ready

**ผลที่คาดหวัง**

- แสดงสถานะ Ready เป็นข้อความ
- แสดงวันหมดเขตรับเป็นข้อความ “20 พ.ย. 2569”

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-02 กรณี 02-1, FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, ASM-04, ASM-05.

### กรณี Ready ไม่มีวันหมดเขต

**ข้อมูลตั้งต้น**

- ผู้ใช้เข้าสู่ระบบ
- มีรายการจองสถานะ Ready ซึ่งไม่มีค่า `pickup_deadline`

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. ตรวจรายละเอียดของรายการ Ready

**ผลที่คาดหวัง**

- แสดงสถานะ Ready ตามปกติ
- ไม่แสดงวันหมดเขต ป้ายกำกับ ช่อง หรือข้อความทดแทนใด ๆ

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-02 กรณี 02-2, FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, ASM-04.

### กรณีสถานะอื่นมีข้อมูลวันหมดเขต

**ข้อมูลตั้งต้น**

- ผู้ใช้เข้าสู่ระบบ
- มีรายการ Waiting และ Completed ที่มีค่า `pickup_deadline`

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. ตรวจรายละเอียดของทั้งสองรายการ

**ผลที่คาดหวัง**

- แสดงสถานะ Waiting และ Completed เป็นข้อความตามปกติ
- ไม่แสดงวันหมดเขตหรือป้ายกำกับวันหมดเขตในทั้งสองรายการ แม้ข้อมูลมีค่า

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-02 กรณี 02-3, FR-ติดตามสถานะการจองหนังสือ-03, NFR-USE-01, ASM-04.

## การทดสอบอัตโนมัติของ AC-ติดตามสถานะการจองหนังสือ-02

- `test_AC_ติดตามสถานะการจองหนังสือ_02_1_includes_ready_deadline` ตรวจ Ready ที่มีวันหมดเขตในข้อมูล API
- `test_AC_ติดตามสถานะการจองหนังสือ_02_2_omits_ready_deadline_when_missing` ตรวจ Ready ที่ไม่มีวันหมดเขต
- `test_AC_ติดตามสถานะการจองหนังสือ_02_3_hides_deadline_for_other_statuses` ตรวจ Waiting และ Completed ที่มีวันหมดเขต

การทดสอบ API เหล่านี้ไม่ตรวจการจัดรูปแบบและการแสดงข้อความบนหน้าเว็บ; ให้ใช้กรณี manual ด้านบนตรวจ UI โดยไม่เพิ่มรูปแบบอื่นนอกเหนือจากที่ spec ระบุ.

## AC-ติดตามสถานะการจองหนังสือ-03

ตรวจการแสดง empty state เมื่อผู้ใช้ที่เข้าสู่ระบบไม่มีรายการจอง ตาม AC-ติดตามสถานะการจองหนังสือ-03, FR-ติดตามสถานะการจองหนังสือ-04 และ ASM-01.

### กรณีผู้ใช้ไม่มีรายการจอง

**ข้อมูลตั้งต้น**

- ผู้ใช้เข้าสู่ระบบแล้ว
- ผู้ใช้นี้ไม่มีรายการจองในทุกสถานะ และ API รายการจองตอบกลับสำเร็จด้วยรายการว่าง

**ขั้นตอน**

1. เปิดเมนู “รายการจองของฉัน”
2. รอให้หน้าโหลดข้อมูลเสร็จ

**ผลที่คาดหวัง**

- หน้าเว็บแสดงข้อความ “ไม่มีรายการ”
- ไม่มีการ์ดรายการจองหรือข้อความแจ้งข้อผิดพลาด

**อ้างอิง:** AC-ติดตามสถานะการจองหนังสือ-03, FR-ติดตามสถานะการจองหนังสือ-04, ASM-01.

## การทดสอบอัตโนมัติของ AC-ติดตามสถานะการจองหนังสือ-03

`test_AC_ติดตามสถานะการจองหนังสือ_03_returns_empty_list` ตรวจว่า API ตอบกลับ `{"reservations": []}` เมื่อผู้ใช้ที่เข้าสู่ระบบไม่มีรายการจอง; ใช้กรณี manual ด้านบนตรวจข้อความ empty state บนหน้าเว็บ.
