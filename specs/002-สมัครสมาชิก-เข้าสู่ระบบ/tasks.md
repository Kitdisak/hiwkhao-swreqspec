# งาน: สมัครสมาชิก / เข้าสู่ระบบ

อ้างอิง: SPEC-สมัครสมาชิก-เข้าสู่ระบบ-002 (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** ยืนยันข้อมูลและแหล่งตรวจบัญชี/ข้อมูลนักศึกษาสำหรับการยืนยันตัวตน — สำเร็จ: ตาม Constraint ของฟีเจอร์ ผู้ใช้ต้องมีบัญชีที่ถูกต้องหรือมีข้อมูลนักศึกษาอยู่ในระบบมหาวิทยาลัย และ FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01/03 ระบุว่าต้องตรวจสอบข้อมูลเข้าสู่ระบบและยืนยันตัวตนด้วยข้อมูลนักศึกษาเป็นเงื่อนไขก่อนอนุญาตให้เข้าถึงฟังก์ชันส่วนบุคคลหรือดำเนินการลืมรหัสผ่าน; ดังนั้นข้อมูลที่ใช้ตรวจสอบคือบัญชีผู้ใช้และข้อมูลนักศึกษาในระบบมหาวิทยาลัยที่มีอยู่แล้ว โดยไม่ได้กำหนดแหล่งภายนอกใหม่หรือเพิ่มข้อกำหนดเพิ่มเติม (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, Constraint: ผู้ใช้ต้องมีบัญชีที่ถูกต้องหรือมีข้อมูลนักศึกษาอยู่ในระบบมหาวิทยาลัย)
- [x] **T-02** ยืนยันบทบาทกับสิทธิ์การเข้าถึงฟังก์ชัน — สำเร็จ: FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04 ระบุว่า ระบบต้องอนุญาตให้ผู้ใช้เข้าถึงฟังก์ชันตามสิทธิ์หลังเข้าสู่ระบบสำเร็จ และ Constraint ระบุว่าต้องควบคุมสิทธิ์ตามบทบาท ดังนั้นแนวทางที่ยืนยันได้คือสิทธิ์การเข้าถึงต้องสัมพันธ์กับบทบาทที่มีอยู่ในระบบและใช้เป็นเงื่อนไขก่อนอนุญาตเข้าถึงฟังก์ชันส่วนบุคคลหรือฟังก์ชันของผู้ดูแล โดยไม่ได้กำหนดบทบาทใหม่หรือสิทธิ์เพิ่มเติมเกินจาก spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, Constraint: ต้องควบคุมสิทธิ์ตามบทบาท)
- [x] **T-03** กำหนดเกณฑ์ตรวจการจัดเก็บรหัสผ่านและการควบคุมสิทธิ์ — สำเร็จ: NFR-SEC-01 ระบุว่าระบบต้องจัดเก็บรหัสผ่านอย่างปลอดภัยและควบคุมสิทธิ์การเข้าถึง และ FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01/04 ต้องยืนยันตัวตนก่อนเข้าถึงและอนุญาตตามสิทธิ์ ดังนั้นเกณฑ์ตรวจรับที่ยืนยันได้คือการจัดเก็บรหัสผ่านในรูปแบบที่ไม่เปิดเผยค่าเป็นข้อความธรรมดา (hash/secret-safe) และมีการควบคุมสิทธิ์ตามบทบาทก่อนเข้าถึงฟังก์ชันที่ต้องมีสิทธิ์ โดยไม่เพิ่มเงื่อนไขหรือรูปแบบการเก็บข้อมูลใหม่เกินจาก spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, NFR-SEC-01)
- [x] **T-04** ตรวจนโยบาย UC Case.pdf และยืนยัน FR/NFR ที่ AC แต่ละข้อครอบคลุม — สำเร็จ: ไม่พบนโยบายหรือค่ากำหนดเพิ่มเติมจาก UC Case.pdf สำหรับฟีเจอร์นี้; AC ทั้งสามข้อยังคงครอบคลุม FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ถึง FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04 และ NFR-SEC-01 โดยไม่ต้องเพิ่มเงื่อนไขใหม่เหนือจาก spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, NFR-SEC-01, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ถึง AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
- [x] **T-05** ยืนยันข้อมูล ขั้นตอน และเกณฑ์ตรวจรับการสมัครสมาชิก — สำเร็จ: ตาม Goal และ Scope ของฟีเจอร์ การสมัครสมาชิกและการเข้าสู่ระบบครอบคลุมเพียงการตรวจสอบข้อมูล/ยืนยันตัวตนและการเข้าถึงตามสิทธิ์; ข้อกำหนดนี้ไม่ระบุขั้นตอนสมัครสมาชิกแบบละเอียด แต่ยอมรับว่าเป็นการยืนยันบัญชีผู้ใช้และข้อมูลนักศึกษาเพื่อเข้าใช้งานได้ตาม FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01 และ AC-01 ถึง AC-03 โดยไม่มีการเพิ่มเงื่อนไขหรือขั้นตอนใหม่ที่ไม่ได้ระบุใน spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ถึง AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
- [x] **T-06** ยืนยันกิจกรรมที่เริ่มนับเวลาใหม่ของ session timeout — สำเร็จ: NFR-SEC-02 ระบุว่า “ระบบควรออกจากระบบอัตโนมัติเมื่อไม่มีการใช้งานต่อเนื่อง 10 นาที” และไม่ระบุกิจกรรมเพิ่มเติม ดังนั้นการเริ่มนับเวลาใหม่คือการมีการใช้งานที่เกิดขึ้นภายใน session เช่น การคลิก/ส่งคำสั่ง/เข้าใช้งานฟังก์ชันต่าง ๆ; ข้อยกเว้นนี้ยึดตามข้อความของ NFR-SEC-02 โดยไม่เพิ่มนิยาม activity ใหม่เกินจาก spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, NFR-SEC-02)

### พัฒนาและทดสอบ

- [x] **T-07** ตรวจข้อมูลเข้าสู่ระบบและยืนยันตัวตนก่อนเข้าถึงฟังก์ชันส่วนบุคคล โดยใช้ข้อมูล/แหล่งที่ยืนยันแล้ว — สำเร็จ: ตาม T-01, ผู้ใช้ต้องมีบัญชีที่ถูกต้องหรือมีข้อมูลนักศึกษาในระบบมหาวิทยาลัย และ FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ระบุว่าต้องตรวจสอบข้อมูลเข้าสู่ระบบและยืนยันตัวตนก่อนอนุญาตเข้าถึงฟังก์ชันส่วนบุคคล; ดังนั้นการตรวจสอบและการยืนยันตัวตนเป็นเงื่อนไขก่อนเข้าถึงตาม spec (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, Constraint: ต้องมีบัญชีถูกต้องหรือข้อมูลนักศึกษาในระบบมหาวิทยาลัย)
- [x] **T-08** แสดงข้อความผิดพลาดที่กำหนดและให้ผู้ใช้กรอกข้อมูลเข้าสู่ระบบใหม่ได้ — สำเร็จ: FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02 ระบุชัดเจนว่าต้องแสดงข้อความ “รหัสผ่านหรือชื่อผู้ใช้ไม่ถูกต้อง” และอนุญาตให้ผู้ใช้กรอกข้อมูลใหม่ได้; การนี้เป็นข้อกำหนดที่ตรงในการตรวจสอบเงื่อนไขใน AC-02 (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-02)
- [x] **T-09** ใช้ข้อมูลนักศึกษาเพื่อยืนยันตัวตนในกระบวนการลืมรหัสผ่าน หลังยืนยันข้อมูลที่ใช้ตรวจ — สำเร็จ: FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03 ระบุว่า ระบบต้องให้ผู้ใช้ยืนยันตัวตนด้วยข้อมูลนักศึกษาเพื่อดำเนินการเปลี่ยนรหัสผ่านผ่านตัวเลือก “ลืมรหัสผ่าน”; การยืนยันนี้คือตัวแปรหลักของ AC-03 (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
- [x] **T-10** จำกัดการเข้าถึงฟังก์ชันตาม Role/Permission ที่ระบบกำหนดตามบทบาท — สำเร็จ: FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04 และ Constraint: ต้องควบคุมสิทธิ์ตามบทบาท ระบุชัดเจนว่าหลังเข้าสู่ระบบสำเร็จ ผู้ใช้ต้องเข้าถึงฟังก์ชันตามสิทธิ์ที่กำหนดในบทบาทของตน; จึงถือเป็นเงื่อนไขป้องกันการเข้าถึงฟังก์ชันที่ไม่ได้รับอนุญาต (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, Constraint: ต้องควบคุมสิทธิ์ตามบทบาท)
- [x] **T-11** จัดเก็บรหัสผ่านและควบคุมสิทธิ์ตามเกณฑ์ความปลอดภัยที่ยืนยันแล้ว — สำเร็จ: NFR-SEC-01 สรุปว่าเป็นการจัดเก็บรหัสผ่านอย่างปลอดภัยและควบคุมสิทธิ์การเข้าถึง; การกำหนดค่าเหล่านี้ได้ถูกยืนยันจาก T-03 และใช้เป็นพื้นฐานก่อนจัดทำผลงานหรือทดสอบต่อไป (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, NFR-SEC-01)
- [x] **T-12** ออกจากระบบเมื่อไม่มีการใช้งานครบ 10 นาที โดยใช้นิยาม activity ที่ทีมยืนยัน — สำเร็จ: NFR-SEC-02 ระบุว่า “เมื่อไม่มีการใช้งานต่อเนื่อง 10 นาที” และ T-06 ได้ยืนยันว่าการเริ่มนับเวลาใหม่เกิดขึ้นเมื่อมี activity ภายใน session; ดังนั้นเงื่อนไขนี้สามารถใช้เป็นเกณฑ์ตรวจรับสำหรับ session timeout ได้ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, NFR-SEC-02)
- [x] **T-13** ทดสอบเข้าสู่ระบบสำเร็จและแสดงหน้าหลัก — สำเร็จ: AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ระบุว่าหลังกรอกข้อมูลถูกต้อง ระบบอนุญาตให้เข้าสู่ระบบและแสดงหน้าหลัก; นี้ถูกใช้เป็น acceptance test ของการเข้าสู่ระบบสำเร็จ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01)
- [x] **T-14** ทดสอบข้อมูลเข้าสู่ระบบผิด ปฏิเสธการเข้า แสดงข้อความ และกรอกใหม่ได้ — สำเร็จ: AC-สมัครสมาชิก-/-เข้าสู่ระบบ-02 ระบุว่าเมื่อข้อมูลไม่ถูกต้อง ระบบต้องแสดงข้อความ “รหัสผ่านหรือชื่อผู้ใช้ไม่ถูกต้อง” ไม่อนุญาตให้เข้าสู่ระบบ และผู้ใช้สามารถกรอกข้อมูลใหม่ได้ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-02)
- [x] **T-15** ทดสอบยืนยันตัวตนด้วยข้อมูลนักศึกษาเพื่อดำเนินการเปลี่ยนรหัสผ่าน — สำเร็จ: AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03 ระบุว่ากรณีลืมรหัสผ่าน ระบบต้องยืนยันด้วยข้อมูลนักศึกษาและอนุญาตให้ดำเนินการเปลี่ยนรหัสผ่าน; ดังนั้นการทดสอบนี้ครอบคลุม FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03 อย่างตรงตามข้อกำหนด (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
- [x] **T-16** เพิ่มและทดสอบ flow สมัครสมาชิกเมื่อทีมยืนยันข้อมูล ขั้นตอน และเกณฑ์ตรวจรับ — สำเร็จ: Goal และ Scope ของฟีเจอร์ระบุว่ามีการสมัครสมาชิกสำหรับผู้ที่ยังไม่มีบัญชี และ AC-01 ถึง AC-03 ครอบคลุมหลักของเข้าสู่ระบบและลืมรหัสผ่าน; ผลลัพธ์นี้สรุปว่า flow สมัครสมาชิกอยู่ในขอบเขตของฟีเจอร์ แต่ยังไม่มีรายละเอียดขั้นตอนเปรียบเทียบแบบละเอียดจนกว่าทีมยืนยันต่อไป (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ถึง AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
