# แผนงาน: สมัครสมาชิก / เข้าสู่ระบบ

อ้างอิง: [spec.md](./spec.md) — SPEC-สมัครสมาชิก-เข้าสู่ระบบ-002 (Draft v2, 2569-11-14)

## 1. สรุปแนวทาง

- รองรับการสมัครสมาชิกด้วยอีเมลที่บังคับเฉพาะบุคคลภายนอก สร้างชื่อแสดงผลจากชื่อกับนามสกุล และจำแนกบุคคลภายนอกจากผลตรวจทะเบียน (AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-05, ASM-06, ASM-11)
- เก็บวันเกิดเต็มตอนสมัครสำหรับบุคคลภายนอกเพื่อยืนยันตัวตนเมื่อลืมรหัสผ่าน (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, ASM-10)
- รองรับการเข้าสู่ระบบตามประเภทผู้ใช้ และปฏิเสธข้อมูลผิดด้วยข้อความตาม spec พร้อมให้ลองใหม่ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, ASM-07, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
- รองรับการตั้งรหัสผ่านใหม่ด้วยข้อมูลยืนยันตามประเภทผู้ใช้และแหล่งข้อมูลวันเกิดที่กำหนด (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-04, ASM-09, ASM-10)
- ออกจากระบบอัตโนมัติหลังไม่มีการทำรายการหรือใช้งานเกิน 10 นาที โดยนิยามกิจกรรมที่รีเซ็ตเวลายังรอคำตอบ (NFR-SEC-02, Q-06)

## 3. โมเดลข้อมูล

เป็นโมเดลเชิงโครงสร้าง ยังไม่กำหนดฐานข้อมูลหรืออัลกอริทึม hash; ฟิลด์รหัสผ่านเก็บค่า hash ตาม NFR-SEC-01/ASM-12 ส่วนเกณฑ์การปกป้องและสิทธิ์ยังรอคำตอบ (Q-02, Q-03)

| Entity | ฟิลด์หลักที่วางแผน | รองรับ |
|---|---|---|
| Account | account_id, user_type (นักศึกษา/บุคลากร/บุคคลภายนอก), display_name (รวมจากชื่อและนามสกุล), email (ไม่บังคับสำหรับนักศึกษา/บุคลากร; บังคับสำหรับบุคคลภายนอก), password_hash, role reference | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, NFR-SEC-01, ASM-05, ASM-07, ASM-11, ASM-12 |
| IdentityProfile | account_id, ชื่อ, นามสกุล, ปีเกิด, เลขบัตรประชาชน, เบอร์โทรศัพท์, student_id (เฉพาะนักศึกษา), วัน/เดือน/ปีเกิดเต็ม (อ้างทะเบียนสำหรับนักศึกษา/บุคลากร; เก็บตอนสมัครสำหรับบุคคลภายนอก) | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-05, ASM-09, ASM-10 |
| AuthSession | account_id, สถานะ session, เวลาใช้งานล่าสุด | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, NFR-SEC-02, Q-06 |
| RolePermissionMapping | role_id, permission references; รายการจริงยังไม่กำหนด | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, Q-02 |

ข้อมูลเลขบัตรประชาชนและวันเกิดจำเป็นต่อการสมัคร/ยืนยันตัวตนตาม FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03 และ AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01; วิธีจัดเก็บและปกป้องยังไม่กำหนดจนกว่าจะได้เกณฑ์ NFR-SEC-01 (Q-03). รหัสผ่านเก็บเป็น hash โดยยังไม่ระบุอัลกอริทึม (NFR-SEC-01, ASM-12, Q-03). การจัดเก็บผลจากการค้นทะเบียนยังไม่กำหนดจนกว่าจะยืนยันแหล่งและวิธีตรวจสอบ (ASM-06, Q-07).

## 4. API / หน้าจอ

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| สมัครสมาชิก | `POST /api/auth/register`; input: ชื่อ, นามสกุล, ปีเกิด, เลขบัตรประชาชน, เบอร์โทรศัพท์, อีเมล (ไม่บังคับสำหรับนักศึกษา/บุคลากร; บังคับสำหรับบุคคลภายนอก), วัน/เดือน/ปีเกิดเต็มสำหรับบุคคลภายนอก; output: สถานะสร้างบัญชี, ประเภทผู้ใช้ และชื่อแสดงผลที่รวมจากชื่อกับนามสกุล | ไม่มี FR สมัครสมาชิกโดยเฉพาะใน spec; ครอบคลุม AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-01, ASM-05, ASM-06, ASM-10, ASM-11; การจัด mapping AC-to-FR รอ Q-04 |
| เข้าสู่ระบบ | `POST /api/auth/login`; input: ข้อมูลระบุตัวตนตามประเภทผู้ใช้และรหัสผ่าน; output: ผลยืนยันตัวตนและ session เมื่อสำเร็จ | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, ASM-07 |
| ตั้งรหัสผ่านใหม่ | `POST /api/auth/password-reset`; input: ข้อมูลยืนยันตามประเภทผู้ใช้และรหัสผ่านใหม่; output: ผลตรวจสอบข้อมูลและผลการตั้งรหัสผ่าน | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, ASM-09, ASM-10 |
| ตรวจสิทธิ์ก่อนเข้าถึงฟังก์ชัน | ใช้ policy helper ปฏิเสธการยืมหนังสือของบุคคลภายนอก; ปัจจุบันยังไม่มี API/service ยืมหนังสือให้เรียก helper | FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-08 |

พฤติกรรมเมื่อทะเบียนไม่ตอบสนองกำหนดไว้ว่าไม่สร้างบัญชี/ไม่อนุญาตตั้งรหัสผ่านและแจ้งให้ลองใหม่ภายหลัง (ASM-13); ช่องทางเชื่อมทะเบียนและแหล่งรหัสประจำตัวยังรอ Q-07. การกำหนดสิทธิ์นอกเหนือจากข้อจำกัดบุคคลภายนอกยังรอ Q-02.

## 5. ตารางตรวจ Constraints

spec ระบุ Constraints 2 ข้อแต่ไม่ได้กำหนด ID จึงอ้างตามลำดับใน spec โดยไม่สร้าง ID ใหม่

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID (Constraint ข้อ 1): ผู้ใช้ต้องมีบัญชีที่ถูกต้องหรือมีข้อมูลนักศึกษา/บุคลากรในทะเบียน; ผู้ไม่พบข้อมูลถือเป็นบุคคลภายนอก | ตรวจทะเบียนเพื่อจำแนกประเภทบัญชีใน API สมัครสมาชิกและ IdentityProfile (AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-06); เมื่อไม่ตอบสนองไม่สร้างบัญชีและแจ้งลองใหม่ (ASM-13); ช่องทางเชื่อมต่อยังรอ Q-07 | ใช้แล้ว |
| ไม่มี ID (Constraint ข้อ 2): ควบคุมสิทธิ์การเข้าถึงตามบทบาท | เพิ่ม policy helper ปฏิเสธการยืมสำหรับบุคคลภายนอก (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, ASM-08); role/function mapping ยังรอ Q-02 และยังไม่มี API/service ยืมหนังสือให้เรียก helper | ยังไม่ได้ใช้ทั้งหมด: ส่วน mapping รอ Q-02 และ helper ยังไม่ถูกเรียกจาก flow ยืม |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 | `test_AC_สมัครสมาชิก_เข้าสู่ระบบ_01` และ `test_AC_สมัครสมาชิก_เข้าสู่ระบบ_01_borrowing_prohibition_by_user_type` | ทดสอบสมัครด้วยฟิลด์บังคับ; ไม่ระบุอีเมลได้สำหรับนักศึกษา/บุคลากรแต่ต้องระบุสำหรับบุคคลภายนอก; จำลองกรณีพบข้อมูล/ไม่พบข้อมูลในทะเบียนและตรวจชื่อแสดงผล; เมื่อทะเบียนไม่ตอบสนองต้องไม่สร้างบัญชีและแจ้งให้ลองใหม่; ตรวจ policy helper ว่าห้ามบุคคลภายนอกยืม (ASM-05, ASM-06, ASM-08, ASM-10, ASM-11, ASM-13); การเชื่อมต่อจริงรอ Q-07 |
| AC-สมัครสมาชิก-/-เข้าสู่ระบบ-02 | `test_AC_สมัครสมาชิก_เข้าสู่ระบบ_02` | ทดสอบข้อมูลเข้าสู่ระบบที่ถูกต้องด้วย identifier ที่อนุญาตของนักศึกษา บุคลากร และบุคคลภายนอก (อีเมลหรือชื่อแสดงผล) แล้วตรวจว่าเข้าสู่ระบบสำเร็จและแสดงหน้าหลัก (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-07) |
| AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03 | `test_AC_สมัครสมาชิก_เข้าสู่ระบบ_03` | ส่ง identifier หรือรหัสผ่านที่ไม่ถูกต้อง ตรวจว่าปฏิเสธการเข้าสู่ระบบ แสดงข้อความที่กำหนด และให้กรอกใหม่ได้ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, ASM-03) |
| AC-สมัครสมาชิก-/-เข้าสู่ระบบ-04 | `test_AC_สมัครสมาชิก_เข้าสู่ระบบ_04` | ทดสอบส่งข้อมูลยืนยันครบชุดตามประเภทผู้ใช้: นักศึกษาตรวจเทียบทะเบียนนักศึกษา, บุคลากรตรวจเทียบทะเบียนบุคลากร, บุคคลภายนอกตรวจเทียบข้อมูลที่เก็บตอนสมัคร; เมื่อข้อมูลตรงกันต้องอนุญาตให้ตั้งรหัสผ่านใหม่; เมื่อทะเบียนไม่ตอบสนองต้องไม่อนุญาตตั้งรหัสผ่านและแจ้งให้ลองใหม่ภายหลัง (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, ASM-09, ASM-10, ASM-13); การเชื่อมต่อจริงรอ Q-07 |

การทดสอบการอนุญาตตาม role อื่น ๆ ต้องรอ Q-02; เกณฑ์ทดสอบ NFR-SEC-01 ต้องรอ Q-03; ส่วนเงื่อนไขกิจกรรมที่รีเซ็ตเวลาใน NFR-SEC-02 ต้องรอ Q-06. การตรวจสอบ traceability ระหว่าง AC กับ FR/NFR รอ Q-04.

## 7. ลำดับงาน

1. ออกแบบ Account และ IdentityProfile จากข้อมูลสมัครและ identifier แยกตามประเภทผู้ใช้ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-05, ASM-07)
2. วางการตรวจทะเบียนและจำแนกผู้ไม่พบข้อมูลเป็นบุคคลภายนอก; เมื่อทะเบียนไม่ตอบสนองไม่สร้างบัญชีและแจ้งให้ลองใหม่ แต่ช่องทางเชื่อมต่อรอ Q-07 (AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-06, ASM-13)
3. เพิ่ม API และหน้าสมัครสมาชิก โดยตรวจเงื่อนไขอีเมลและเก็บวันเกิดเต็มสำหรับบุคคลภายนอก พร้อมสร้างชื่อแสดงผลจากชื่อและนามสกุล (AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01, ASM-05, ASM-10, ASM-11)
4. ปรับ API เข้าสู่ระบบให้รองรับ identifier ตามประเภท และข้อความกรณีข้อมูลไม่ถูกต้อง (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-01, FR-สมัครสมาชิก-/-เข้าสู่ระบบ-02, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-02, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-03)
5. ปรับ flow ลืมรหัสผ่านให้ตรวจชุดข้อมูลตามประเภทและแหล่งวันเกิด ก่อนอนุญาตให้ตั้งรหัสผ่านใหม่ (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-03, AC-สมัครสมาชิก-/-เข้าสู่ระบบ-04, ASM-09, ASM-10)
6. เพิ่ม policy helper ห้ามบุคคลภายนอกยืมหนังสือ; เชื่อม helper เข้ากับ flow ยืมเมื่อมี API/service และ mapping บทบาทรอทีม (FR-สมัครสมาชิก-/-เข้าสู่ระบบ-04, ASM-08, Q-02)
7. กำหนดแนวทางปกป้องรหัสผ่าน/ข้อมูลส่วนบุคคลกับทีม และวางการหมดอายุ session โดยรอเกณฑ์ที่ยังไม่ชัด (NFR-SEC-01, NFR-SEC-02, Q-03, Q-06)
8. เพิ่มและรันทดสอบตาม AC ทั้ง 4 ข้อ พร้อมทบทวน traceability และ Constraints (AC-สมัครสมาชิก-/-เข้าสู่ระบบ-01 ถึง AC-สมัครสมาชิก-/-เข้าสู่ระบบ-04, Q-02, Q-03, Q-04, Q-06, Q-07)

## 8. สิ่งที่ยังไม่ทำ

- **Q-02** แต่ละบทบาทเข้าถึงฟังก์ชันใดได้บ้าง นอกเหนือจากข้อจำกัดของบุคคลภายนอกที่ระบุไว้? ต้องถามทีม/ผู้รับผิดชอบ UC-14 ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03** ใช้เกณฑ์ใดตรวจสอบการจัดเก็บรหัสผ่านในรูป hash และการควบคุมสิทธิ์ให้เป็นไปตาม NFR-SEC-01? ต้องถามทีม/ผู้รับผิดชอบนโยบายความปลอดภัย ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-04** AC แต่ละข้อควรอ้างอิง FR/NFR ใด และมีนโยบายหรือค่ากำหนดใดใน UC Case.pdf ที่ต้องยืนยันเพิ่มเติม? ต้องถามทีม/ผู้จัดทำ UC Case.pdf ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-06** การกระทำใดนับเป็นการทำรายการหรือการใช้งานที่เริ่มนับเวลาใหม่สำหรับ NFR-SEC-02? ต้องถามทีม/ผู้รับผิดชอบนโยบายความปลอดภัย ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-07** ใช้ interface/API หรือ service ใดเชื่อมทะเบียนนักศึกษา/บุคลากร และรหัสประจำตัวที่ใช้ค้นทะเบียนรับมาจากไหน (ผู้ใช้กรอกหรือระบบหาได้อย่างไร)? ต้องถามทีม/ผู้ดูแลทะเบียนของมหาวิทยาลัย ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
