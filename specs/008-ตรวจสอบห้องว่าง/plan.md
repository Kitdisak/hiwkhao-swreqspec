# แผนงาน: ตรวจสอบห้องว่าง

อ้างอิง: SPEC-ตรวจสอบห้องว่าง-008 (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกเลือกวันที่ตั้งแต่วันนี้เป็นต้นไปและประเภทห้องเพื่อค้นหาห้องอ่านหนังสือหรือห้องประชุม (FR-ตรวจสอบห้องว่าง-01)
- ใช้ข้อมูลห้องและตารางการจองที่มีอยู่เป็นแหล่งอ้างอิง ไม่สร้างรายการจองในฟีเจอร์นี้ (Constraints, Scope: Out of scope)
- คำนวณช่วงว่างทุก 30 นาทีระหว่าง 08:00–20:00 จากรายการจอง และไม่นับช่วงที่เริ่มผ่านไปแล้วในวันนี้ (FR-ตรวจสอบห้องว่าง-02, ASM-03, ASM-05)
- จำนวนผู้ใช้งานเป็นตัวกรองเสริม โดยห้องต้องมีความจุอย่างน้อยเท่ากับจำนวนที่ระบุ (FR-ตรวจสอบห้องว่าง-03, ASM-04)
- แสดงเฉพาะห้องที่มีช่วงว่าง; หากผลลัพธ์ว่าง แจ้งว่าไม่มีห้องว่างโดยไม่แนะนำวันหรือเวลาอื่น (FR-ตรวจสอบห้องว่าง-04)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตามคำสั่ง /plan; spec ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตามคำสั่ง /plan; spec ไม่มี Constraint ระบุภาษา/framework |

ไม่เลือกฐานข้อมูล เนื่องจาก spec ไม่ระบุเทคโนโลยีฐานข้อมูลและไม่มีค่าเริ่มต้นในคำสั่ง /plan

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Room | room reference, room type, capacity (ข้อมูลอาจไม่มี) | FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-03 |
| RoomBooking | booking reference, room reference, date, start time, end time | FR-ตรวจสอบห้องว่าง-02; Constraint: ผลลัพธ์ต้องอ้างอิงการจองที่มีอยู่ |
| AvailabilityConfig | opening time, closing time, slot duration | FR-ตรวจสอบห้องว่าง-02, ASM-03 |
| AvailabilityResult (ผลคำนวณ ไม่จำเป็นต้องจัดเก็บถาวร) | room reference, date, available time slots | FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-04 |

สร้างช่วงเวลาจาก AvailabilityConfig โดยค่าตั้งต้นตาม ASM-03 คือ 08:00–20:00 และช่วงละ 30 นาที; ช่วงใดที่มีรายการจองทับแม้บางส่วนจะไม่ถูกนับว่าว่าง (FR-ตรวจสอบห้องว่าง-02, ASM-03, ASM-05). การอ่านรายการจองเป็นแบบอ่านข้อมูลเดิม ไม่สร้าง/แก้ไขการจอง (Constraints, Scope: Out of scope).

การเลือกทางเทคนิคของทีมที่ไม่ได้มาจาก spec: เก็บข้อมูลห้องและรายการจองห้องในหน่วยความจำไว้ที่ `backend/app/rooms/store.py` เป็นแหล่งเดียว; UC-09 จะใช้ store เดียวกันเพื่อบันทึกการจองภายหลัง โดยไม่ซ้ำกับ store การจองหนังสือ. มีข้อมูล demo จำนวนน้อยซึ่งไม่ใช่ข้อมูลจริงของห้องสมุด. ค่ากำหนดเวลาอ่านจาก environment variables `ROOMS_OPENING_TIME`, `ROOMS_CLOSING_TIME` และ `ROOMS_SLOT_MINUTES` โดยใช้ค่าเริ่มต้นตาม ASM-03. ฟังก์ชันคำนวณความว่างรับรายการห้อง รายการจอง วันที่ ประเภทห้อง จำนวนผู้ใช้ เวลาปัจจุบันใน Asia/Bangkok และ config เป็น input; ไม่อ่าน store หรือนาฬิกาเอง. Tests สร้าง fixture ของตนเอง ไม่พึ่งข้อมูล demo. ไม่สร้างฐานข้อมูลจริงหรือการบันทึกการจองใน UC-08 (FR-ตรวจสอบห้องว่าง-02, Constraints, Scope: Out of scope).

## 4. API / หน้าจอ

รายการ method/path เป็นข้อเสนอทางเทคนิคเพื่อรองรับ FR; ไม่รวมการสร้างรายการจองห้อง

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ตรวจสอบห้องว่างรายวัน | `GET /api/rooms/availability`; input: date, room type, optional user count; output: ห้องที่มีช่วงว่างพร้อมช่วงเวลาว่าง หรือผลไม่มีห้องว่าง; จำนวนผู้ใช้ที่ไม่ใช่จำนวนเต็มตั้งแต่ 1 ขึ้นไปให้ตอบข้อผิดพลาดตรวจสอบข้อมูลและไม่ค้นหา | FR-ตรวจสอบห้องว่าง-01 ถึง FR-ตรวจสอบห้องว่าง-04 |
| หน้าตรวจสอบห้องว่าง `/rooms/availability` | input: วันที่, ประเภทห้อง, จำนวนผู้ใช้ (ไม่บังคับ); output: รายการห้อง/ช่วงเวลาว่าง, ข้อความตรวจสอบจำนวนผู้ใช้ หรือข้อความว่าไม่มีห้องว่างโดยไม่มีรายการ/คำแนะนำ | FR-ตรวจสอบห้องว่าง-01 ถึง FR-ตรวจสอบห้องว่าง-04, ASM-01 ถึง ASM-05 |

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ตรวจสอบห้องว่าง-008

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ระบบต้องมีข้อมูลห้องและตารางการจอง | ใช้ Room และ RoomBooking เป็นข้อมูลตั้งต้นสำหรับคำนวณช่วงว่าง (FR-ตรวจสอบห้องว่าง-02) | ใช้แล้ว |
| ไม่มี ID: ผลลัพธ์ต้องอ้างอิงการจองที่มีอยู่ | ตรวจรายการ RoomBooking ของวันที่เลือกก่อนระบุช่วงเวลาว่าง (FR-ตรวจสอบห้องว่าง-02, ASM-05) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ตรวจสอบห้องว่าง-01 | `test_AC_ตรวจสอบห้องว่าง_01` | เตรียมห้องประเภทเดียวกัน A ที่ถูกจอง 08:00–12:00 และ B ที่ถูกจองเต็มวัน; ตรวจว่าห้อง A แสดงเฉพาะช่วง 12:00–20:00 ทุก 30 นาทีและไม่แสดงห้อง B; ตรวจกรณีค้นหาวันนี้เวลา 14:10 และกรณีวันที่ก่อนวันนี้ซึ่งค้นหาไม่ได้ (FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-02, ASM-03, ASM-05) |
| AC-ตรวจสอบห้องว่าง-02 | `test_AC_ตรวจสอบห้องว่าง_02` | เตรียมห้องว่างความจุ 4, 6 และ 10; ระบุ 6 แล้วตรวจว่ามีเฉพาะ 6/10, ไม่ระบุแล้วตรวจว่ามีทั้งสาม, ระบุ 12 แล้วตรวจข้อความไม่มีห้องว่าง, และระบุค่าที่ไม่ใช่จำนวนเต็มตั้งแต่ 1 ขึ้นไปแล้วตรวจว่าแจ้งให้กรอกใหม่โดยไม่ค้นหา (FR-ตรวจสอบห้องว่าง-03, ASM-04) |
| AC-ตรวจสอบห้องว่าง-03 | `test_AC_ตรวจสอบห้องว่าง_03` | เตรียมข้อมูลให้มีห้องว่างเฉพาะประเภทห้องอ่านหนังสือ แล้วค้นหาห้องประชุม; ตรวจข้อความไม่มีห้องว่างและไม่แสดงรายการหรือคำแนะนำวัน/เวลาอื่น (FR-ตรวจสอบห้องว่าง-04, ASM-02, ASM-05) |

ทดสอบ NFR-PERF-01 ด้วยสคริปต์ `backend/tests/perf_room_availability.py`: สร้างข้อมูลทดสอบ 50 ห้อง (ประเภทห้องอ่านหนังสือ/ห้องประชุม, ความจุ 2–20 คน) และรายการจอง 36,000 รายการใน 60 วัน โดยแต่ละห้องมีการจอง 12 จาก 24 ช่วงต่อวัน; ทดสอบ 50/200 requests พร้อมกันทั้งแบบไม่ใช้ตัวกรองและกรองอย่างน้อย 12 คน. วัดตั้งแต่เริ่มส่ง HTTP request จนรับและตรวจสอบ JSON response ครบ ซึ่งเป็นการวัด API แยกจาก browser rendering ตามวิธีวัดของ SPEC-001 ASM-06; รายงานสัดส่วนคำขอไม่เกิน 3 วินาที, p95, ค่าเฉลี่ย และค่าสูงสุด. เป้าหมายคืออย่างน้อย 95% ไม่เกิน 3 วินาที แต่ไม่ใช้เป็นเกณฑ์ผ่าน/ตก (NFR-PERF-01, ASM-06).

## 7. ลำดับงาน

1. เตรียมการอ่านข้อมูลห้องและตารางการจองที่มีอยู่โดยไม่สร้างรายการจอง (Constraints, FR-ตรวจสอบห้องว่าง-02)
2. อ่านค่ากำหนดเวลาเปิด/ปิดและความยาวช่วงเวลา โดยตั้งค่าตาม ASM-03 และไม่ hard-code ใน logic (FR-ตรวจสอบห้องว่าง-02, ASM-03)
3. รับวันที่และประเภทห้องจากผู้ใช้; จำกัดวันที่ค้นหาให้เริ่มตั้งแต่วันนี้ (FR-ตรวจสอบห้องว่าง-01, AC-ตรวจสอบห้องว่าง-01, ASM-05)
4. สร้างช่วงละ 30 นาทีและตัดช่วงที่มีรายการจองทับ รวมถึงช่วงที่เวลาเริ่มผ่านไปแล้วในวันนี้ (FR-ตรวจสอบห้องว่าง-02, AC-ตรวจสอบห้องว่าง-01, ASM-05)
5. กรองประเภทห้องและตัวกรองความจุที่ไม่บังคับ; ปฏิเสธจำนวนผู้ใช้ที่ไม่ใช่จำนวนเต็มตั้งแต่ 1 ขึ้นไป (FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-03, AC-ตรวจสอบห้องว่าง-02)
6. ตัดห้องที่ไม่มีช่วงว่างออกและแสดงผลหรือสถานะไม่มีห้องว่างตามที่กำหนด (FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-04, AC-ตรวจสอบห้องว่าง-03)
7. ทดสอบ AC ทั้งสามข้อและประเมิน NFR-PERF-01 ตามชุดข้อมูล/ภาระทดสอบใน spec (AC-ตรวจสอบห้องว่าง-01 ถึง AC-ตรวจสอบห้องว่าง-03, NFR-PERF-01)

## 8. สิ่งที่ยังไม่ทำ

- **Q-06** เวลาทำการจริงและวันหยุด/วันปิดทำการของห้องสมุดตรงกับค่ากำหนดของทีมอย่างไร? ต้องยืนยันกับผู้ดูแลห้อง/ผู้กำหนดตารางห้อง (บรรณารักษ์) ส่วนการตั้งค่าให้ตรงกับเวลาจริงและการรองรับวันหยุด/วันปิดทำการจะยังไม่สร้างจนกว่าจะได้คำตอบ; ระหว่างนี้ใช้ค่าทีมตาม ASM-03 และยังไม่รองรับวันหยุด/วันปิดทำการ
