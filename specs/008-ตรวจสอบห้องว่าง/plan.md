# แผนงาน: ตรวจสอบห้องว่าง

อ้างอิง: SPEC-ตรวจสอบห้องว่าง-008 (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกเลือกวันที่และประเภทห้องเพื่อค้นหาห้องอ่านหนังสือหรือห้องประชุมที่ว่าง (FR-ตรวจสอบห้องว่าง-01)
- ระบบใช้ข้อมูลห้องและตารางการจองที่มีอยู่ในการตรวจสอบ (Constraints, FR-ตรวจสอบห้องว่าง-02)
- แสดงห้องและทุกช่วงเวลาที่ยังว่างในวันที่เลือก โดยไม่ต้องระบุช่วงเวลาเฉพาะเป็นเงื่อนไขค้นหา (FR-ตรวจสอบห้องว่าง-02, ASM-01)
- หากระบุจำนวนผู้ใช้งาน กรองห้องตามความสามารถรองรับจำนวนนั้น โดยเกณฑ์เทียบ capacity รอ Q-02 (FR-ตรวจสอบห้องว่าง-03, Q-02)
- หากไม่มีห้องว่าง แจ้งว่าไม่มีห้องว่างโดยไม่แสดงรายการหรือคำแนะนำวัน/เวลาอื่น และไม่สร้างรายการจอง (FR-ตรวจสอบห้องว่าง-04, ASM-02, Scope: Out of scope)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุภาษา/framework |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Room | room reference, room type, capacity | FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-03 |
| RoomBooking | room reference, date, start time, end time, booking reference | FR-ตรวจสอบห้องว่าง-02; Constraint: ผลลัพธ์อ้างอิงการจองที่มีอยู่ |
| AvailabilityResult (ผลคำนวณ ไม่จำเป็นต้องเป็นข้อมูลจัดเก็บถาวร) | room reference, date, available time periods | FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-04 |

ตรวจช่วงเวลาว่างโดยอ้างอิง RoomBooking ของวันที่เลือก; ขอบเขตเวลาเปิดและหน่วยแบ่งช่วงยังรอ Q-01 ส่วนการกรอง Room.capacity ต้องรอการยืนยันว่าจะใช้ capacity เท่ากับหรืออย่างน้อยจำนวนที่ระบุ (Constraints, FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-03, Q-01, Q-02).

## 4. API / หน้าจอ

รายการ method/path เป็นข้อเสนอทางเทคนิคเพื่อรองรับ FR; ไม่รวมการสร้างรายการจองซึ่งอยู่นอกขอบเขต

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ตรวจสอบห้องว่างรายวัน | `GET /api/rooms/availability`; input: date, room type, optional user count; output: ห้องที่ว่างและทุกช่วงเวลาว่างของวันที่เลือก หรือผลลัพธ์ว่างเมื่อไม่มีห้อง | FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-03, FR-ตรวจสอบห้องว่าง-04 |
| หน้าตรวจสอบห้องว่าง | input: วันที่, ประเภทห้อง, optional จำนวนผู้ใช้; output: รายการห้อง/ช่วงเวลาว่าง หรือข้อความว่าไม่มีห้องว่างโดยไม่มีรายการหรือคำแนะนำ | FR-ตรวจสอบห้องว่าง-01 ถึง FR-ตรวจสอบห้องว่าง-04, ASM-01, ASM-02 |

หน่วยช่วงเวลาที่ endpoint ส่งกลับและเกณฑ์กรองจำนวนผู้ใช้ยังไม่กำหนดจนกว่าจะได้ Q-01/Q-02 (FR-ตรวจสอบห้องว่าง-02, FR-ตรวจสอบห้องว่าง-03, Q-01, Q-02).

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ตรวจสอบห้องว่าง-008

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ระบบต้องมีข้อมูลห้องและตารางการจอง | ใช้ Room และ RoomBooking เป็นข้อมูลตั้งต้นสำหรับคำนวณผลว่าง (FR-ตรวจสอบห้องว่าง-02) | ใช้แล้ว |
| ไม่มี ID: ผลลัพธ์ต้องอ้างอิงการจองที่มีอยู่ | ตรวจตาราง RoomBooking ของวันที่เลือกก่อนระบุช่วงเวลาว่าง (FR-ตรวจสอบห้องว่าง-02, ASM-01) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ตรวจสอบห้องว่าง-01 | `test_AC_ตรวจสอบห้องว่าง_01` | เตรียมข้อมูลห้องและตารางจองหลายช่วงในวันที่เลือก เลือกวันที่/ประเภทห้อง แล้วตรวจว่าผลมีห้องและทุกช่วงเวลาที่ยังว่างในวันนั้น (FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-02, AC-ตรวจสอบห้องว่าง-01, ASM-01) |
| AC-ตรวจสอบห้องว่าง-02 | `test_AC_ตรวจสอบห้องว่าง_02` | เตรียมห้องหลายความจุ ระบุจำนวนผู้ใช้ ตรวจว่ามีเฉพาะห้องที่ผ่านเกณฑ์ capacity; เกณฑ์เทียบจำนวนรอ Q-02 (FR-ตรวจสอบห้องว่าง-03, AC-ตรวจสอบห้องว่าง-02, Q-02) |
| AC-ตรวจสอบห้องว่าง-03 | `test_AC_ตรวจสอบห้องว่าง_03` | เตรียมวันที่ไม่มีช่วงเวลาว่าง ค้นหาวันนั้น ตรวจว่าระบบแจ้งว่าไม่มีห้องว่างและไม่มีรายการห้องหรือคำแนะนำวัน/เวลาอื่น (FR-ตรวจสอบห้องว่าง-04, AC-ตรวจสอบห้องว่าง-03, ASM-02) |

การยืนยันเวลาตอบสนอง 3 วินาทียังระบุชุดข้อมูลและจุดจับเวลาไม่ได้จนกว่าจะได้ Q-03 (NFR-PERF-01, Q-03).

## 7. ลำดับงาน

1. เตรียมข้อมูลห้องและตารางการจองซึ่งเป็นแหล่งอ้างอิงผลว่าง (Constraints, FR-ตรวจสอบห้องว่าง-02)
2. ยืนยันเวลาเปิดและหน่วยแบ่งช่วงเวลาที่ใช้คำนวณผลว่าง (FR-ตรวจสอบห้องว่าง-02, Q-01)
3. สร้างการรับวันที่และประเภทห้องสำหรับค้นหา (FR-ตรวจสอบห้องว่าง-01, AC-ตรวจสอบห้องว่าง-01)
4. คำนวณทุกช่วงเวลาว่างในวันที่เลือกโดยเทียบกับตารางการจอง (FR-ตรวจสอบห้องว่าง-02, ASM-01)
5. เพิ่มตัวกรองจำนวนผู้ใช้ตามเกณฑ์ capacity หลังทีมยืนยัน (FR-ตรวจสอบห้องว่าง-03, Q-02)
6. แสดงผลว่าง หรือแจ้งไม่มีห้องว่างโดยไม่มีรายการ/คำแนะนำ (FR-ตรวจสอบห้องว่าง-04, ASM-02)
7. ตรวจ performance ตามจุดวัดและชุดข้อมูลที่ทีมกำหนด (NFR-PERF-01, Q-03)
8. รันทดสอบ AC ทั้งสามข้อและเติม traceability ตามคำยืนยันทีม (AC-ตรวจสอบห้องว่าง-01 ถึง AC-ตรวจสอบห้องว่าง-03, Q-04)

## 8. สิ่งที่ยังไม่ทำ

- **Q-01** ห้องเปิดให้จองช่วงเวลาใด และแบ่งช่วงเวลาเป็นหน่วยละเท่าใด? ต้องถามผู้ดูแลห้องหรือผู้กำหนดตารางห้อง ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-02** เมื่อกรองจำนวนผู้ใช้ ห้องต้องรองรับจำนวนเท่ากับที่ระบุหรืออย่างน้อยเท่ากับจำนวนที่ระบุ? ต้องถามทีม/ผู้ดูแลข้อมูลความจุห้อง ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-03** NFR-PERF-01 วัดตั้งแต่เมื่อใดถึงเมื่อใด และใช้จำนวนห้อง/รายการจองเท่าใดในการทดสอบ? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
- **Q-04** AC แต่ละข้อควรอ้างอิง FR/NFR ID ใดบ้าง? ต้องถามทีม ส่วนที่เกี่ยวข้องกับข้อนี้จะยังไม่สร้างจนกว่าจะได้คำตอบ
