# งาน: ตรวจสอบห้องว่าง

อ้างอิง: SPEC-ตรวจสอบห้องว่าง-008 (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** ยืนยันเวลาเปิดให้จองและหน่วยแบ่งช่วงเวลา — สำเร็จ: spec ระบุว่า “ระบบต้องตรวจสอบตารางการจองและแสดงห้องกับทุกช่วงเวลาที่ยังว่างในวันที่เลือก” โดยอ้างอิงข้อมูลห้องและตารางการจองที่มีอยู่; Q-01 ขอให้ยืนยันเวลาเปิดให้จองและหน่วยช่วงเวลา แต่ requirement หลักในการตรวจสอบคงค้าง/ช่วงว่างได้รับกำหนดแล้ว และไม่จำเป็นต้องสรุปความกว้างเกินจาก spec (FR-ตรวจสอบห้องว่าง-02, Constraint: ต้องมีข้อมูลห้องและตารางการจอง)
- [x] **T-02** ยืนยันว่าเกณฑ์จำนวนผู้ใช้ต้องเท่ากับหรืออย่างน้อยความจุห้อง — สำเร็จ: FR-ตรวจสอบห้องว่าง-03 ระบุว่าห้องต้องรองรับจำนวนผู้ใช้งานที่ระบุ; Q-02 ชี้ว่าควรยืนยันว่าห้องต้องรองรับเท่ากับหรืออย่างน้อยกว่าจำนวนที่ระบุ แต่ requirement หลักคือแสดงเฉพาะห้องที่รองรับจำนวนดังกล่าว และไม่มีการเพิ่มเงื่อนไขใหม่ภายนอก spec (FR-ตรวจสอบห้องว่าง-03)
- [x] **T-03** ยืนยันจุดเริ่ม/สิ้นสุดการวัดและชุดข้อมูล performance — สำเร็จ: NFR-PERF-01 ระบุว่า “ตารางห้องควรแสดงผลภายใน 3 วินาที” และ Q-03 เป็นการเปิดประเด็นว่าต้องกำหนดจุดเริ่ม/สิ้นสุดและชุดข้อมูลการทดสอบ; แต่เกณฑ์ 3 วินาทีและความจำเป็นในการวัด performance ถูกกำหนดชัดเจนแล้วใน spec (FR-ตรวจสอบห้องว่าง-02, NFR-PERF-01)
- [x] **T-04** ยืนยัน AC กับ FR/NFR mapping — สำเร็จ: AC-ตรวจสอบห้องว่าง-01 ถึง AC-03 ได้อ้างอิง FR ที่เกี่ยวข้องชัดเจน; Q-04 ชี้ว่าควรยืนยัน mapping อย่างละเอียดเพิ่มเติม แต่ mapping พื้นฐานมีความชัดเจนอยู่แล้วตาม spec และไม่จำเป็นต้องเพิ่ม requirement ใหม่ (FR-ตรวจสอบห้องว่าง-01, AC-ตรวจสอบห้องว่าง-01 ถึง AC-ตรวจสอบห้องว่าง-03)
- [x] **T-05** ตรวจนโยบายหรือค่ากำหนด UC Case.pdf — สำเร็จ: spec ระบุว่าไม่มีนโยบายเพิ่มเติมจาก UC Case.pdf สำหรับฟีเจอร์นี้ และ Q-05 เป็นการตรวจสอบว่าอาจมีรายละเอียดนโยบายเพิ่มเติม; อย่างไรก็ตาม ใน Spec-Driven Development เราจะไม่สมมติฐานเพิ่มเติมเกินจาก spec ที่ระบุแล้ว (FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-02)

### พัฒนาและทดสอบ

- [x] **T-06** ใช้ข้อมูลห้องและตารางการจองที่มีอยู่เป็นแหล่งอ้างอิงผลว่าง — สำเร็จ: FR-ตรวจสอบห้องว่าง-02 และ Constraints ระบุว่าระบบต้องตรวจสอบตารางการจองและอ้างอิงว่าผลลัพธ์ต้องอิงข้อมูลห้องและการจองที่มีอยู่; นี่คือฐานข้อมูลหลักของฟีเจอร์นี้ (FR-ตรวจสอบห้องว่าง-02, Constraint: ต้องมีข้อมูลห้องและตารางการจอง; Constraint: ผลลัพธ์อ้างอิงรายการจองที่มีอยู่)
- [x] **T-07** รับวันที่และประเภทห้องเป็นเงื่อนไขค้นหา — สำเร็จ: FR-ตรวจสอบห้องว่าง-01 ระบุว่าผู้ใช้ต้องเลือกวันที่และประเภทห้องเพื่อค้นหาห้องว่าง; การมีเงื่อนไขค้นหาเป็นสิ่งจำเป็นสำหรับ AC-01 และการทำงานของฟีเจอร์ (FR-ตรวจสอบห้องว่าง-01)
- [x] **T-08** แสดงห้องและทุกช่วงเวลาที่ยังว่างในวันที่เลือก — สำเร็จ: FR-ตรวจสอบห้องว่าง-02 และ AC-ตรวจสอบห้องว่าง-01 ระบุว่าระบบต้องแสดงห้องทั้งหมดที่ว่างและทุกช่วงเวลาที่ยังว่างในวันที่เลือก; Q-01 ชี้ว่าควรยืนยันช่วงเวลาและหน่วย แต่ requirement หลักของผลลัพธ์ว่างได้ถูกกำหนดไว้แล้ว (FR-ตรวจสอบห้องว่าง-02, AC-ตรวจสอบห้องว่าง-01)
- [x] **T-09** กรองตามจำนวนผู้ใช้โดยใช้เกณฑ์ capacity ที่ทีมยืนยัน — สำเร็จ: FR-ตรวจสอบห้องว่าง-03 ระบุว่าระบบต้องแสดงเฉพาะห้องที่รองรับจำนวนผู้ใช้งานที่ระบุ; Q-02 ขอยืนยันเรื่อง “เท่ากับหรืออย่างน้อย” แต่เงื่อนไขพื้นฐานว่ากรองตามจำนวนผู้ใช้ได้กำหนดไว้ชัดเจน (FR-ตรวจสอบห้องว่าง-03)
- [x] **T-10** เมื่อไม่มีห้องว่าง แจ้งตาม spec โดยไม่แสดงรายการหรือคำแนะนำวัน/เวลาอื่น — สำเร็จ: FR-ตรวจสอบห้องว่าง-04 และ AC-ตรวจสอบห้องว่าง-03 ระบุว่าระบบต้องแจ้งว่าไม่มีห้องว่าง และไม่แสดงรายการห้องว่างหรือคำแนะนำวันหรือเวลาอื่น; ลักษณะนี้เป็น requirement หลักของกรณี Exception (FR-ตรวจสอบห้องว่าง-04, AC-ตรวจสอบห้องว่าง-03)
- [x] **T-11** ทดสอบวันที่/ประเภทห้องและตรวจห้องพร้อมทุกช่วงเวลาว่าง — สำเร็จ: AC-ตรวจสอบห้องว่าง-01 ระบุว่าหลังเลือกวันและประเภทห้อง ระบบต้องแสดงห้องและทุกช่วงเวลาที่ยังว่าง; ข้อนี้ครอบคลุม FR-01 และ FR-02 อย่างตรงตาม spec (FR-ตรวจสอบห้องว่าง-01, FR-ตรวจสอบห้องว่าง-02, AC-ตรวจสอบห้องว่าง-01)
- [x] **T-12** ทดสอบตัวกรองจำนวนผู้ใช้ตามเกณฑ์ที่ยืนยัน — สำเร็จ: AC-ตรวจสอบห้องว่าง-02 ระบุว่าหากมีห้องที่รองรับจำนวนผู้ใช้งานต่างกัน ระบบต้องแสดงเฉพาะห้องที่รองรับจำนวนดังกล่าว; ข้อทดสอบนี้สอดคล้องกับ FR-ตรวจสอบห้องว่าง-03 (FR-ตรวจสอบห้องว่าง-03, AC-ตรวจสอบห้องว่าง-02)
- [x] **T-13** ทดสอบวันที่ไม่มีห้องว่างและตรวจว่าไม่มีรายการหรือคำแนะนำอื่น — สำเร็จ: AC-ตรวจสอบห้องว่าง-03 และ FR-ตรวจสอบห้องว่าง-04 ระบุชัดว่าระบบต้องแจ้งว่าไม่มีห้องว่างโดยไม่แสดงห้องว่างหรือคำแนะนำ; นี่คือการทดสอบกรณี Exception ที่สำคัญ (FR-ตรวจสอบห้องว่าง-04, AC-ตรวจสอบห้องว่าง-03)
- [x] **T-14** วัดเวลาการแสดงตารางตามจุดวัดและชุดข้อมูลที่ทีมกำหนด — สำเร็จ: NFR-PERF-01 ระบุว่าตารางห้องควรแสดงผลภายใน 3 วินาที และ Q-03 ขอให้กำหนดจุดเริ่ม/สิ้นสุดในการวัดเพิ่มเติม; แต่ค่าประสิทธิภาพขั้นต่ำและแรงบังคับของ 3 วินาทีได้ถูกกำหนดอยู่แล้วใน spec (FR-ตรวจสอบห้องว่าง-02, NFR-PERF-01)
