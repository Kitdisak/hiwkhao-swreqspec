# งาน: ชำระค่าปรับออนไลน์

อ้างอิง: [SPEC-ชำระค่าปรับออนไลน์-007](./spec.md) (Draft v2)

## ลำดับงาน

### ยืนยันประเด็นคงค้าง

- [x] **T-01** กำหนดสถานะเมื่อ Gateway ไม่ตอบหรือตอบช้า — ระบุ Pending หลัง 30 วินาที, ห้ามชำระซ้ำ, ตรวจสอบด้วย ref เดิมทุก 5 นาที และหมดอายุเมื่อครบ 30 นาที (FR-ชำระค่าปรับออนไลน์-04, ASM-04)
- [x] **T-02** กำหนดการจับคู่ผล Gateway และจัดการผลซ้ำ/ผิดลำดับ — ใช้ `payment_ref` และยอดเงินจับคู่, ยอมรับผลสำเร็จซ้ำโดยไม่บันทึกซ้ำ และยอมรับผลสำเร็จที่มาหลังหมดอายุ (FR-ชำระค่าปรับออนไลน์-02, FR-ชำระค่าปรับออนไลน์-03, NFR-REL-01)
- [x] **T-03** กำหนดบทบาท Actor — สมาชิกเป็น Primary Actor และ Payment Gateway เป็น Secondary Actor (ASM-02)
- [x] **T-04** กำหนดรายละเอียดที่แสดงก่อนยืนยัน — แสดงข้อมูลค่าปรับแต่ละรายการ ยอดรวม และช่องทางที่เลือก (FR-ชำระค่าปรับออนไลน์-01)
- [x] **T-05** ตรวจการโยง AC กับ FR/NFR — AC-01 ถึง AC-03 อ้างอิง FR/NFR ใน spec (AC-ชำระค่าปรับออนไลน์-01 ถึง AC-ชำระค่าปรับออนไลน์-03)
- [x] **T-06** ตรวจขอบเขต Use Case — ใช้ข้อกำหนดใน spec ปัจจุบัน; ไม่เพิ่มนโยบายค่าปรับหรือขอบเขตนอกเหนือจาก spec (Scope, Q-07, Q-08)

### พัฒนาและทดสอบ

- [x] **T-07** แสดงรายการค่าปรับค้าง รายละเอียดต่อรายการ และยอดรวม โดยไม่คำนวณค่าปรับใหม่ (FR-ชำระค่าปรับออนไลน์-01)
- [x] **T-08** สร้างคำขอพร้อม `payment_ref` ที่ไม่ซ้ำ ผูกกับสมาชิก รายการค่าปรับ และยอดรวม พร้อมจำกัดคำขอ Pending ให้มีได้ครั้งละหนึ่งคำขอต่อชุดค่าปรับ (FR-ชำระค่าปรับออนไลน์-02, Constraints)
- [ ] **T-09** เชื่อมต่อ Payment Gateway จริงผ่านการสื่อสารที่ปลอดภัย — blocked: spec ไม่ระบุผู้ให้บริการ, endpoint/payload, วิธีตรวจ callback หรือ sandbox จึงยังเชื่อมระบบจริงอย่างปลอดภัยไม่ได้; มี adapter boundary ที่ปิดใช้งานเป็นค่าเริ่มต้นและไม่มีการส่งเงินจริง (FR-ชำระค่าปรับออนไลน์-02, NFR-SEC-01)
- [x] **T-10** ตรวจสอบ callback ด้วย adapter, จับคู่ ref/ยอดเงิน, บันทึกผลสำเร็จครั้งเดียว และเก็บผลที่ต้องตรวจสอบ (FR-ชำระค่าปรับออนไลน์-02, FR-ชำระค่าปรับออนไลน์-03, NFR-REL-01)
- [x] **T-11** จัดการผลล้มเหลว, Pending, ตรวจสถานะ และหมดอายุ; ห้ามเปลี่ยนค่าปรับเป็นชำระแล้วหากไม่มีผลสำเร็จที่ตรวจสอบได้ (FR-ชำระค่าปรับออนไลน์-04, NFR-REL-01)
- [x] **T-12** แสดงช่องทางที่เลือกและห้ามเปลี่ยนหลังสร้างคำขอ; เมื่อคำขอ Pending ให้ตรวจสถานะจาก ref เดิม (FR-ชำระค่าปรับออนไลน์-04, FR-ชำระค่าปรับออนไลน์-05)
- [x] **T-13** ทดสอบ flow ผลสำเร็จและการบันทึกครั้งเดียวด้วย fake Gateway (AC-ชำระค่าปรับออนไลน์-01, FR-ชำระค่าปรับออนไลน์-03)
- [x] **T-14** ทดสอบผลล้มเหลวและการคงค่าปรับค้างด้วย fake Gateway (AC-ชำระค่าปรับออนไลน์-02, FR-ชำระค่าปรับออนไลน์-04)
- [x] **T-15** ทดสอบการเปลี่ยนช่องทางก่อนยืนยันและตรวจข้อมูลที่แสดง; ตรวจ build ของหน้าจอ (AC-ชำระค่าปรับออนไลน์-03, FR-ชำระค่าปรับออนไลน์-01, FR-ชำระค่าปรับออนไลน์-05)

## ข้อจำกัดและคำถามที่ยังเปิดอยู่

- **Q-07** อัตราค่าปรับต่อวันและวิธีคำนวณยอดค่าปรับต่อรายการกำหนดอย่างไร? ต้องถามบรรณารักษ์/ผู้กำหนดนโยบายค่าปรับ
- **Q-08** จะยืนยันการตรวจผลสำเร็จซ้ำและกรณีไม่มีผลตอบกลับจนคำขอหมดอายุด้วย AC เดิมข้อใด หรือทีมต้องอนุมัติการเพิ่ม AC ใหม่ก่อน? ต้องถามทีม

ยังไม่เพิ่มพฤติกรรมหรือ AC ใหม่สำหรับ Q-07/Q-08; ใช้ fake Gateway ในการทดสอบเท่านั้น ไม่มีการส่งเงินจริงหรือการเชื่อมต่อ Gateway จริงจนกว่าจะมีข้อกำหนดผู้ให้บริการและ API.
