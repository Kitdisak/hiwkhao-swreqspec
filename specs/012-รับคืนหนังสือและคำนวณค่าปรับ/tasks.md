# งาน: รับคืนหนังสือและคำนวณค่าปรับ

อ้างอิง: SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012 (Draft v3)

## ลำดับงาน

### งานจากข้อกำหนดเดิม

- [x] **T-01** สแกนรหัสประจำเล่มและค้นหา Loan ที่ยังไม่คืน — สำเร็จ: ค้นด้วยรหัส Copy และเลือก Loan ที่ยังไม่คืนเพียงรายการเดียว (FR-01, ASM-03)
- [x] **T-02** ตรวจวันกำหนดคืนและแยกกรณีคืนตรงเวลาหรือเกินกำหนด — สำเร็จ: ใช้วันปฏิทินและไม่คิดค่าปรับเมื่อคืนตรงวันกำหนด (FR-02, FR-06)
- [x] **T-03** คำนวณค่าปรับจากวันเกินกำหนดและอัตราต่อวัน — สำเร็จ: ใช้ rate configuration ชั่วคราว 5.00 บาท/วัน/เล่ม, Decimal และ ROUND_HALF_UP สองตำแหน่ง; ค่าจริงยังรอ Q-01 (FR-03, NFR-ACC-01, ASM-01, ASM-07 ถึง ASM-10)
- [x] **T-04** เมื่อยืนยัน บันทึกการคืนและเปลี่ยนสถานะ Copy — สำเร็จ: ไม่มี Waiting ให้เปลี่ยนเป็น Available; มี Waiting ให้เป็น Reserved และเลื่อนคิวแรกเป็น Ready (FR-04, ASM-02, ASM-13, ASM-14)
- [x] **T-05** เมื่อไม่พบ Loan ที่ยังไม่คืน แจ้งให้ตรวจสอบและไม่บันทึกการคืน — สำเร็จ: API ตอบข้อผิดพลาดและไม่มีการเปลี่ยนสถานะ (FR-05, ASM-04)
- [x] **T-06** ทดสอบคืนเกินกำหนด — สำเร็จ: ตรวจวันเกินกำหนด, ค่าปรับ, FineItem, สถานะ Loan/Copy และผลตามคิว (AC-รับคืนหนังสือและคำนวณค่าปรับ-01)
- [x] **T-07** ทดสอบคืนตรงเวลา — สำเร็จ: ไม่มี FineItem และ Copy เป็น Available เมื่อไม่มี Waiting reservation (AC-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-06)
- [x] **T-08** ทดสอบ Copy ที่ไม่มี Loan ค้าง — สำเร็จ: แจ้งให้ตรวจสอบและไม่บันทึกการคืน (AC-รับคืนหนังสือและคำนวณค่าปรับ-03)

### งานจากข้อยุติ Draft v3

- [x] **T-09** ตั้งค่ากำหนดอัตราและคำนวณค่าปรับ — สำเร็จ: rate ไม่ hardcode; คิดแยกต่อ Loan โดยใช้อัตรา ณ วันรับคืนและวันที่ Asia/Bangkok บน server (FR-02, FR-03, NFR-ACC-01, ASM-07 ถึง ASM-10)
- [x] **T-10** เก็บ FineItem ร่วมกับข้อมูล Loan/Copy/Reservation — สำเร็จ: backing store ใช้ SQLite เดิม, FineItem ผูก Loan/member พร้อม applied rate และคง model/สัญญาที่ SPEC-007 ใช้ (ASM-11, ASM-12)
- [x] **T-11** เพิ่มข้อมูลวันคืนและสถานะ Returned ใน LoanItem — สำเร็จ: migration รักษารายการยืมเดิมและ unique active Loan ต่อ Copy (FR-04, ASM-12)
- [x] **T-12** บันทึกการคืน ค่าปรับ Copy และ Reservation แบบ atomic — สำเร็จ: ทั้งหมดใช้ transaction เดียว; เลือก Available หรือ Waiting → Ready/Reserved และ deadline provisional 3 วัน (FR-04, ASM-12 ถึง ASM-14)
- [x] **T-13** จัดการกรณีไม่พบหรือพบ active Loan หลายรายการ — สำเร็จ: ไม่พบให้แจ้งตรวจสอบ; พบมากกว่าหนึ่งรายการให้ปฏิเสธและแจ้งเจ้าหน้าที่ (FR-01, FR-05, ASM-03, ASM-04, ASM-15)
- [x] **T-14** เชื่อม API และหน้าจอสแกน/ยืนยันรับคืน — สำเร็จ: แสดง Loan, วันกำหนดคืน, ค่าปรับประมาณการ และผลการยืนยัน (FR-01 ถึง FR-06, AC-01 ถึง AC-03)
- [x] **T-15** ทดสอบ Acceptance Criteria และ regression — สำเร็จ: ทดสอบ rounding, migration, atomic rollback, Reservation และการอ่าน FineItem ผ่าน SPEC-007; `pytest -q` ผ่าน 164 tests และ frontend build ผ่าน (AC-01 ถึง AC-03, ASM-07 ถึง ASM-15)

### งานที่รอคำตอบ

- [ ] **T-16** เปลี่ยนเป็นอัตราค่าปรับจริง — **รอ Q-01**; ห้ามแทนค่า provisional จนกว่าจะได้รับอัตราจากผู้กำหนดนโยบาย (FR-03, ASM-07, Q-01)
- [ ] **T-17** เปลี่ยน pickup deadline เป็นจำนวนวันจริง — **รอ Q-02**; ปัจจุบันใช้ provisional 3 วัน (FR-04, ASM-14, Q-02)
- [ ] **T-18** กำหนดการจัดการเมื่อผู้จองไม่มารับ — **รอ Q-03**; ยังไม่เปลี่ยนสถานะ Reservation/Copy เมื่อพ้น deadline (Q-03)
- [ ] **T-19** กำหนดการแจ้งเตือนผู้จอง — **รอ Q-04**; ยังไม่เพิ่มการแจ้งเตือนหรือเลือกช่องทางเอง (Q-04)

## ข้อจำกัดและคำถามที่ยังเปิดอยู่

- **Q-01** อัตราค่าปรับจริงยังไม่ทราบ; ใช้ 5.00 บาท/วัน/เล่มเป็นค่า provisional
- **Q-02** จำนวนวันรับหนังสือหลัง Reservation เป็น Ready ที่ใช้งานจริงยังไม่ทราบ; ใช้ 3 วันเป็นค่า provisional
- **Q-03** ยังไม่ทราบว่าต้องทำอย่างไรเมื่อผู้จองไม่มารับภายใน pickup deadline
- **Q-04** ยังไม่ทราบว่าต้องแจ้งเตือนผู้จองหรือไม่และใช้ช่องทางใด

หมายเหตุ: ไม่รวมการชำระค่าปรับออนไลน์ (UC-07); ใช้ FineItem/store contract เดิมของ SPEC-007 และไม่แก้โค้ดหรือ tests ของ payment service.
