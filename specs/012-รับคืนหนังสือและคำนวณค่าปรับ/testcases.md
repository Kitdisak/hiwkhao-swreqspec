# Test Cases: AC-รับคืนหนังสือและคำนวณค่าปรับ-01

อ้างอิง: [spec.md](./spec.md), SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012 (Draft v3)

## ขอบเขต

ทดสอบการยืนยันคืน Loan ที่เกินกำหนด การคำนวณค่าปรับตามวันปฏิทินและอัตราต่อวัน การบันทึกการคืนและ FineItem ตลอดจนการเปลี่ยนสถานะ Copy ตามคิว Reservation ตาม AC-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง FR-รับคืนหนังสือและคำนวณค่าปรับ-04, NFR-ACC-01 และ ASM-07 ถึง ASM-14.

## กรณีทดสอบ

### กรณีคืนเกินกำหนดเมื่อไม่มี Reservation สถานะ Waiting

**ข้อมูลตั้งต้น**

- มี Loan ที่ยังไม่คืนของ Copy `COPY-RETURN-01` และสมาชิกที่เชื่อมกับ Loan
- วันกำหนดคืนคือ 15 พฤศจิกายน 2569; ยืนยันคืนวันที่ 18 พฤศจิกายน 2569 ตาม Asia/Bangkok
- ไม่มี Reservation สถานะ Waiting สำหรับชื่อเรื่อง
- ใช้อัตรา 5.00 บาท/วันจากค่ากำหนดทดสอบ ซึ่งเป็นค่า provisional ตาม ASM-07

**ขั้นตอน**

1. สแกนรหัส `COPY-RETURN-01` และตรวจข้อมูล Loan/วันกำหนดคืน
2. บรรณารักษ์ยืนยันรับคืน
3. ตรวจผลตอบกลับและข้อมูล Loan, Copy และ FineItem ใน store

**ผลที่คาดหวัง**

- บันทึก Loan เป็น Returned ด้วยวันที่ 18 พฤศจิกายน 2569
- จำนวนวันเกินกำหนดเป็น 3 วัน และยอดค่าปรับเป็น `15.00` บาท
- สร้าง FineItem หนึ่งรายการที่เชื่อมกับ Loan และสมาชิก พร้อมอัตรา `5.00`, จำนวนวัน 3 และยอด `15.00`
- Copy เปลี่ยนเป็น Available

**อ้างอิง:** AC-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง FR-รับคืนหนังสือและคำนวณค่าปรับ-04, NFR-ACC-01, ASM-07 ถึง ASM-13.

### กรณีคืนเกินกำหนดเมื่อมี Reservation สถานะ Waiting

**ข้อมูลตั้งต้น**

- เตรียม Loan เกินกำหนดเช่นเดียวกับกรณีก่อน
- มี Reservation สถานะ Waiting ของชื่อเรื่องเดียวกัน และเป็นรายการแรกตามลำดับคิว
- ใช้ pickup deadline ชั่วคราว 3 วันตาม ASM-14

**ขั้นตอน**

1. สแกน Copy และยืนยันรับคืน
2. ตรวจ Loan, FineItem, Copy และ Reservation หลังบันทึก

**ผลที่คาดหวัง**

- บันทึก Loan และ FineItem ด้วยจำนวนวัน/ยอดค่าปรับที่คำนวณตามกรณีไม่มี Waiting
- Reservation แรกเปลี่ยนจาก Waiting เป็น Ready และผูกกับ Copy ที่คืน
- Copy เปลี่ยนเป็น Reserved
- pickup deadline เป็นวันที่รับคืนบวก 3 วันตามค่า provisional ใน ASM-14

**อ้างอิง:** AC-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-04, ASM-12, ASM-14.

### กรณีขอบเขตวัน Asia/Bangkok และการปัดเศษ

**ข้อมูลตั้งต้น**

- วันกำหนดคืนคือ 17 พฤศจิกายน 2569
- เวลาที่ server ได้รับคือ `2026-11-17T18:00:00Z` ซึ่งเป็นวันที่ 18 พฤศจิกายน 2569 ใน Asia/Bangkok
- ตั้งอัตราทดสอบเป็น `2.125` บาทต่อวัน

**ขั้นตอน**

1. ตรวจรายการและค่าปรับที่คำนวณจากเวลาข้างต้น
2. ตรวจวันรับคืน จำนวนวันเกินกำหนด และยอดที่ปัดแล้ว

**ผลที่คาดหวัง**

- วันที่รับคืนฝั่ง server เป็น 18 พฤศจิกายน 2569 และเกินกำหนด 1 วัน
- ยอด `2.125` ถูกปัดแบบ ROUND_HALF_UP เป็น `2.13` บาท และแสดงทศนิยมสองตำแหน่ง

**อ้างอิง:** AC-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-03, NFR-ACC-01, ASM-09, ASM-10.

### กรณีบันทึกค่าปรับล้มเหลวระหว่างยืนยัน

**ข้อมูลตั้งต้น**

- มี Loan เกินกำหนด, Copy ที่ถูกยืม และ Reservation สถานะ Waiting
- ทำให้การบันทึก FineItem ล้มเหลวระหว่าง transaction

**ขั้นตอน**

1. บรรณารักษ์ยืนยันรับคืน
2. ตรวจสถานะ Loan, Copy, FineItem และ Reservation หลังเกิดข้อผิดพลาด

**ผลที่คาดหวัง**

- การยืนยันไม่สำเร็จ
- ไม่มีการเปลี่ยนแปลงบางส่วน: Loan ยังคง Borrowed, Copy ยังคง Borrowed, Reservation ยังคง Waiting และไม่มี FineItem ใหม่

**อ้างอิง:** FR-รับคืนหนังสือและคำนวณค่าปรับ-04, ASM-12.

## การทดสอบอัตโนมัติที่มีอยู่

ใน `backend/tests/test_ac_รับคืนหนังสือและคำนวณค่าปรับ.py`:

- `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01_overdue_return_creates_linked_fine` ตรวจวันคืน, 3 วันเกินกำหนด, FineItem ที่เชื่อม Loan/สมาชิก และ Copy เป็น Available
- `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01_staff_confirm_endpoint` ตรวจการยืนยันผ่าน API ของเจ้าหน้าที่
- `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01_round_half_up_and_bangkok_date` ตรวจวัน Asia/Bangkok และ ROUND_HALF_UP; ทดสอบผลคำนวณจาก lookup
- `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01_02_waiting_reservation_becomes_ready` ตรวจ Waiting → Ready, การผูก Copy และ Copy เป็น Reserved โดยใช้ข้อมูลคืนตรงเวลา
- `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01_rollback_on_fine_storage_failure` ตรวจ rollback เมื่อบันทึก FineItem ล้มเหลว

ยังไม่มี automated test เดียวที่รวมกรณีคืนเกินกำหนดพร้อม Reservation Waiting; กรณีดังกล่าวจึงระบุไว้เป็นกรณีทดสอบแยกเพื่อให้ตรวจครบทั้งการคำนวณค่าปรับและการเลื่อนคิวใน AC-01.

หมายเหตุ: อัตรา 5.00 บาทและ pickup deadline 3 วันเป็นค่า provisional ตาม ASM-07 และ ASM-14; อัตราจริงยังรอ Q-01 และจำนวนวันจริงยังรอ Q-02.

### กรณีคืนตรงวันกำหนดเมื่อไม่มี Reservation สถานะ Waiting

# Test Cases: AC-รับคืนหนังสือและคำนวณค่าปรับ-03

อ้างอิง: [spec.md](./spec.md), SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012 (Draft v3)

## ขอบเขต

ทดสอบกรณีค้นหา Loan ที่ยังไม่คืนไม่พบจากรหัสหนังสือที่สแกน โดยระบบต้องแจ้งให้ตรวจสอบข้อมูลและไม่บันทึกการคืน ตาม AC-รับคืนหนังสือและคำนวณค่าปรับ-03, FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-05 และ ASM-03 ถึง ASM-05.

## กรณีทดสอบ

### กรณีสแกนรหัสที่ไม่มี Loan ซึ่งยังไม่คืน

**ข้อมูลตั้งต้น**

- เตรียมรหัส Copy `COPY-MISSING` ซึ่งไม่มี Loan สถานะ Borrowed
- ตรวจสถานะข้อมูล Loan, Copy, FineItem และ Reservation ก่อนเริ่มทดสอบ

**ขั้นตอน**

1. บรรณารักษ์สแกนรหัส `COPY-MISSING` ในหน้ารับคืน
2. ตรวจข้อความแจ้งเตือนและยืนยันว่าไม่มีขั้นตอนบันทึกการคืนให้ดำเนินต่อ
3. ตรวจข้อมูล Loan, Copy, FineItem และ Reservation หลังสแกน

**ผลที่คาดหวัง**

- ระบบแจ้งให้ตรวจสอบข้อมูลตาม FR-05
- ไม่มีการบันทึกการคืนหรือสร้าง FineItem
- สถานะและข้อมูลเดิมของ Loan, Copy และ Reservation ไม่เปลี่ยน

**อ้างอิง:** AC-รับคืนหนังสือและคำนวณค่าปรับ-03, FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-05, ASM-03 ถึง ASM-05.

## การทดสอบอัตโนมัติที่มีอยู่

`backend/tests/test_ac_รับคืนหนังสือและคำนวณค่าปรับ.py::test_AC_รับคืนหนังสือและคำนวณค่าปรับ_03_missing_active_loan_does_not_change_data` เรียก `GET /api/returns/lookup` ด้วยรหัสที่ไม่มี active Loan และตรวจว่า API ตอบ 404 พร้อม code `active_loan_not_found`, ข้อความมีคำว่า “ตรวจสอบ” และไม่มีการสร้างตาราง LoanItem จากคำขอนั้น

การทดสอบอัตโนมัติครอบคลุม API lookup; ขั้นตอนสแกนบนหน้าจอและการแสดงข้อความแก่บรรณารักษ์ให้ตรวจด้วยกรณีทดสอบหน้าจอด้านบน.
