# แผนงาน: รับคืนหนังสือและคำนวณค่าปรับ

อ้างอิง: SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012 (Draft v2)

## 1. สรุปแนวทาง

- บรรณารักษ์สแกนรหัสหนังสือเพื่อค้นหา Loan ที่ยังไม่คืน (FR-รับคืนหนังสือและคำนวณค่าปรับ-01, ASM-03)
- ตรวจวันกำหนดคืนและคำนวณค่าปรับเมื่อคืนเกินกำหนดตามวันปฏิทินและอัตราห้องสมุด (FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-03, Constraints, ASM-01)
- เมื่อบรรณารักษ์ยืนยัน บันทึกการคืนและเปลี่ยนสถานะหนังสือเป็น Available (FR-รับคืนหนังสือและคำนวณค่าปรับ-04, ASM-02)
- เมื่อคืนตรงเวลา บันทึกการคืนโดยไม่คิดค่าปรับ; เมื่อไม่พบ Loan ที่ยังไม่คืน แจ้งให้ตรวจสอบและไม่บันทึกรายการ (FR-รับคืนหนังสือและคำนวณค่าปรับ-05, FR-รับคืนหนังสือและคำนวณค่าปรับ-06, ASM-04)
- ขอบเขตนี้ไม่รวมการชำระค่าปรับออนไลน์ และไม่มี Open Questions คงค้าง (Scope: Out of scope UC-07, ASM-06)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นตามรายวิชาใน prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นตามรายวิชาใน prompt /plan; ไม่มี Constraint ระบุภาษา/framework |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| BookCopy | unique item identifier, circulation status | FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-04, Constraint: รหัสประจำเล่ม |
| Loan | loan reference, BookCopy reference, due date, return date, loan status | FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-04, FR-รับคืนหนังสือและคำนวณค่าปรับ-05 |
| FineAssessment | loan reference, overdue calendar days, library daily rate, rounded fine amount | FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-03, FR-รับคืนหนังสือและคำนวณค่าปรับ-06, NFR-ACC-01, Constraint: อัตราห้องสมุด |

ใช้ Loan ที่ยังไม่คืนของ BookCopy ที่สแกน; ค่าปรับคิดจากจำนวนวันปฏิทินเกินกำหนดคูณอัตราต่อวันที่ห้องสมุดกำหนด ไม่มี grace period/เพดาน และปัดเป็นทศนิยมสองตำแหน่ง (FR-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง FR-รับคืนหนังสือและคำนวณค่าปรับ-03, ASM-01, ASM-03).

## 4. API / หน้าจอ

ข้อเสนอ interface สำหรับรับคืนและคำนวณค่าปรับ; ไม่รวม endpoint ชำระค่าปรับออนไลน์ (Scope: Out of scope UC-07)

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| ค้นหารายการยืมจากรหัสหนังสือ | `GET /api/loans/active?itemCode={code}`; input: รหัสประจำเล่มที่สแกน; output: Loan ที่ยังไม่คืนและวันกำหนดคืน หรือผลไม่พบรายการ | FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-05, ASM-03, ASM-04 |
| ยืนยันรับคืน | `POST /api/returns`; input: Loan reference และการยืนยันของบรรณารักษ์; output: ผลรับคืน, จำนวนวันเกินกำหนด/ค่าปรับเมื่อมี และสถานะ BookCopy เป็น Available | FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-03, FR-รับคืนหนังสือและคำนวณค่าปรับ-04, FR-รับคืนหนังสือและคำนวณค่าปรับ-06, NFR-ACC-01 |
| หน้าจอรับคืน | input: รหัสหนังสือที่สแกน; output: Loan ที่ยังไม่คืน, due date, fine amount เมื่อเกินกำหนด, ผลรับคืน หรือข้อความให้ตรวจสอบเมื่อไม่พบ Loan | FR-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง FR-รับคืนหนังสือและคำนวณค่าปรับ-06 |

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ค่าปรับคำนวณตามจำนวนวันเกินกำหนดและอัตราห้องสมุด | FineAssessment คิดวันปฏิทินเกินกำหนดคูณอัตราต่อวันจากนโยบายห้องสมุด (FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-03, ASM-01) | ใช้แล้ว |
| ไม่มี ID: ต้องมีรายการยืมของหนังสือที่นำมาคืน | ค้นหา Loan ที่ยังไม่คืนก่อนรับคืน; หากไม่พบ แจ้งตรวจสอบและไม่บันทึก (FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-05, ASM-03, ASM-04) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-รับคืนหนังสือและคำนวณค่าปรับ-01 | `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_01` | เตรียม Loan ที่เกินกำหนด ใช้อัตรารายวันที่กำหนดในข้อมูลทดสอบ คำนวณวันปฏิทิน/ยอดสองตำแหน่ง ยืนยันคืน แล้วตรวจ Loan ปิด, fine amount และ BookCopy เป็น Available (FR-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง FR-รับคืนหนังสือและคำนวณค่าปรับ-04, NFR-ACC-01, AC-รับคืนหนังสือและคำนวณค่าปรับ-01, ASM-01, ASM-02) |
| AC-รับคืนหนังสือและคำนวณค่าปรับ-02 | `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_02` | เตรียม Loan ที่คืนภายในวันกำหนด ยืนยันคืน แล้วตรวจว่าไม่มีค่าปรับและ BookCopy เปลี่ยนเป็น Available (FR-รับคืนหนังสือและคำนวณค่าปรับ-04, FR-รับคืนหนังสือและคำนวณค่าปรับ-06, AC-รับคืนหนังสือและคำนวณค่าปรับ-02, ASM-02) |
| AC-รับคืนหนังสือและคำนวณค่าปรับ-03 | `test_AC_รับคืนหนังสือและคำนวณค่าปรับ_03` | สแกนรหัสที่ไม่มี Loan ยังไม่คืน ตรวจว่าระบบแจ้งให้ตรวจสอบและไม่มี Loan/BookCopy ถูกเปลี่ยนแปลง (FR-รับคืนหนังสือและคำนวณค่าปรับ-01, FR-รับคืนหนังสือและคำนวณค่าปรับ-05, AC-รับคืนหนังสือและคำนวณค่าปรับ-03, ASM-04) |

## 7. ลำดับงาน

1. สแกนรหัสประจำเล่มและค้นหา Loan ที่ยังไม่คืน (FR-รับคืนหนังสือและคำนวณค่าปรับ-01, ASM-03)
2. หากไม่พบ Loan ที่ยังไม่คืน แจ้งให้ตรวจสอบและไม่บันทึกการคืน (FR-รับคืนหนังสือและคำนวณค่าปรับ-05, AC-รับคืนหนังสือและคำนวณค่าปรับ-03, ASM-04)
3. ตรวจ due date และจำแนกคืนตรงเวลาหรือเกินกำหนดตามวันปฏิทิน (FR-รับคืนหนังสือและคำนวณค่าปรับ-02, FR-รับคืนหนังสือและคำนวณค่าปรับ-06, ASM-01)
4. เมื่อเกินกำหนด คำนวณ FineAssessment จากวันเกินกำหนดและอัตราต่อวัน ปัดทศนิยมสองตำแหน่ง (FR-รับคืนหนังสือและคำนวณค่าปรับ-03, NFR-ACC-01, ASM-01)
5. ให้บรรณารักษ์ยืนยันการรับคืน (FR-รับคืนหนังสือและคำนวณค่าปรับ-04)
6. บันทึก return date ปิด Loan และเปลี่ยน BookCopy เป็น Available (FR-รับคืนหนังสือและคำนวณค่าปรับ-04, ASM-02)
7. ทดสอบกรณีเกินกำหนด คืนตรงเวลา และไม่พบ Loan ตาม AC ทั้งสามข้อ (AC-รับคืนหนังสือและคำนวณค่าปรับ-01 ถึง AC-รับคืนหนังสือและคำนวณค่าปรับ-03)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน SPEC-รับคืนหนังสือและคำนวณค่าปรับ-012 (Draft v2); ไม่มีรายการที่ต้องระงับไว้รอคำตอบ (ASM-06).
