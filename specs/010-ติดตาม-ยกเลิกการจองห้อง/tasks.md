# งาน: ติดตาม / ยกเลิกการจองห้อง

อ้างอิง: [SPEC-ติดตาม-ยกเลิกการจองห้อง-010](./spec.md) (Draft v2), [plan.md](./plan.md)

## ลำดับงาน

- [x] **T-01** ขยายแบบจำลองรายการจองร่วมใน `backend/app/rooms/models.py` และ `backend/app/rooms/store.py` ให้เก็บสถานะรายการ โดยยกเลิกแล้วต้องเก็บไว้ใน store พร้อมสถานะ “ยกเลิกแล้ว” แทนการลบรายการ (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-03, ASM-11) — สำเร็จใน `RoomBooking.status`, `get_room_booking`, `get_member_room_bookings` และ `cancel_room_booking`
- [x] **T-02** เพิ่มรายการจองและรายละเอียดรายการจองของผู้ใช้ปัจจุบันจาก session ใน API/backend โดยแสดงวัน เวลา ห้อง และสถานะ และเปิดดูรายละเอียดโดยไม่เปลี่ยนข้อมูล (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05, ASM-08) — สำเร็จใน `GET /api/me/room-reservations` และ `GET /api/me/room-reservations/{booking_id}` ใน `backend/app/main.py`
- [x] **T-03** เพิ่ม endpoint ยืนยันยกเลิกที่ระบุผู้ใช้จาก session ตาม SPEC-009 เท่านั้น ไม่รับรหัสสมาชิกจาก request และตอบ 401 เมื่อไม่มี session หรือ session หมดอายุ (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, Constraint: session, ASM-08) — สำเร็จใน `POST /api/me/room-reservations/{booking_id}/cancel`
- [x] **T-04** ใช้ server datetime เดียวกับฟังก์ชันเวลาของ SPEC-008/009 ใน `backend/app/rooms/` และ timezone Asia/Bangkok เพื่อเปรียบเทียบเวลาปัจจุบัน ณ ขณะรับคำขอกับ start time โดยอนุญาตเฉพาะตอนเวลาปัจจุบัน < start time (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-07) — สำเร็จใน `cancel_room_booking`
- [x] **T-05** ดำเนินการยกเลิกภายใต้ `lock_room(room_id)` เดียวกับ SPEC-009 ใน `backend/app/rooms/store.py` เปลี่ยนสถานะเป็น “ยกเลิกแล้ว” และรักษารายการไว้ภายใต้ transaction ใน backend process เดียว (FR-ติดตาม-/-ยกเลิกการจองห้อง-03, ASM-13) — สำเร็จใน `cancel_room_booking` และ `cancel_room_booking` ของ store
- [x] **T-06** จัดการคำขอยกเลิกซ้ำและรายการที่ไม่มีสิทธิ์: เจ้าของที่รายการยกเลิกแล้วตอบว่ายกเลิกแล้วโดยไม่เปลี่ยน store; รายการของผู้อื่นหรือไม่มีอยู่ตอบ “ไม่สามารถยกเลิกได้” และไม่เปิดเผยว่าพบรายการหรือไม่ (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, ASM-09, ASM-10) — สำเร็จใน `cancel_room_booking` และ endpoint ยกเลิก โดยใช้ outcome เดียวกันสำหรับ owner repeat/other/missing และทดสอบใน `test_ac_ติดตามยกเลิกห้อง_010.py`
- [x] **T-07** เมื่อถึงหรือเกิน start time ปฏิเสธคำขอด้วยข้อความ “ไม่สามารถยกเลิกได้” โดยไม่เปลี่ยนสถานะหรือช่วงเวลา (FR-ติดตาม-/-ยกเลิกการจองห้อง-04, AC-ติดตาม-/-ยกเลิกการจองห้อง-02, ASM-07) — สำเร็จใน `cancel_room_booking` โดยใช้ `local_now >= start_at` ใน Asia/Bangkok; endpoint ต้องปฏิเสธ HTTP 409 ด้วยข้อความเดียวกันและไม่เปลี่ยน status ของรายการ ทดสอบกรณีเท่าจุดเริ่มและหลังเริ่มใน `test_ac_ติดตามยกเลิกห้อง_010.py`
- [x] **T-09** เพิ่มหน้ารายการและรายละเอียดใน frontend ให้แสดงสถานะ “ยกเลิกแล้ว” และซ่อนปุ่มยกเลิกสำหรับรายการดังกล่าว; หน้าอ่านรายละเอียดต้องไม่เปลี่ยนข้อมูล; การไม่มี session ต้องตอบ/พาไปเข้าสู่ระบบตามพฤติกรรม API (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05, ASM-08) — สำเร็จใน `frontend/src/features/rooms/RoomReservationsPage.jsx` และ route `/rooms/reservations`
- [x] **T-10** ทดสอบ AC-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง AC-ติดตาม-/-ยกเลิกการจองห้อง-03 รวมกรณียกเลิกสำเร็จ, ยกเลิกซ้ำ, ก่อน/หลัง start time, session 401, รายการผู้อื่น/ไม่มีอยู่, ความว่างหลังยกเลิก และการไม่เปลี่ยนข้อมูลเมื่อติดตามอย่างเดียว (FR-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง FR-ติดตาม-/-ยกเลิกการจองห้อง-05, NFR-REL-01) — สำเร็จใน `backend/tests/test_ac_ติดตามยกเลิกห้อง_010.py`
