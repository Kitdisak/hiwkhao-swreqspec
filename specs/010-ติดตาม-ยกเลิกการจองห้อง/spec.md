# Feature: ติดตาม / ยกเลิกการจองห้อง
Spec ID: SPEC-ติดตาม-ยกเลิกการจองห้อง-010 | Source: SRS v0.3 | Use case: UC-10
Owner: ทีม หิวข้าว | Status: Draft v2 | Updated: 2569-11-18

## Goal
สมาชิกตรวจสอบรายละเอียดการจองห้องและยกเลิกรายการที่ยังอยู่ในเงื่อนไขอนุญาต

## Primary Actor
นักศึกษา / สมาชิก

## Scope
### In scope
- แสดงวัน เวลา และห้องที่จอง
- เลือกการจองที่ต้องการยกเลิก
- ยืนยันการยกเลิกและคืนช่วงเวลาให้ว่าง
### Out of scope
- สร้างรายการจองห้องใหม่ (UC-09)

## Constraints
- ต้องมีรายการจองห้อง
- ยกเลิกได้เฉพาะรายการของผู้ใช้และต้องยกเลิกก่อนเวลาเริ่มรายการจอง
- ผู้ใช้ต้องระบุจาก session ตาม SPEC-จองห้องอ่านหนังสือ-/-ห้องประชุม-009 และห้ามรับรหัสสมาชิกจากคำขอ; การยกเลิกต้องทำภายใต้ lock ต่อห้องเดียวกับ SPEC-009 ใน backend process เดียว
- ใช้ข้อมูลตาม timezone Asia/Bangkok และเวลาปัจจุบันของ server เท่านั้น ห้ามใช้เวลาจาก browser

## Requirements
- **FR-ติดตาม-/-ยกเลิกการจองห้อง-01** ระบบต้องแสดงรายการจองห้องของผู้ใช้พร้อมวัน เวลา ห้อง และสถานะ โดยรายการที่ยกเลิกแล้วต้องแสดงสถานะ “ยกเลิกแล้ว” และไม่มีปุ่มยกเลิก
- **FR-ติดตาม-/-ยกเลิกการจองห้อง-02** ระบบต้องระบุผู้ใช้จาก session ตาม SPEC-จองห้องอ่านหนังสือ-/-ห้องประชุม-009 ห้ามรับรหัสสมาชิกจากคำขอ และให้ผู้ใช้ยืนยันการยกเลิกรายการจองของตนเองก่อนเวลาเริ่มรายการตามเวลาปัจจุบันของ server ใน Asia/Bangkok
- **FR-ติดตาม-/-ยกเลิกการจองห้อง-03** เมื่อยกเลิกสำเร็จ ระบบต้องไม่ลบรายการออกจาก store แต่เปลี่ยนสถานะเป็นยกเลิกแล้ว ทำให้ช่วงเวลานั้นว่างทันทีที่คำตอบยกเลิกสำเร็จส่งกลับ และไม่ใช้รายการยกเลิกแล้วในการคำนวณช่วงว่างของ SPEC-ตรวจสอบห้องว่าง-008 หรือการตรวจซ้อนของ SPEC-จองห้องอ่านหนังสือ-/-ห้องประชุม-009
- **FR-ติดตาม-/-ยกเลิกการจองห้อง-04** เมื่อถึงหรือเกินเวลาเริ่มรายการ ระบบต้องปฏิเสธคำขอยกเลิกและแจ้งข้อความทั่วไปว่า “ไม่สามารถยกเลิกได้” (UC-10 Exception 4b)
- **FR-ติดตาม-/-ยกเลิกการจองห้อง-05** หากผู้ใช้เพียงดูรายละเอียด ระบบต้องไม่เปลี่ยนแปลงข้อมูล (UC-10 Alternative 4a)

## Quality Requirements
- **NFR-REL-01** เมื่อยกเลิกสำเร็จ ตารางห้องต้องอัปเดตทันทีหลังระบบยืนยันการยกเลิก

## Acceptance Criteria
- [ ] **AC-ติดตาม-/-ยกเลิกการจองห้อง-01** (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, FR-ติดตาม-/-ยกเลิกการจองห้อง-03, NFR-REL-01)
  - **Given** มีรายการจองที่ยังยกเลิกได้
  - **When** ผู้ใช้เจ้าของรายการยืนยันยกเลิกภายในเงื่อนไขก่อนเวลาเริ่ม
  - **Then** ระบบเปลี่ยนสถานะรายการเป็น “ยกเลิกแล้ว” โดยไม่ลบรายการออกจาก store ทำให้ช่วงเวลานั้นว่าง และเมื่อคำตอบยกเลิกสำเร็จส่งกลับ ผู้ใช้จะเห็นการค้นหาห้องว่างและการจองถัดไปมองเห็นช่วงเวลานั้นว่าง
  - **And** คำขอยกเลิกซ้ำของเจ้าของที่รายการถูกยกเลิกแล้วต้องไม่เปลี่ยนข้อมูลและตอบกลับว่ายกเลิกแล้ว
- [ ] **AC-ติดตาม-/-ยกเลิกการจองห้อง-02** (FR-ติดตาม-/-ยกเลิกการจองห้อง-04)
  - **Given** รายการจองถึงหรือเกินเวลาเริ่มรายการตามเวลาปัจจุบันของ server
  - **When** ผู้ใช้ยืนยันยกเลิก
  - **Then** ระบบปฏิเสธและแสดงข้อความทั่วไปว่า “ไม่สามารถยกเลิกได้”
- [ ] **AC-ติดตาม-/-ยกเลิกการจองห้อง-03** (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05)
  - **Given** ผู้ใช้ต้องการเพียงดูรายละเอียด
  - **When** ผู้ใช้เปิดรายการจอง
  - **Then** ระบบแสดงรายละเอียดโดยไม่เปลี่ยนข้อมูล
  - **And** รายการที่ถูกยกเลิกแล้วแสดงสถานะ “ยกเลิกแล้ว” และไม่มีปุ่มยกเลิก
  - **And** ผู้ใช้ไม่เข้าสู่ระบบตอบ 401
  - **And** ผู้ใช้ขอยกเลิกรายการของผู้อื่นหรือรายการที่ไม่มีอยู่ต้องไม่บอกว่ารายการมีอยู่หรือไม่และแสดง “ไม่สามารถยกเลิกได้”

## Assumptions
- **ASM-01** ผู้ใช้ยกเลิกได้เฉพาะรายการจองของตนเอง
- **ASM-02** ยกเลิกได้ก่อนเวลาเริ่มรายการเท่านั้น; เมื่อถึงหรือเกินเวลาเริ่มรายการ ระบบปฏิเสธการยกเลิก
- **ASM-03** เมื่อปฏิเสธการยกเลิก ระบบแสดงข้อความทั่วไปว่า “ไม่สามารถยกเลิกได้”
- **ASM-04** เมื่อระบบยืนยันการยกเลิกแล้ว ช่วงเวลาต้องว่างและตารางห้องต้องอัปเดตทันที
- **ASM-05** AC-01 อ้างอิง FR-02/FR-03/NFR-REL-01; AC-02 อ้างอิง FR-04; AC-03 อ้างอิง FR-01/FR-05
- **ASM-06** ไม่มีนโยบายหรือค่ากำหนดเพิ่มเติมจากที่ระบุใน spec และ UC Case.pdf สำหรับฟีเจอร์นี้
- **ASM-07** เขตเวลา Asia/Bangkok ใช้กับการเปรียบเทียบ start time; จุดเปรียบเทียบคือเวลาปัจจุบันของ server ณ ขณะรับคำขอยกเลิก; ยกเลิกได้เมื่อเวลาปัจจุบัน < เวลาเริ่ม แต่เมื่อ ≥ เวลาเริ่มปฏิเสธด้วย “ไม่สามารถยกเลิกได้”
- **ASM-08** ผู้ใช้ระบุจาก session เท่านั้น ห้ามรับรหัสสมาชิกจากคำขอ; ไม่มี session ตอบ 401
- **ASM-09** รายการซ้ำที่เจ้าของยกเลิกแล้วตอบกลับว่ายกเลิกแล้วและไม่เปลี่ยนข้อมูล store
- **ASM-10** รายการของผู้อื่นหรือรายการที่ไม่มีอยู่คืนข้อความเดียวกันว่า “ไม่สามารถยกเลิกได้” เพื่อไม่เปิดเผยว่าเกิดรายการหรืออำนาจเจ้าของ
- **ASM-11** รายการที่ยกเลิกแล้วเก็บไว้ใน store และมีสถานะยกเลิกแล้ว มิได้นับในการคำนวณช่วงว่างหรือการตรวจซ้อนของการจอง
- **ASM-12** “ทันที” หมายถึงเมื่อคำตอบยกเลิกสำเร็จส่งกลับผู้ใช้ การค้นหาห้องว่างและการจองครั้งถัดไปต้องเห็นช่วงเวลาว่างแล้ว; ไม่กำหนด SLA เป็นวินาทีและทดสอบโดยยกเลิกแล้วเรียกคำนวณช่วงว่างทันที
- **ASM-13** การยกเลิกและการจองใหม่ของห้องเดียวกันทำภายใต้ lock ต่อห้องเดียวกับ SPEC-009 ใน backend/app/rooms/store.py; ใช้ in-memory store ภายใน backend process เดียว
