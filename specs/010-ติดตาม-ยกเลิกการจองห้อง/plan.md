# แผนงาน: ติดตาม / ยกเลิกการจองห้อง

อ้างอิง: SPEC-ติดตาม-ยกเลิกการจองห้อง-010 (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกดูรายการจองของตนเองพร้อมวัน เวลา และห้อง (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, ASM-01)
- อนุญาตให้ผู้ใช้ยกเลิกเฉพาะรายการของตนเองก่อนเวลาเริ่มรายการ (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, Constraints, ASM-01, ASM-02)
- เมื่อยกเลิกสำเร็จ ทำให้ช่วงเวลาว่างและอัปเดตตารางหลังระบบยืนยันการยกเลิก (FR-ติดตาม-/-ยกเลิกการจองห้อง-03, NFR-REL-01, ASM-04)
- เมื่อถึงหรือเกินเวลาเริ่ม ปฏิเสธคำขอและแสดงข้อความ “ไม่สามารถยกเลิกได้” (FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-03)
- การเปิดดูรายละเอียดต้องไม่เปลี่ยนข้อมูล และไม่สร้าง/จัดการการจองใหม่ซึ่งอยู่นอกขอบเขต (FR-ติดตาม-/-ยกเลิกการจองห้อง-05, Scope: Out of scope)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุภาษา/framework |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| RoomReservation | reservation reference, member reference, room reference, date, start time, end time, reservation status | FR-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง FR-ติดตาม-/-ยกเลิกการจองห้อง-05, NFR-REL-01 |
| Member / authenticated user | user reference สำหรับจำกัดรายการและการยกเลิกให้เป็นของผู้ใช้ปัจจุบัน | Constraints: ผู้ใช้ยกเลิกได้เฉพาะรายการของตนเอง, FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-02, ASM-01 |
| RoomSchedule | room reference, reservation time ranges, availability derived from active reservations | FR-ติดตาม-/-ยกเลิกการจองห้อง-03, NFR-REL-01, ASM-04 |

เมื่อเปิดดูข้อมูลให้อ่านโดยไม่แก้ RoomReservation; การยกเลิกต้องตรวจเจ้าของรายการและเวลาเริ่มก่อนเปลี่ยนสถานะ และทำให้ช่วงเวลาว่าง/ตารางสะท้อนผลหลังยืนยัน (FR-ติดตาม-/-ยกเลิกการจองห้อง-02 ถึง FR-ติดตาม-/-ยกเลิกการจองห้อง-05, ASM-01 ถึง ASM-04).

## 4. API / หน้าจอ

รายการต่อไปนี้เป็นข้อเสนอทางเทคนิคเพื่อรองรับ FR; ไม่รวมการสร้างการจองใหม่

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| รายการจองของผู้ใช้ | `GET /api/me/room-reservations`; input: authenticated user context; output: รายการของผู้ใช้พร้อมวัน เวลา และห้อง | FR-ติดตาม-/-ยกเลิกการจองห้อง-01 |
| ยกเลิกรายการจองของผู้ใช้ | `DELETE /api/me/room-reservations/{reservationId}`; input: reservation reference และการยืนยัน; output: ผลการยกเลิก/ข้อความ “ไม่สามารถยกเลิกได้” | FR-ติดตาม-/-ยกเลิกการจองห้อง-02, FR-ติดตาม-/-ยกเลิกการจองห้อง-03, FR-ติดตาม-/-ยกเลิกการจองห้อง-04, NFR-REL-01 |
| หน้ารายการและรายละเอียดการจอง | input: ผู้ใช้ที่เข้าสู่ระบบและรายการของตน; output: รายละเอียดโดยไม่เปลี่ยนข้อมูล หรือผลยกเลิกและสถานะช่วงเวลาหลังยืนยัน | FR-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง FR-ติดตาม-/-ยกเลิกการจองห้อง-05 |

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ติดตาม-ยกเลิกการจองห้อง-010

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ต้องมีรายการจองห้อง | หน้ารายการอ่าน RoomReservation ของผู้ใช้; เมื่อไม่มีรายการไม่มีการเปลี่ยนแปลงข้อมูล (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05) | ใช้แล้ว |
| ไม่มี ID: ยกเลิกได้เฉพาะรายการของผู้ใช้และก่อนเวลาเริ่ม | ตรวจ member reference ว่าตรงผู้ใช้ปัจจุบันและตรวจว่าเวลาปัจจุบันก่อน start time (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-01, ASM-02) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ติดตาม-/-ยกเลิกการจองห้อง-01 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_01` | เตรียมรายการของผู้ใช้ที่ยังไม่ถึงเวลาเริ่ม ยืนยันยกเลิก ตรวจว่ารายการถูกยกเลิก ช่วงเวลาว่าง และตารางอัปเดตทันทีหลังยืนยัน (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, FR-ติดตาม-/-ยกเลิกการจองห้อง-03, NFR-REL-01) |
| AC-ติดตาม-/-ยกเลิกการจองห้อง-02 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_02` | เตรียมรายการที่ถึงหรือเลยเวลาเริ่ม ยืนยันยกเลิก ตรวจว่าระบบปฏิเสธและแสดง “ไม่สามารถยกเลิกได้” (FR-ติดตาม-/-ยกเลิกการจองห้อง-04) |
| AC-ติดตาม-/-ยกเลิกการจองห้อง-03 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_03` | เปิดดูรายละเอียดรายการจองโดยไม่ส่งคำขอยกเลิก ตรวจว่ารายละเอียดแสดงและข้อมูลการจองไม่เปลี่ยน (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05) |

AC-01 ต้องตรวจทั้งสถานะรายการ ช่วงเวลาว่าง และตารางหลังยืนยัน; คำว่า “ทันที” ยังไม่มีเกณฑ์เวลาตัวเลขใน spec จึงตรวจลำดับการอัปเดตตามที่ระบุไว้ (AC-ติดตาม-/-ยกเลิกการจองห้อง-01, NFR-REL-01).

## 7. ลำดับงาน

1. แสดงเฉพาะรายการจองของผู้ใช้พร้อมวัน เวลา และห้อง (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, ASM-01)
2. แสดงรายละเอียดโดยไม่แก้ข้อมูลเมื่อผู้ใช้เพียงเปิดดู (FR-ติดตาม-/-ยกเลิกการจองห้อง-05, AC-ติดตาม-/-ยกเลิกการจองห้อง-03)
3. ตรวจว่ารายการจองเป็นของผู้ใช้ปัจจุบันและยังไม่ถึงเวลาเริ่ม (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, ASM-01, ASM-02)
4. ปฏิเสธรายการที่ถึงหรือเกินเวลาเริ่ม พร้อมข้อความทั่วไป (FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-03)
5. รับการยืนยันและดำเนินการยกเลิกเมื่อรายการยังยกเลิกได้ (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, AC-ติดตาม-/-ยกเลิกการจองห้อง-01)
6. คืนช่วงเวลาให้ว่างและอัปเดตตารางหลังยืนยันการยกเลิก (FR-ติดตาม-/-ยกเลิกการจองห้อง-03, NFR-REL-01, ASM-04)
7. ทดสอบการยกเลิกที่อนุญาต/ไม่อนุญาตและการเปิดดูโดยไม่แก้ข้อมูล (AC-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง AC-ติดตาม-/-ยกเลิกการจองห้อง-03)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน SPEC-ติดตาม-ยกเลิกการจองห้อง-010 (Draft v2); ไม่มีรายการที่ต้องระงับไว้รอคำตอบ (ASM-06).
