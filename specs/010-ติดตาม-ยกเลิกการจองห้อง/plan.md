# แผนงาน: ติดตาม / ยกเลิกการจองห้อง

อ้างอิง: SPEC-ติดตาม-ยกเลิกการจองห้อง-010 (Draft v2)

## 1. สรุปแนวทาง

- นักศึกษา/สมาชิกดูรายการจองของตนเองพร้อมวัน เวลา ห้อง และสถานะ และรายการยกเลิกแล้วแสดง “ยกเลิกแล้ว” โดยไม่มีปุ่มยกเลิก (FR-01, ASM-11)
- ระบุผู้ใช้จาก session ตาม SPEC-009 เท่านั้นและอนุญาตยกเลิกเฉพาะรายการของตนเองเมื่อเวลาปัจจุบันของ server ใน Asia/Bangkok < เวลาเริ่ม (FR-02, ASM-07, ASM-08)
- เมื่อยกเลิกสำเร็จ เก็บรายการไว้ เปลี่ยนสถานะเป็นยกเลิกแล้ว และคืนช่วงเวลาให้ว่างก่อนคำตอบสำเร็จส่งกลับ (FR-03, NFR-REL-01, ASM-12)
- เมื่อถึงหรือเกินเวลาเริ่ม ปฏิเสธคำขอและแสดงข้อความ “ไม่สามารถยกเลิกได้” (FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-03)
- คำขอยกเลิกซ้ำของเจ้าของตอบว่ายกเลิกแล้วและไม่เปลี่ยน store; รายการของผู้อื่นหรือไม่มีอยู่ตอบ “ไม่สามารถยกเลิกได้” (FR-02, ASM-09, ASM-10)
- การเปิดดูรายละเอียดไม่เปลี่ยนข้อมูล และไม่สร้าง/จัดการการจองใหม่ซึ่งอยู่นอกขอบเขต (FR-05, Scope: Out of scope)

## 2. เทคโนโลยีที่ใช้

| สิ่งที่เลือก | มาจาก | หมายเหตุ |
|---|---|---|
| React (Vite) สำหรับหน้าบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุเทคโนโลยี |
| Python FastAPI สำหรับหลังบ้าน | **ทีมเลือกเอง ไม่ได้มาจาก spec** | ค่าเริ่มต้นรายวิชาตาม prompt /plan; ไม่มี Constraint ระบุภาษา/framework |
| Asia/Bangkok กับ server datetime | ASM-07 และ Constraint เขตเวลาใน spec | ใช้ฟังก์ชันเวลาปัจจุบันของ server ที่ SPEC-008/009 ใช้ใน backend/app/rooms/ ห้ามรับเวลาจาก browser |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลักที่เสนอ | รองรับ |
|---|---|---|
| RoomReservation | reservation reference, member reference, room reference, date, start time, end time, reservation status (`ยกเลิกแล้ว`) | FR-01 ถึง FR-05, ASM-09, ASM-11 |
| Member / authenticated user | user reference ที่อ่านจาก session เพื่อจำกัดรายการและการยกเลิก ไม่มีรหัสสมาชิกใน request | Constraint SPEC-009, FR-02, ASM-08, ASM-10 |
| RoomSchedule | room reference, reservation time ranges, availability derived without cancelled reservations | FR-03, NFR-REL-01, ASM-11, ASM-12 |

ฟังก์ชันและข้อมูลจะอยู่ร่วมใน in-memory store ของ `backend/app/rooms/store.py` ที่ SPEC-008/009 ใช้ร่วมกัน; ไม่ลบ RoomReservation เมื่อนำห้องกลับว่าง แต่เปลี่ยนสถานะและข้อมูล availability ของ SPEC-008/SPEC-009 จะไม่ตัดรายการนี้ว่าเป็นช่วงจองที่ใช้งานอยู่

เมื่อเปิดดูข้อมูลให้อ่านโดยไม่แก้ RoomReservation; การยกเลิกต้องตรวจเจ้าของรายการและเวลาเริ่มก่อนเปลี่ยนสถานะ และทำให้ช่วงเวลาว่าง/ตารางสะท้อนผลหลังยืนยัน (FR-ติดตาม-/-ยกเลิกการจองห้อง-02 ถึง FR-ติดตาม-/-ยกเลิกการจองห้อง-05, ASM-01 ถึง ASM-04).

## 4. API / หน้าจอ

รายการต่อไปนี้เป็นข้อเสนอทางเทคนิคเพื่อรองรับ FR; ไม่รวมการสร้างการจองใหม่

| รายการ | Method / path หรือ input/output หลัก | รองรับ |
|---|---|---|
| รายการจองของผู้ใช้ | `GET /api/me/room-reservations`; input: session เท่านั้น; output: รายการพร้อมวัน เวลา ห้อง และสถานะ; ไม่มีปุ่มยกเลิกสำหรับรายการยกเลิกแล้ว | FR-01 |
| รายละเอียดรายการจอง | `GET /api/me/room-reservations/{reservationId}`; input: reservation reference; output: รายละเอียดโดยไม่เปลี่ยนข้อมูล | FR-01, FR-05 |
| ยกเลิกรายการจองของผู้ใช้ | `POST/PUT /api/me/room-reservations/{reservationId}/cancel`; input: reservation reference และการยืนยัน ไม่มีรหัสสมาชิกใน request; output: สำเร็จ, ยกเลิกแล้วสำหรับซ้ำ, หรือ “ไม่สามารถยกเลิกได้”; ไม่มี session → 401 | FR-02, FR-03, FR-04, NFR-REL-01 |
| หน้ารายการและรายละเอียดการจอง | input: session และ reservation reference; output: รายละเอียดแบบอ่านอย่างเดียวหรือผลยกเลิก; รายการยกเลิกแล้วไม่แสดงปุ่มยกเลิก | FR-01 ถึง FR-05 |

## 5. ตารางตรวจ Constraints

Constraints ใน spec ไม่มี ID เฉพาะ จึงอ้างอิงด้วยข้อความ Constraint ภายใต้ SPEC-ติดตาม-ยกเลิกการจองห้อง-010

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| ไม่มี ID: ต้องมีรายการจองห้อง | หน้ารายการอ่าน RoomReservation ของผู้ใช้; เมื่อไม่มีรายการไม่มีการเปลี่ยนแปลงข้อมูล (FR-ติดตาม-/-ยกเลิกการจองห้อง-01, FR-ติดตาม-/-ยกเลิกการจองห้อง-05) | ใช้แล้ว |
| ไม่มี ID: ยกเลิกได้เฉพาะรายการของผู้ใช้และก่อนเวลาเริ่ม | รับผู้ใช้จาก session และเรียก lock ห้องใน `backend/app/rooms/store.py`; เปรียบเทียบ server datetime Asia/Bangkok กับ start time (FR-02, FR-04, ASM-07, ASM-08) | ใช้แล้ว |
| ไม่มี ID: รายการยกเลิกแล้วไม่ลบและไม่ต้องนับซ้ำ | เปลี่ยน status ใน RoomReservation แล้วไม่ใช้รายการนั้นใน availability ของ SPEC-008 และ overlap ของ SPEC-009 (FR-03, ASM-11) | ใช้แล้ว |
| ไม่มี ID: ยกเลิกและจองทำภายใต้ lock ต่อห้องเดียวกัน | ออกแบบให้ยกเลิกเข้าร่วม `lock_room(room_id)` ที่มีอยู่ใน store เพื่อร่วมจัดระเบียบกับการจองของ SPEC-009 (ASM-13) | ใช้แล้ว |

## 6. แผนทดสอบจาก Acceptance Criteria

| AC ID | ชื่อ test | ทดสอบอย่างไร |
|---|---|---|
| AC-ติดตาม-/-ยกเลิกการจองห้อง-01 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_01` | เตรียมรายการก่อน start time ยืนยันยกเลิก ตรวจ status ยกเลิกแล้ว รายการยังอยู่ใน store และเรียกคำนวณช่วงว่าง SPEC-008/การจอง SPEC-009 ภายหลังต้องเห็นช่วงว่าง; ส่งคำขอซ้ำและตรวจว่าไม่มีข้อมูลเปลี่ยน ตอบว่ายกเลิกแล้ว (FR-02, FR-03, NFR-REL-01, ASM-07 ถึง ASM-13) |
| AC-ติดตาม-/-ยกเลิกการจองห้อง-02 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_02` | ใช้ server datetime Asia/Bangkok ในขณะรับคำขอ เตรียมรายการที่เวลาปัจจุบัน ≥ start time ยืนยันยกเลิกและตรวจว่าปฏิเสธด้วย “ไม่สามารถยกเลิกได้” (FR-04, ASM-07) |
| AC-ติดตาม-/-ยกเลิกการจองห้อง-03 | `test_AC_ติดตาม_ยกเลิกการจองห้อง_03` | เปิดดูรายละเอียดและยืนยันไม่มีข้อมูลเปลี่ยน รายการยกเลิกแล้วแสดงสถานะและไม่มีปุ่มยกเลิก ไม่มี session ต้อง 401 และการขอยกเลิกของผู้อื่น/รายการไม่มีอยู่ต้องตอบ “ไม่สามารถยกเลิกได้” (FR-01, FR-05, ASM-08, ASM-10) |

AC-01 ต้องตรวจทั้ง status รายการ ช่วงเวลาว่าง และคำขอถัดไปของ SPEC-008/SPEC-009 หลังคำตอบสำเร็จ; “ทันที” ไม่มี SLA วินาที แต่ต้องทำให้เห็นผลว่างเมื่อคำตอบสำเร็จส่งกลับ (AC-01, NFR-REL-01, ASM-12).

## 7. ลำดับงาน

1. แสดงเฉพาะรายการจองของผู้ใช้พร้อมวัน เวลา ห้อง และสถานะ (FR-01, ASM-01)
2. แสดงรายละเอียดโดยไม่แก้ข้อมูลเมื่อผู้ใช้เพียงเปิดดู รวม status และการแสดงไม่มีปุ่มยกเลิกเมื่อยกเลิกแล้ว (FR-05, AC-03)
3. อ่านผู้ใช้จาก session ตรวจว่ารายการเป็นของผู้ใช้ปัจจุบันและยังไม่ถึงเวลาเริ่มด้วย server datetime Asia/Bangkok (FR-02, ASM-07, ASM-08)
4. ปฏิเสธรายการที่ถึงหรือเกินเวลาเริ่ม พร้อมข้อความทั่วไป (FR-ติดตาม-/-ยกเลิกการจองห้อง-04, ASM-03)
5. รับการยืนยันและดำเนินการยกเลิกเมื่อรายการยังยกเลิกได้ (FR-ติดตาม-/-ยกเลิกการจองห้อง-02, AC-ติดตาม-/-ยกเลิกการจองห้อง-01)
6. เปลี่ยนสถานะยกเลิกแล้วใน store เดิม คืนช่วงเวลาให้ว่างภายใต้ lock ห้องและไม่ส่งรายการยกเลิกแล้วไปยัง availability/overlap (FR-03, NFR-REL-01, ASM-11, ASM-13)
7. ทดสอบการยกเลิกที่อนุญาต/ไม่อนุญาตและการเปิดดูโดยไม่แก้ข้อมูล (AC-ติดตาม-/-ยกเลิกการจองห้อง-01 ถึง AC-ติดตาม-/-ยกเลิกการจองห้อง-03)

## 8. สิ่งที่ยังไม่ทำ

ไม่มี Open Questions ใน SPEC-ติดตาม-ยกเลิกการจองห้อง-010 (Draft v2); ไม่มีรายการที่ต้องระงับไว้รอคำตอบ (ASM-06).
